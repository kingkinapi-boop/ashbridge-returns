## When it starts
This card waits until D04 (the preparer queue) is approved by Zo at a design sitting (RV-53); the Lead marks D04 done then.

## Goal
The preparer's list of returns, sorted by due date, showing each return's state, tier and what is blocking it, with both due dates on every row, so the next piece of work is always obvious.

## Build
- `src/app/(staff)/prepare/queue/`: built to D04's approved design: an MOJ sortable table (U00) of the returns `visibleReturns` gives the signed-in preparer (SEC-2 through V00), default order filing due date then corporation name (RV-20, rule 6, stated in D04's brief), with search and filters for state and blocker (rule 21).
- Columns: corporation and year end (link to the return record), state (blueprint 02's words through U02's `StatusWords`), tier (or "not set" until the tier card sets one, a real value with its meaning in D04's notes), filing due date and balance-due date from F02 (FLOW-7), who holds it, and what blocks it.
- What blocks a return, from code only, each with words and a link to where it is resolved: "waiting on the client since <date>" (FLOW-3's dated flag, never a state); an ops-confirms item from the bridge; books refused (B05's reasons); documents refused or flagged for a person (E00, E02); the gap list not signed (G00); held by someone else (FLOW-10). A return with nothing blocking says "ready for you".
- Days to the filing due date, with returns past it marked in words and a non-colour cue (rule 7).
- Back from a return keeps the queue's filter, sort and scroll; next and previous on the return record follow the queue (rule 21).
- Shortcuts through U01: next row, open, search.

## Test fixtures (spec-writer)
- Test-world returns for one preparer across states: one waiting on the client since a pinned date, one with refused books, one held by another preparer, one past its filing due date, one with a 28 Feb year end and one CCPC meeting the three-month balance-due rule, more than 5 rows; a return assigned to another preparer.

## Golden files (spec-writer)
- The ARIA snapshot of the queue for the fixture set (`e2e/staff/__golden__/`).

## Acceptance checks
1. RV-20: the queue lists exactly the preparer's returns, sorted by filing due date by default with `aria-sort` set; sorting by each sortable column works; search and the state and blocker filters narrow the list.
2. FLOW-7: each row shows the filing due date and the balance-due date as F02 computes them, including the 28 Feb year end (due 31 Aug) and the three-month CCPC case.
3. FLOW-3: the waiting return shows "waiting on the client since <date>" as a blocker while its state reads qa (never a state called waiting).
4. RV-20: refused books, a return held by another preparer and an unsigned gap list each show their blocker with a link that leads to where it is resolved; a return with none says "ready for you".
5. SEC-2: the return assigned to another preparer is not listed and not found by search.
6. Rule 21: back from a return restores filter, sort and scroll; next and previous on the return follow the queue order.
7. RV-53: the queue matches D04's approved pages within the visual threshold, and D04's click and page-load budgets for "open the next return" hold.
8. RV-54: U02's sweeps pass on the queue; the whole task works by keyboard alone; the golden ARIA snapshot matches.
