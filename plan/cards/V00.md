## When it starts
Every screen is designed first and Zo approves the design before it is built (RV-53, end state item 12). This card waits until D13 (sign-in and the return record shell) is approved by Zo at a design sitting; the Lead marks D13 done then, and only then does the queue release this card.

## Goal
The frame every staff screen sits in: per-person sign-in with a second factor, a server-side session, navigation by role, the one return record shell (identity bar plus record tabs) every family fills, holds on a return, and a log of every source a person opens. Who may see which return is decided here, on the server, once.

## Build
- Sign-in screens (`src/app/(staff)/sign-in/`): password, then the one-time code, then the page the person asked for; built to D13's approved pages with U00 components and the GOV.UK error pattern. Every refusal reads "sign-in failed" (A06 keeps the true reason). Sign-out from the header.
- The session cookie: the token from A06, `HttpOnly`, `Secure`, `SameSite=Strict`, path `/`, no expiry beyond A06's limits; every request checks it on the server through A06's `getSession` and `touch`; no session means the sign-in page, with the asked-for address kept.
- `src/modules/access/` and `src/contracts/access.ts` (SEC-2): `canSee(user, returnId)` and `visibleReturns(user, filter)`: a preparer sees only returns assigned to them; ops sees returns in the states where ops acts (blueprint 02) plus any assigned; the CPA and the owner see everything. Every return route, server action and search goes through these; there is no other path to a return's data. Assignments live in `db/schema/16_access.sql` (append-only with events, row-level security on, no policies, `is_test`).
- Source log (SEC-3): `logSourceOpen(user, pointer, screen)` writes who, what (the pointer), when and from which screen to an append-only table in `16_access.sql`; V01 calls it on every open.
- The staff layout (`src/app/(staff)/layout.tsx`, `_shell/`): the Generic header with the Ashbridge Tax logo, the service navigation by role from D01's navigation, header search (results page when more than one match, rule 21; only returns `visibleReturns` allows), and the return record shell: U02's `ReturnFrame` with the identity bar and the record tabs D13 approved; families fill a tab and never add their own tab set (rule 23). U02's `HoldBanner` on every return page (FLOW-10).
- Shortcuts for moving between tabs and to search, through U01.
- Routes are listed in D01's map (U02's sweeps then run on them).

## Acceptance checks
1. SEC-1: a test user signs in with password and code and lands on the asked-for page; a wrong password or code shows "sign-in failed" with the GOV.UK error pattern and no hint which part was wrong; sign-out ends the session at once (the next request goes to sign-in).
2. SEC-1: the cookie is `HttpOnly`, `Secure` and `SameSite=Strict`; a request with a forged or expired token gets the sign-in page and no return data.
3. SEC-2: preparer A sees only her assigned returns in navigation, search and by direct address (another return's address answers "not found", the same as a return that does not exist); ops sees ops-state returns; the CPA and the owner see all; property (fast-check, fixed seed): for any assignment table and any user, every route and search result is a subset of `visibleReturns`.
4. SEC-3: opening a source through `logSourceOpen` writes one row with who, what, when and screen; the rows refuse update and delete.
5. FLOW-10: a preparer takes a return's hold from the shell; a second preparer sees who holds it and cannot act until it expires on the pinned clock.
6. RV-50: every shell page names the return (corporation and year end) in the identity bar and the title; the record tabs equal D13's approved list.
7. RV-53: the sign-in page, the code page and the return record shell match D13's approved pages within the visual threshold (baselines made in the cloud container).
8. RV-54, RV-51: U02's sweeps pass on every route this card adds; signing in and reaching a return works by keyboard alone; the golden ARIA snapshots match.
