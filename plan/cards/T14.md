## Goal
FLOW-8: "An amended return starts a new cycle at prepare and needs a new T183CORP." F02's move table has no move out of `filed` or `assessed` back to prepare, so an amended return is a new return record for the same corporation and tax year, linked to the one it amends, starting in `prepare`. It carries the original's facts as proposed facts for the preparer to verify again, and needs its own trace, review, approval, T183CORP, check and filing. The original is never changed.

## Spec
- Fixtures (pinned clock): C01 taken to `assessed` with an open T13 follow-up item, and a copy taken to `closed`; C01 in `filed`; C01 in `review` (refused); users: the CPA, the owner, ops, a preparer, an AI actor.
- Classes:
  - FLOW-8 start: `startAmendedReturn` on a return in `filed`, `assessed` or `closed` creates exactly one new return (same corporation, year end and client reference as F07 gives, `is_test`) in `prepare` with one first state event (who, when, why naming the follow-up item or the written reason) and one link row (original id, amended id, follow-up item id or reason, who, when), in one transaction; a failure keeps none of them.
  - FLOW-8 with T13: closing a follow-up item with outcome `amend` does not start anything by itself; a person starts it here, naming the item; an item closed with another outcome cannot be named.
  - States: a return in any state before `filed` is refused naming the state; a second amended return while one for the same original is not yet `filed` is refused naming it.
  - FLOW-9: starting an amended return from a `closed` original writes nothing on the original's tables (the closed guard holds; every write is on the new return or the link table, which T10's sweep must allow: the link row names the original only as a column, never by a write with the original's `return_id`).
  - EV-8: each `cpa-accepted` fact of the original is carried as a new fact on the new return through L00's `proposeFact`, with the same source pointer and status `proposed`, so the preparer verifies it again; nothing is carried as verified or accepted.
  - FLOW-8 new T183CORP (with T11): the new return's moves to `client_sign` and `ready_to_file` are refused with only the original's T183CORP sent record and certificate; the original's approval, check and filing record count for nothing on the new return.
  - Who (AI-7, SEC-2): ops, a preparer, an AI actor or the system starting an amended return is refused with the reason and nothing is stored; any user who can see the original sees the link to the amended return and back (through V00).
  - SEC-7: UPDATE, DELETE and TRUNCATE on the link table are refused (db test on PGlite and Postgres 16).
- Golden file (`src/modules/amended/__golden__/`): the link row and first state event for C01's amended return.
