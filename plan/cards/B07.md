## Goal
For a client with bank statements only, the firm books the bank and card lines in QBO, outside Returns. Returns then proves the books hold exactly the statements: each QBO bank or card transaction is matched to its statement line by account, date and amount, each match is written as an "agrees with" link (so the dot can turn green), and every transaction or statement line left over is flagged for a person.

## Build
- `data/books/match-rules.json` (data, not code): the date window per account kind (bank: same date up to 3 days later in QBO; card: transaction date or posting date, up to 3 days either way), the amount rule (equal in integer cents, same sign once the card's sign convention is turned to the company's view), and how a statement account is paired with a QBO account (the last four digits of the account number and the currency).
- `src/modules/books/bankmatch/`:
  - `pairAccounts(returnId)`: each statement account (from E10 and E11 facts) with exactly one QBO bank or card account by the rule; none or more than one is flagged for a person and that account is not matched.
  - `matchAccount(returnId, statementAccount)`: one-to-one matching of the year's statement lines to the QBO transactions on the paired account: exact date first, then the nearest date inside the window, ties broken by statement order and then QBO id, so the same inputs always give the same matches. Each match is written through L01's `linkAgrees` under the rule for a third-party statement against the same amount in QBO (EV-13); a refused link stays unmatched with the reason.
  - Flags for a person, each with its pointers: a QBO transaction with no statement line ("booked, not on a statement"); a statement line with no QBO transaction ("on a statement, not booked"); a statement line dated outside the return's year ("statement line from another year", not matched); two identical statement lines where QBO has one ("possible duplicate"); a month of the year with no statement lines for an account that has them in other months ("statement month missing").
  - The result per account: counts and totals in cents of matched, booked-only and statement-only lines, and the check that statement activity equals matched plus statement-only, and QBO activity equals matched plus booked-only.
  - Runs only for a return whose books source in the bridge contract (F07) is `firm-books`, passed in; for others it reports "not a bank-only client" and does nothing.
  - Every result carries the rules version (a hash of `match-rules.json`), the snapshot ids, the fact versions and this card's code release (ARC-10).
- `src/modules/books/index.ts` gains the matching exports.
- `src/pipeline/steps/books.ts` (B05's step) runs the matching for a `firm-books` return after `readReturnBooks`, and reports the result per account with the books result.

7. ARC-10: every result carries the rules version and the snapshot and fact versions; changing `match-rules.json` changes the rules version.
