## Goal
When a return reaches assessed, the system freezes its binder: the printed return, every source, the trace, the comments, the approvals, the T183CORP and its certificate, the check and the confirmation, listed in one manifest, each part fingerprinted and the manifest fingerprinted as a whole. Then the return closes, and from then on nothing about it can be written. The binder is kept at least six years and the T183CORP at least six years after filing; nothing deletes either.

## Spec
- Fixtures (pinned clock): C01 taken through filed and assessed in the test world (T09 and T11 fixtures, a notice of assessment from W29); a copy with the T183CORP certificate missing; a copy with no filing record; a copy where a document was received but feeds no figure; a return filed on 29 Feb.
- Classes:
  - FLOW-9 contents: the manifest lists exactly: the printed return of the approved lock export (RT-11) and that lock export; every document received for the return (each marked whether it feeds a figure); every QBO snapshot and attachment reached from the approval's items; the trace of the approved lock export; every comment, response and resolution; every approval with its items, review record, sources opened and voids; B06's recheck records with the snapshots they read; every X00 answer and V03 risk judgment; every preparer sign (T12, V04); the T183CORP sent record and certificate; the check result, the check export and the filing record with the confirmation number; the notice of assessment with its compare result and any follow-up item with its close (T13). Each entry names its kind, id, version, file key and sha256.
  - FLOW-9 fingerprint: the manifest's canonical form (entries sorted by kind then id, keys by code point, no Unicode normalization) hashes to the binder fingerprint; reordering the inputs gives the same fingerprint; changing any one part's bytes or version changes it (property, fast-check, fixed seed).
  - FLOW-9 missing parts: a binder missing the printed return, the certificate, the filing record or the notice is refused naming each missing part; nothing is frozen, the return stays in `assessed`, and it is flagged for a person. An open T13 follow-up item (FLOW-8) also refuses the freeze naming it; the freeze runs again when the item closes (T13's close event, through the pipeline).
  - FLOW-2: guard `assessed_to_closed` passes only with a frozen binder for the return whose verify passes; the freeze and the move run in one transaction (FX5's caller transaction), so a failure keeps neither.
  - FLOW-9 read-only (rule test, every table): after closing, an insert, update or delete on any table with a `return_id` for that return is refused by the database naming "return is closed"; the sweep finds every such table from the catalog (not a list), asserts it read at least one table and a named sentinel, and checks each has the closed guard; the only tables allowed to take rows for a closed return are named with a reason in `99_closed.sql` (the source log, SEC-3, so reading a closed binder is still logged; the state events table, for the closing event itself; `returns.jobs`, runner bookkeeping: the freeze job's own row, and learning jobs (N01) enqueued for a closed return; `returns.differences`, learning records (END-5, LL-3 to LL-7): N01 writes the CRA-assessed differences and their causes and ranking after close, and they describe the build's misses, not the return) and the sweep fails on any other exemption.
  - Verify: `verifyBinder` re-hashes every part and the manifest and passes on C01; a stored file changed on disk under its key (a tamper made in the test) fails naming the part; a manifest row inserted straight into the database is refused by the triggers.
  - SEC-8 retention: the binder's keep-until date is six years after the date it was frozen (calendar years; 29 Feb gives 28 Feb), never earlier than the T183CORP's `t183RetainUntil`; property (fixed seed): for any filing and freeze dates with freeze on or after filing, keep-until is at least six years after each.
  - SEC-8, SEC-7, EV-1: UPDATE, DELETE and TRUNCATE on the binder tables are refused (db test on PGlite and Postgres 16); the module exports no delete; the file store refuses to delete or overwrite a binder file.
  - Who: freezing runs as the system step on the move into `assessed`; a person, an AI actor or a preparer calling freeze directly is refused; any user who can see the return can read and verify its binder (SEC-2 through V00), and nobody can change it.
- Golden file (`src/modules/binder/__golden__/`): C01's manifest and fingerprint.

## Build
- `src/contracts/binder.ts` (zod): the manifest entry, the binder record (return, manifest file key, fingerprint, frozen at, keep until), the verify result, and the ports it reads through (T07, T04, T08, V04, T09, T11, L00, the storage contract, F02).
- `src/modules/binder/`: `freezeBinder(returnId, deps)` collects the parts, writes the manifest write-once through the storage contract, stores the binder record and moves the return to `closed` through F02 in one transaction; `verifyBinder(returnId, deps)`; `keepUntil(frozenOn, filedOn)`. `// @mutate` on the manifest, fingerprint and keep-until files (mutation 100 per marked file, ARC-15).
- `src/pipeline/steps/binder.ts`: runs `freezeBinder` after the move into `assessed`; wired in `src/pipeline/handlers.ts`. Guard `assessed_to_closed` registered in `src/pipeline/deps.ts`.
- `db/schema/81_binder.sql`: binders and manifest entries, append-only with F01's `refuse_change` triggers, row-level security on, no policies, `is_test`, a foreign key on every return_id.
- `db/schema/99_closed.sql`: `returns.refuse_if_closed()` and its insert, update and delete trigger on every table with a `return_id` column, made from the catalog when the schema loads (so it is the last file), with the named exemptions and their reasons (the source log, the state events, `returns.jobs` (runner bookkeeping: the freeze job's own row, and learning jobs (N01) enqueued for a closed return) and `returns.differences`, as in the rule test above; chosen: exempt `returns.differences` rather than make the N cards write before close, so learning never races the freeze). A table added later by any card is covered because this file runs last; the rule test above proves it.
