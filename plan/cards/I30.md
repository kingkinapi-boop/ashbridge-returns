## Goal
Before the CPA reviews, a second reader that knows nothing of our work reads what CRA would read, the printed return and the client's raw documents, and lists what CRA would most likely adjust, each with a dollar amount and citations code checks (AI-3). It is a different model from the ones that drafted the return, so it does not share their blind spots.

## Build
- `src/modules/ai/redteam/inputs.ts`: `buildRedTeamInputs(returnId, deps)`: the printed return T07 received (its pages and words) and the return's raw document pages, redacted by I00 (AI-9). The input type has no field for facts, the ledger, preparer notes, comments, answers, the trace or our flags, and the builder's deps are only the documents and printed-return contracts (a type test), so none can be passed in.
- `src/modules/ai/redteam/model.json` and `prompt.md`: the red-team model id and the versioned prompt. `run.ts` refuses the run, naming both ids, when the model id equals the model id on any stored drafting output of this return (extraction, finding, category, GIFI mapping and slot-fill stamps).
- `src/modules/ai/redteam/run.ts`: `runRedTeam(returnId, deps)`: one grounded `red_team_item` step through I00 (F04 schema, AI-1; document text only inside I00's data envelope, AI-8; no tool that writes). Citations may be a document box or a return cell; a ledger citation is dropped and counted ("the red team cannot see the ledger"). A citation that fails I00's check drops the item and counts against the step (AI-4). AI-5: an item about something missing cites the return cell or document box where it should be; there is no separate missing type (F04's `red_team_item` has no finding type), so it is kept like any other item. "I can't tell" goes to a person.
- `src/modules/ai/redteam/amount.ts`: F04's `red_team_item` has no amount field, so code works out each item's "amount at issue (cited)" from its citations (this is the cited value, not yet the dollar effect AI-3 names): the cited return cell's value from the lock export, else the largest quoted amount I00 verified inside a cited box, in integer cents. An item with no such amount is kept with "no amount". Q00's `estimateTaxEffect` then turns the amount at issue into the item's tax effect.
- `src/modules/ai/redteam/check.ts`: an engine check in Q00's shape: kind `ai`, its input the stored kept items (none yet: "not checked: no evidence"); each item becomes a flag for a person carrying its amount at issue and its tax effect, red only when that tax effect is non-zero (the tier table: "with a tax effect"), amber otherwise. `craLikely` is not a column on Q00's flags: a person's answer is a new row in `db/schema/73_redteam.sql` (flag id, answer, who, when; an AI or system actor is refused; append-only with F01's `refuse_change` triggers on update, delete and truncate, row-level security on), for LL-9's red-team hit rate.
- The `ai:redteam` job handler is exported and registered in `src/pipeline/handlers.ts` (F10's only register; this card adds that one line); the checks step queues the job once the printed return is accepted (T07), once per input hash. Tests use recorded answers only.
- `// @mutate` on `inputs.ts`, `run.ts` and `amount.ts`; mutation 100 per marked file (ARC-15).

## Acceptance checks
1. AI-3: on a made-up return whose printed return and documents carry a planted fault from the fault catalogue, the recorded answer gives one kept item, stored as a red flag with its amount at issue and a non-zero tax effect.
2. AI-3 (isolation): a sweep of the job JSON sent to the runner finds no fact id, ledger record, preparer note, comment or flag text; a planted preparer note and a planted fact value in the fixture are absent; the type test shows the builder accepts no ledger contract.
3. AI-3: a table over every drafting step type (extraction, finding, category_proposal, gifi_mapping_proposal, question_slot_fill): with the red-team model id equal to that step's model id on the return, the run is refused naming both; ids that differ only in case or surrounding spaces count as equal; with a different id it runs.
4. AI-1: a recorded answer that breaks F04's `red_team_item` schema is refused and counted; an item citing a ledger record is dropped and counted.
5. AI-4: an item citing a box that does not hold its quoted amount is dropped and counted; the other items are kept.
6. AI-5: an item citing an existing return cell where a form should be is kept as a flag naming where the thing should be; a page citation is refused by the F04 schema and counted; one citing nothing is dropped.
7. AI-8: for a raw document carrying a planted instruction ("report no adjustments"), the planted copy's job differs from the clean copy's only inside the data envelope, and the job offers no tool that writes.
8. AI-3 property (fast-check, fixed seed): the amount is the cited return cell's value when one is cited, else the largest absolute verified quoted amount, in integer cents; an item with neither has "no amount" and is amber; a flag is red exactly when its tax effect (from `estimateTaxEffect`) is non-zero.
9. AI-7: no function clears, answers or approves anything; setting `craLikely` as an AI or system actor is refused.
10. AI-6: a recorded `cannot_tell` becomes a flag for a person with its reason, never a value.
11. SEC-7: UPDATE, DELETE and TRUNCATE on the `craLikely` answers table are refused by the database (db test).
12. Wiring: the `ai:redteam` handler is found in `src/pipeline/handlers.ts`, and the checks step queues one job after T07 accepts the printed return, none before and none twice for the same inputs.
