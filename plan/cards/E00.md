## Goal
When a client's document arrives, Returns takes it in once: fingerprints it, catches a duplicate, keeps the bytes write-once, and prepares every page image and every word box at once, so any source opens fast later (ARC-11, RV-4). Spreadsheets and CSV files are read cell by cell instead. Splitting, classifying and tamper signs are E02's; this card makes every document readable.

## Build
- `src/contracts/documents.ts`: the intake result types (document id, fingerprint, file key, kind of file: pdf, image, sheet, other; page list with image keys and the reading engine per page; status) and the service interface other modules take as a parameter (F10's rule).
- `src/modules/documents/intake/` (it uses storage, reading, sheets and jobs only through `src/contracts`, passed in by the pipeline):
  - `intakeReturn(returnId)`: lists the return's folder through the client-documents contract (A05's Drive stand-in), and for each file not yet seen enqueues one `documents:intake` job (F06; idempotency key = return id + Drive file id + sha256) (ARC-5).
  - The job handler: sha256 fingerprint of the bytes (EV-2). The same fingerprint already on any return is a duplicate: a link row to the first document and an event, and the file is not read again. Otherwise the bytes go to the file store (A05, content-addressed), a document row is written with who gave it and when (from the bridge pointer when there is one), and reading starts.
  - PDFs: A01 reads the text layer; pages A01 reports as "no text layer" go to Tesseract (A02); the document keeps both kinds of page in one reading result with the engine named per page (amber A101: joining them is this card's). Images (JPEG, PNG, HEIC refused with the reason until a free converter is chosen) become one page read by Tesseract. Spreadsheets and CSV files go to the sheets reader (A07) and get no page images (EV-14).
  - Page images: every PDF or image page is rasterised once at a fixed resolution (150 dpi for viewing; the reading engines keep their own) with the free libraries A02 and W20 already use, stored in the file store, and listed on the document with its size. Word boxes come from the reading result. Both are ready before the document's status becomes `ready` (ARC-11).
  - Encrypted, broken or unsupported files are kept (bytes stored, fingerprinted) with status `refused` and the reason, so a person sees them; they never fail silently.
  - Version stamps on every derived row: reading engines and versions, rasteriser version, this card's code release (ARC-10).
  - SEC-11: while go-live is off, a return whose folder lacks "(Test)" is refused before any byte is read (A05 also refuses; this is the second line).
- `src/pipeline/steps/intake.ts`: replaces F10's placeholder with the real step (`intakeReturn`), reporting each document's status.
- `db/schema/10_documents.sql` (F01 wrote the document table): add page rows (document, page number, image key, width, height, engine, version), the duplicate link, the document status and its reason. Append-only where F01's rule says so.
- `src/modules/documents/index.ts`: the module's public exports.
- No log line holds document text or a page image path with a client name; logs name document ids only.
- Version stamps (findings F01-F09, R14): every version stamp this card writes is non-blank scalars only; {}, {"x":null} and {"x":""} are refused by F01's SQL check and VersionStampSchema, so the spec names the stamp's fields and values.

## Acceptance checks
1. EV-2: intake of the C01 folder stores each distinct file once; the second copy of the PDF is linked to the first as a duplicate with an event and is not read again (a spy on the reading contract shows one read).
2. ARC-11: after intake, every page of every PDF and image has a stored page image and word boxes, and the document status is `ready` only when all its pages have both.
3. ARC-11: the mixed PDF's text page is read by the text layer and its scanned page by Tesseract, in one reading result naming the engine per page; F09's `valueInBox` finds a known C01 amount on each.
4. EV-14: the CSV is read by the sheets reader, gets no page images, and its cells are stored with sheet, row and column.
5. ARC-5: running `intakeReturn` twice adds no job and no document the second time; a job that fails once is retried by F06's rules and ends `ready`.
6. EV-2: the encrypted PDF and the HEIC file end `refused` with their reasons, bytes stored and fingerprinted; the other files are unaffected.
7. ARC-10: every page row and reading result carries engine and version stamps; one written without is refused.
8. SEC-11: a folder whose company name lacks "(Test)" is refused before any byte is read.
9. ARC-11, RV-4 timing (cloud): for the largest test-world document available when the spec is written, opening a stored page image and its word boxes by page takes under 200 ms (the remaining budget of RV-4's second is the viewer's).
10. SEC-4: no log line from the run holds any word from the fixture documents (a planted-word scan of the captured log).
