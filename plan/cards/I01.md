## Goal
One way for every owner-manager topic (personal expenses, meals, vehicles, home office, GIFI 9270, shareholder-loan signs, CCPC status, association, dividend refunds) to run: code picks and masks the facts, the AI looks for the issue, code checks every citation, and each grounded finding becomes a flag for a person with its facts and dollar amount. A topic card then only writes a prompt, its fact selection and its recordings.

## Build
- `src/modules/ai/checklist/_core/topic.ts`: a topic definition: id, prompt version and text, model id, `selectFacts(returnId, ledger)` (code chooses the facts; never the whole ledger), the code checks that already cover the subject, and severity. `registerTopic` refuses a topic whose subject is one AI-2 leaves to code (CK-43, CK-30, CK-38, CK-35, CK-41, CK-46), a missing prompt version, or a duplicate id.
- `src/modules/ai/checklist/_core/run.ts`: `runTopic(topic, returnId, deps)`: selects facts, passes them through I00's `groundedStep` (redaction first, AI-9; F04 finding schema; citation checks, AI-4), then turns each kept finding into a Q00 check result of kind `ai`: a flag for a person (CK-5, CK-42) carrying the cited facts, the dollar amount and Q00's tax effect estimate. An "I can't tell" answer becomes a flag saying so (AI-6). A finding on facts an already raised code flag covers (the topic's covering checks, same fact ids) is dropped and counted "already flagged by CK-NN" (AI-2).
- `src/modules/ai/checklist/_core/register.ts`: exposes topics to Q00's registry so they run with the other checks and sort by EX-4.
- No path from a finding to a fact status, an exception answer or an approval: the module gets read-only ledger contracts (AI-7, a type test).
- Tests use recorded answers only (A04's `recorded` engine). A fixture topic (`_fixture-topic`) with its recordings lives in `__fixtures__/`, not in the product.
- `// @mutate` on `run.ts`; mutation 100 per marked file (ARC-15).

## Acceptance checks
1. AI-2: the fixture topic on a made-up C01 return produces one grounded finding citing two facts, stored as a flag with those facts, the amount and a tax effect (CK-42, CK-6).
2. AI-4: a recorded finding with a citation to a fact id that does not exist is dropped and counted against the topic; the other finding is kept.
3. AI-6: a recorded "I can't tell" answer becomes a flag for a person, never a pass and never a value.
4. AI-2: registering a topic whose subject is CK-43, CK-30, CK-38, CK-35, CK-41 or CK-46 is refused; a finding on the same facts as a raised flag from a covering check is dropped and counted "already flagged".
5. AI-9: the facts the AI receives hold no value of a key E03 marks sensitive (a planted SIN fact is selected and must arrive masked).
6. CK-5, AI-7: no function in the module returns pass or fail, or writes a fact status, an answer or an approval (a type test and an export sweep).
7. AI-10: every flag carries the model, prompt version, OCR engine and mapping release from the output stamp.

## Not in this card
Any real topic and its prompt (I10 to I22). Scoring topics on the test world (I40). The red team (I30). Screens.
