## Waits on the trial
No spec job starts until P02 is done and `reference/taxprep/FINDINGS.md` is on main. The spec-writer writes every test below from what FINDINGS.md records, quoting the finding each test rests on. Where FINDINGS.md says a question stayed open, the test pins the simulator's placeholder behaviour and is named "unconfirmed" so the matrix shows it. Real Auto-fill data appears as structure only, never values (decision 0008).

## Goal
The simulator behaves like the Taxprep release the trial used wherever the trial showed how, so every later card is proven against recorded behaviour and not against our guesses.

## Build
- `data/taxprep/releases/<trial release>.json`: the real input-cell identifier list from day 1's "all input cells" export, in S02's format, marked confirmed with the capture date.
- `data/taxprep/trial/`: the recorded settings and behaviour as data: the export settings Taxprep uses (separator, negatives, decimal and thousands), the import text encoding, the token cell never sent to CRA, the roll-forward map (which cell is fed from which cell of last year's return), the diagnostics list with each one's category, which cells Taxprep fills from the GIFI by itself, how copy numbers behave after a delete, whether an import can clear a cell, and how calculated review lines are exported.
- `src/modules/taxprep-sim/trial/`: switches the simulator to the trial's behaviour, reading only that data: the token cell (RT-2), roll-forward on a new year from a prior-year return (RT-24), the cells filled from the GIFI, calculated review lines in the export by the recorded filter or file (RT-10), a printed-return diagnostics list by category (RT-17), the export settings and encoding (RT-9).
- Any S01 fault the trial shows works differently is changed to match, with the finding quoted.

## Acceptance checks
1. RT-23: sample client 01's import, run on the trial release, gives an export equal to the trial's captured export structure for that client (identifiers, order, settings; values from our own made-up file only).
2. RT-2: the token cell is the one FINDINGS.md names; it appears in the export and is listed as never sent to CRA.
3. RT-24: a new year rolled forward from a prior-year return fills exactly the cells the roll-forward map names, from the cells it names.
4. RT-10: the export holds the calculated review lines in the form FINDINGS.md records (one saved filter or a second file).
5. RT-17: the printed-return diagnostics list carries each diagnostic's category as recorded; a Hidden or Ignored diagnostic is still listed as such.
6. RT-9: the export settings and encoding equal the recorded ones; F03's fixed settings are checked against them (a mismatch fails with both named).
7. Every behaviour the trial left open is listed in `data/taxprep/trial/open.json` with the placeholder used, and each has a test named "unconfirmed".

## Not in this card
Updating `reference/sample-clients/lib/taxprep-cells.json` and regenerating the sample CSVs (Lead-run, after the trial). Reading diagnostics from a real printed return (T05). Anything the trial did not record.
