Real Auto-fill data appears as structure only, never values (decision 0008).

## Goal
The simulator behaves like the Taxprep release the trial used wherever the trial showed how, so every later card is proven against recorded behaviour and not against our guesses.

## Build
- `data/taxprep/releases/<trial release>.json`: the real input-cell identifier list from day 1's "all input cells" export, in S02's format, marked confirmed with the capture date.
- `data/taxprep/trial/`: the recorded settings and behaviour as data: the export settings Taxprep uses (separator, negatives, decimal and thousands), the import text encoding, that no cell holds a token (Q23), the roll-forward map (which cell is fed from which cell of last year's return), the diagnostics list with each one's category, which cells Taxprep fills from the GIFI by itself, how copy numbers behave after a delete, whether an import can clear a cell, and how calculated review lines are exported.
- `src/modules/taxprep-sim/trial/`: switches the simulator to the trial's behaviour, reading only that data: roll-forward on a new year from a prior-year return (RT-24), the cells filled from the GIFI, calculated review lines in the export by the recorded filter or file (RT-10), the Diagnostics panel list by category, as text a preparer would copy (RT-17; the printed return carries none), the export settings and encoding (RT-9).
- What the interim findings already settle, for the spec-writer to use as written: the export settings and Windows-1252 (RT-9); calculated cells come in the same export from a filter built with "Select all", unmarked, values with rates to 4 decimals (RT-10, Q22); deleting a copy renumbers the later copies down with no gap (RT-7, Q21); text imported into a calculated cell is accepted, shown and not reported (RT-4); Taxprep calculates Schedule 1 net income, taxable income and Part I tax from the GIFI cells at once (Q25); no cell holds a token (RT-2, Q23: S00 already wipes `IFirm.ContactPartner` on open); an import to the next free copy index creates the copy (RT-7, S00); every exported negative carries a leading apostrophe (RT-3, S00); diagnostics do not print (RULE-2, RT-17); "Import and link corporations" writes about 75 Schedule 23 workchart cells from the linked return (Q25, RT-14, RT-15).
- Any S01 fault the trial shows works differently is changed to match, with the finding quoted.

## Acceptance checks
1. RT-23: sample client 01's import, run on the trial release, gives an export equal to the trial's captured export structure for that client (identifiers, order, settings; values from our own made-up file only).
2. RT-2: the trial data names no token cell, and no simulator release lists one.
3. RT-24: a new year rolled forward from a prior-year return fills exactly the cells the roll-forward map names, from the cells it names.
4. RT-10: the export holds the calculated review lines in the form FINDINGS.md records (one saved filter or a second file).
5. RT-17: the Diagnostics panel text carries each diagnostic's category and `<code>_<cell id>` key as recorded; a Hidden or Ignored diagnostic is still listed as such; the simulated printed return carries none.
6. RT-9: the export settings and encoding equal the recorded ones; F03's fixed settings are checked against them (a mismatch fails with both named).
7. RT-7: deleting copy 1 of two S8 copies (classes 1 and 8) leaves one copy, `CCACat.FD08C[1].FED.Ttw08cA1` = 8, in the export.
8. RT-4: a text value imported into a calculated cell is held and exported, and the import report has no line for it (trial behaviour; the import writer, not the simulator, must refuse it).
9. Every behaviour the trial left open is listed in `data/taxprep/trial/open.json` with the placeholder used, and each has a test named "unconfirmed".
