## Goal
One framework every document reader (E10 to E25) plugs into, so that no number enters the ledger unless code has found it inside its box (or its cell), every fact has exactly one source pointer, arithmetic self-checks run in code, and a failed check or a suspect document marks the facts suspect. It also replaces the walking skeleton's "one fact" stub with the real facts step.

## Build
- `src/modules/extraction/_core/` (it reaches documents, reading results, sheets, the ledger and the AI runner only through `src/contracts`, passed in by the pipeline):
  - The extractor interface: `kind` (a document kind from E02's `kinds.json`), `version`, and `extract(piece, reading | sheet) -> candidate[]`. A candidate: fact key (must be in E03's catalogue, with the value type the catalogue gives), value, row key when the key repeats, and its proposed source (page and box from F09, or sheet, row and column from A07), the method (`code` or `ai`, with the AI stamp when `ai`).
  - The registry: one extractor per kind; a second registration for a kind is refused. A piece whose kind has no extractor is reported "no reader for this kind", never skipped silently.
  - The acceptance gate (EV-6, EV-14): a candidate from a page is accepted only when F09's `valueInBox` holds; one from a sheet only when A07's `cellValueMatches` holds. A failed candidate is rejected with the reason and counted per extractor and per kind (a rejection counter stored with the run, which screens and the lesson list read later). AI candidates pass the same gate; there is no other way in. An AI "I can't tell" for a field (AI-6) becomes a "not read" entry for a person, never a guessed value.
  - Values are converted by the catalogue's value type: money with F09's `normaliseAmount` into integer cents; dates to ISO dates with the layout the extractor names; text trimmed. A value that does not convert is rejected with the reason.
  - Self-checks (EV-7): a small library of arithmetic checks in integer cents that extractors declare (lines sum to their stated total; opening plus activity equals closing, page by page and for the whole statement; debits equal credits on a trial balance). The run records each check, its inputs and the difference in cents. A failed check marks every fact from that extraction `suspect` with the check and the difference.
  - Suspect documents: every fact from a piece E02 marked suspect is stored suspect, with E02's reason. A piece marked "not used" (wrong year or entity) is never extracted.
  - Storing: each accepted candidate is written through the ledger contract's `proposeFact` with exactly one pointer (EV-5): document page and box, or sheet, row and column; the origin comes from the piece's kind (E02's origin key); the version stamp names the extractor version, the catalogue version, the reading engine and version, and this card's code release (ARC-10). The run is idempotent: the same piece read by the same extractor version writes no second fact.
- `data/extraction/labels.json` and a generic labelled-amount extractor in `_core/labelled/`: for a kind listed in the file, it reads the amount that follows a listed label on the same line (label words, fact key, which side the amount sits). Data, not code. It serves simple one-figure pages and the skeleton; E10 to E25 write their own readers.
- `src/pipeline/steps/facts.ts`: replaces F10's placeholder: for every used, classified piece of the return, runs its kind's extractor and returns per piece the facts written, the rejections, the self-check results and "no reader" pieces.
- The skeleton's "one fact" stub is removed: the skeleton's C01 fixture page is read by the labelled-amount extractor through the real facts step (its kind and label go in `labels.json`); `e2e/skeleton/stubs.ts` and `stubs.md` drop the stub; the `e2e/steps/skeleton-*.ts` files call the facts step.
- `src/modules/extraction/index.ts`: the public exports (framework, registry, the labelled-amount extractor). E10 to E25 add their readers through the registry.
- Box (findings F01-F09, RC2): every box this card writes, stores or reads is F09's Box shape (page plus left, top, width and height as page fractions, BoxSchema from src/contracts/reading.ts), never its own {x0,y0,x1,y1}.
- Version stamps (findings F01-F09, R14): every version stamp this card writes is non-blank scalars only; {}, {"x":null} and {"x":""} are refused by F01's SQL check and VersionStampSchema, so the spec names the stamp's fields and values.

## Acceptance checks
1. EV-6: on the clean statement, every candidate is accepted and the stored facts equal the golden file; the amount just outside its box is rejected with "value not found", counted once against that extractor, and no fact is written for it.
2. EV-14: on the CSV trial balance, each candidate's pointer is sheet, row and column and `cellValueMatches` holds; a candidate pointing at an empty cell is rejected with "empty cell".
3. EV-5: every stored fact has exactly one pointer and a fact key from the catalogue; a candidate with an unknown key, or with a value of the wrong type for its key, is rejected with the reason.
4. EV-7: the statement one cent off fails its self-check and every fact from it is stored suspect with the check name and the 1-cent difference; property (fast-check, fixed seed): for any list of line amounts in cents and a stated total, the sum check passes exactly when the total equals the sum.
5. EV-7: facts from the piece E02 marked suspect are stored suspect with E02's reason; a piece marked not used is never extracted (a spy on the extractor shows no call).
6. AI-6: the AI-method candidate passes the same box gate (a planted AI value outside its box is rejected and counted); the "I can't tell" field is listed as not read for a person and no fact is written for it.
7. EV-5: a piece whose kind has no extractor is reported "no reader for this kind"; registering a second extractor for a kind is refused.
8. ARC-10: every stored fact's stamp names the extractor version, the catalogue version, the reading engine and version and the code release; a candidate written without them is refused.
9. EV-5: running the facts step twice on the same pieces writes no second fact and returns deep-equal results.
10. END-2 (skeleton, cloud): the skeleton's one fact now comes from the facts step through the labelled-amount extractor; the stub is gone from `stubs.ts` and `stubs.md`; SK0's checks 1 and 6 still pass.
