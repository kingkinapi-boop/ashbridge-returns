## Re-spec needed (1 Oct 2026)
The first version of this card followed CCH's help page (`[taxpayer name|return id|language]`, `T4SLIP[1].TOATSC4` with `57,565.00`, blank means "no import", CRLF and Windows-1252 as faults). The Taxprep trial showed each of those is wrong for release CCH iFirm 2026.20.198267 (`reference/taxprep/FINDINGS.md`). Any spec written against the old card is void: the spec job starts again from this text.

## Goal
One parser and one writer for Taxprep's CSV files, used by the simulator, the import writer and the export reader, so nobody writes a second one.

## Build
- The file shape Taxprep's export writes (RT-3, RT-9): bytes in Windows-1252, no byte-order mark, CRLF after every line including the last, comma separator, every value in double quotes. Header line `[<return name>|0|0|<GUID>],"Current Year","Last Year",""`; the parser returns the name and the GUID (all zeros allowed) and checks nothing else about them (identity is T02's job, RT-1). Rows: identifier unquoted, then `"current"`, `"last"`, `"description"`. The parser also accepts rows with only the current value or with extra trailing quoted columns (Taxprep's import does), and reports which shape each row had; the writer always writes the four-column shape with the description empty unless given.
- Values: a cell value is either a value or a clear (RT-12): `""` and `" "` parse as a clear, never as zero and never as "no import"; `"0"` is zero. The writer writes a clear only when the row says `clear` explicitly (RT-8); a row with no value is a type error, so a blank cannot be written by accident. Dates YYYY-MM-DD, yes or no as `Y` or `N`, amounts as integers with `-` for negatives and no separators. The parser also reads a negative exported with one leading apostrophe (`"'-1356"`, trial day 3: calculated cell `FDONE.Ttwone66` with the Export dialog's default "-123" negative-number setting, `reference/taxprep/2026-10-03-day3/notes.md`) as that negative number and reports that the row had the apostrophe; the writer never writes an apostrophe. An apostrophe anywhere else, or before a non-negative number, is refused with the row.
- Value kinds for the writer: amount, text, date, yes-no, rate. An amount with cents is refused with the row (RT-25); a text value with a character outside Windows-1252 is refused with the row and the character (RT-9).
- The identifier grammar (RT-21) as a type with a parser that refuses anything else: two or more parts separated by dots, each part letters and digits starting with a letter, with an optional copy index `[n]`, n a whole number from 1, no spaces. It must accept every identifier in `reference/taxprep/2026-10-01-day1/exports/` and `reference/taxprep/2026-10-02-day2/exports/` (for example `IDENT.Ident120`, `GFBGII[1].GFGIJ.Ttwgij104`, `GFGBA.Ttwgba64`, `FDONE.SLIPA[3].TtwoneA2`, `CCACat.FD08C[2].FED.Ttw08cA1`, `IFirm.ContactPartner`). It exposes the copy path (`CCACat.FD08C`) and the copy index, and a function that replaces a copy index.
- A natural-key registry type (RT-7): for each repeating group path, the cell under it that holds the row's natural key (for example `CCACat.FD08C` keyed by `FED.Ttw08cA1`, the CCA class). A helper that, given parsed export rows, returns natural key to current copy index, refusing two copies with the same key.
- The ignored-on-import list (RT-13) as one constant: `IDENT.Ident120`, `IDENT.Ident121` (year start and end) and the contact-synchronised cells the trial saw skipped (`IDENT.Ident311`, `IDENT.Ident492`), each with the finding it rests on; the writer refuses a row for any of them.
- The fixed settings (RT-9) as one constant, and a check that refuses a file written with other settings or re-saved by another program.
- The cell classes of RT-14 as a type.
- Golden-file tests (Vitest `toMatchFileSnapshot`, files in `__golden__/`, owned by the spec-writer).
- The fault set, each refused with a plain reason: a byte-order mark; LF-only line ends (or a missing CRLF on the last line); a tab, semicolon or space separator; unquoted values; negatives as `(123)`; a thousands comma or space inside a number; a decimal comma; scientific notation; a reformatted date (`01/10/2026`); UTF-8 byte sequences (`C3 A9` for é); a header that is not in brackets.

## Acceptance checks
1. RT-3, ARC-14: `reference/taxprep/2026-10-02-day2/exports/rt-07-imported-default.csv` parses and is written back byte for byte (a golden file); so do a made-up file holding a header with a GUID, a zero, a clear, a date, a Y and an N, an accented text value (byte E9), a copy index and a rate, and sample client 01's `import.csv` (all-zero GUID).
2. RT-3: a row with only the current value and a row with two extra trailing columns both parse; the writer writes both back in the four-column shape (golden).
3. RT-12, RT-8: `""` and `" "` parse as a clear and `"0"` as zero; the writer cannot be called with an empty value without the explicit clear flag (type test), and with it writes `""`.
4. RT-9: every member of the fault set is refused with its own reason (one test per member, using a file that differs from a good file in that one way only).
5. RT-9: writing a text value holding a character outside Windows-1252 (for example `≥` or an emoji) is refused naming the row and the character; é, è, ç and à are written as single bytes.
6. RT-25: writing an amount of 7693.52 is refused naming the row; 7694 and -123 are written as `"7694"` and `"-123"`.
7. RT-21: every identifier in the committed trial exports parses; identifiers with no dot, a lower-case or digit first character in a part, a copy index of 0, a non-number index or a space are refused with the row and the reason.
8. RT-7: given export rows with `CCACat.FD08C[1].FED.Ttw08cA1` = 8 (after a delete renumbered class 8 from copy 2), the helper maps class 8 to copy 1; two copies with the same class are refused as duplicates.
9. RT-13: the writer refuses a row for each identifier on the ignored-on-import list, naming it.
10. RT-3 property (fast-check, fixed seed): any list of valid rows (identifiers from the grammar, Windows-1252 text, whole-dollar amounts, clears) survives write then parse unchanged.
11. RT-14: the cell-class type holds exactly the six classes (traced, overridden, dropped, rolled forward, orphan, calculated); any other value is refused.
12. RT-3, RT-9: an export row `FDONE.Ttwone66,"'-1356","",""` (day 3) parses as the amount -1356 with the row marked "apostrophe"; written back it is `"-1356"` (golden); `"'1356"`, `"''-1356"` and `"-'1356"` are refused naming the row; no input to the writer produces an apostrophe (property, fixed seed). T02's export reader rests on this.
