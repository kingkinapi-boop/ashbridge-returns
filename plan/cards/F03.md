## Goal
One parser and one writer for Taxprep's CSV files, used by the simulator, the import writer and the export reader, so nobody writes a second one.

## Build
- The CCH syntax: a header `[taxpayer name|return id|language]`; rows of cell identifier, this year's value, prior year's value; dates as YYYY-MM-DD; copies of repeating forms as `FORM[n].CELL`; "0" is a value; a blank means "no import".
- The identifier grammar (form, copy number, cell) as a type with a parser that refuses anything else.
- A natural-key registry type: for each repeating form, the fields that identify a row (for example CCA class number).
- The fixed export settings (column separator, negative numbers, decimal and thousands separators) as one constant, with a check that refuses a file written with other settings or re-saved by a spreadsheet program (amber: pick the settings and record why).
- The cell classes of RT-14 as a type.
- Golden-file tests (Vitest `toMatchFileSnapshot`, files in `__golden__/`, owned by the spec-writer): a small made-up file in, the same file out.
- The fault set, each refused with a plain reason: other separators, scientific notation, lost leading zeros, reformatted dates, a byte-order mark, CRLF endings, Windows-1252 accents, blank versus "0".

## Acceptance checks
1. RT-3: parse then write returns the same bytes for a file built on CCH's example row (`T4SLIP[1].TOATSC4` with 57,565.00), including a header, a zero, a blank, a date and a copy index.
2. RT-9: a file with other separators or number formats is refused with a plain reason.
3. RT-12: a blank value parses as "no import", never as zero.
4. RT-13: the T2 year-start and year-end identifiers are marked "ignored on import".
5. RT-7: two rows of a repeating form with the same natural key are refused as duplicates.
6. A property-based test (fast-check): any list of valid rows survives write then parse unchanged.
7. RT-9: every file in the fault set is refused with its reason.
