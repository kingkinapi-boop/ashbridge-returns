## When it starts
This card waits until D02 is approved by Zo at a design sitting (RV-53), and D02's pages include the CPA queue (`/review` in the map); the Lead marks D02 done then. If D02's approved pages hold no queue page, the spec job releases the job and reports it to the Lead.

## Goal
The CPA's first screen: every return waiting in review, in the order Zo set (Z20-4: overdue first, then tier, then due date), each row naming the return, its tier in words, both due dates, how long it has waited and whether it is back from rework, with one link to its brief. A second view lists only the returns back from rework.

## Spec
- Fixtures (test world, pinned clock): at least 7 returns in review across red, amber and green tiers, one past its filing due date, two with the same tier and due date, one with a 28 Feb year end, one CCPC on the three-month balance-due rule, two back from rework (moved rework to review) and the rest on their first review; one return in each of approved, rework and trace (never listed); users: the CPA, the owner, a preparer assigned to one of the returns in review, ops.
- Classes:
  - FLOW-2: the queue lists exactly the returns whose current state is `review`; a return in any other state, including one just approved and one sent back to rework, is absent (property, fixed seed: for any set of returns in random states, the listed set equals the set in `review`).
  - RV-8 with Z20-4: the default order equals X01's `queueOrder` for the listed rows (overdue first, then red, amber, green, then filing due date, then longest waiting, then id); any shuffle of the input gives the same rows in the same order; the table states its default order in its caption and sets `aria-sort` (rule 6).
  - RV-8, rule 7: each row's tier shows in words with a non-colour cue, and a "Why this tier" link or details gives X01's reasons; a return X01 has not tiered shows "not set" (a real value, never blank).
  - FLOW-7: each row shows the filing due date and the balance-due date exactly as F02 computes them, including the 28 Feb year end (due 31 Aug) and the three-month CCPC case; an overdue return says so in words and a non-colour cue. Overdue means the pinned clock is past the filing due date (FLOW-12); a past balance-due date shows in words but does not count as overdue.
  - Waiting since: each row shows the time of its latest move into `review` from F02's state events, and the round ("first review" or "back from rework", from the `from` state of that move). A return that went review, rework, review shows the second move's time, not the first.
  - Z20-4 "Back from rework": the second view lists exactly the rows whose latest move into review came from rework, in the same order; an empty view says so in words (no blank table).
  - Rule 21: search by corporation name and a tier filter narrow both views; Back from a brief returns to the view with its search, filter, sort and scroll kept.
  - SEC-2: the CPA and the owner see the queue; the preparer and ops get the same "not found" as an address that does not exist, and the queue's data function returns nothing for them; the preparer's assigned return is not reachable through this page's search.
  - RV-50, rule 16: every row names the corporation and year end; every link leads to a built page (the brief, V02); no placeholder, no dead control.
  - RV-53: the page matches D02's approved queue page within the visual threshold, and D02's budget for "open the next return to review" holds (clicks and page loads).
  - RV-54: U02's sweeps pass on both views and the empty state; the task works by keyboard alone; golden ARIA snapshot of the default view for the fixture set (`e2e/staff/__golden__/`).

Reads only, through contracts passed in; writes nothing. `// @mutate` on the file that picks the latest move and the round (mutation 100, ARC-15).

Shortcuts through U01: next row, open, search.
