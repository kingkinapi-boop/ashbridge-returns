## Goal
One table says, for a named Taxprep release, which Taxprep cell each figure goes to, which figures are never imported because the preparer chooses them in Taxprep, and which cell last year feeds by roll-forward. It is the only Taxprep-specific part of the system (RT-21). This card builds the table's format, its loader and checks, the GIFI rows read from Taxprep's own descriptions, the copy lookup for repeating forms, the whole-dollar rounding with its plug line, and the check that blocks imports when a new release removes or renames a cell the table uses. The schedule cards (M10 to M23) then fill the table one schedule at a time.

## Build
- `src/contracts/mapping.ts` (zod): a mapping row is
  - `figureKey`: a GIFI code (`gifi:8141`) or a schedule line (`s1:line-104`), plus a `rowKey` for repeating rows (the natural key, for example the CCA class `8`);
  - `identifier`: the Taxprep identifier (F03's grammar); for a repeating group, written with copy `[1]` as the template (`CCACat.FD08C[1].FED.Ttw08cA9`), never a fixed copy;
  - `source`: one of `gifi` (from B01's GIFI totals), `fact` (a fact key, imported only when verified, RT-4), `taxChoice` (TB-6: never imported; the preparer types it in Taxprep and cites it), `never` (on F03's ignored-on-import list, RT-13: never imported, checked by export);
  - for people: the form's jump code, the line or GIFI code, Taxprep's description (RT-21);
  - `release`, `confirmed` (true only where a real export listed the identifier), `sourceNote` (where the row came from).
- `data/taxprep/map/_format.md`: the file format the schedule cards write (`data/taxprep/map/<schedule>.json`), one paragraph per field, with two worked rows (`gifi:1002` to `GFGBA.Ttwgba64`, and CCA class additions under `CCACat.FD08C`).
- `src/modules/mapping/core/`:
  - `gifiRowsFromRelease(release)`: reads every identifier whose Taxprep description starts `GIFI code <nnnn> - Amount - ` and returns one `gifi` row per code (RT-21: the code-to-identifier table is read from the export, never typed). The `Account` and `Prior year` cells of each code are recognised and never mapped (prior-year cells are not written). A code with no Amount cell, or two, is reported by code. `data/taxprep/map/gifi.json` is generated from S03's trial release by a script in this card and committed; a test regenerates it and compares.
  - `loadMapping(release)`: loads every `data/taxprep/map/*.json` for the release and refuses, naming the row: an identifier F03's grammar refuses; an identifier not on the release's input list (S02 `isInput`, RT-4), including any on the calculated list, except `taxChoice` rows (Taxprep may list a choice cell as calculated because it defaults to a computed value: trial day 3, CCA claimed); a `gifi` or `fact` row whose identifier is on F03's ignored-on-import list (RT-13: it must be `never`); two rows with the same figure key and row key; two rows writing the same identifier; a repeating-group row whose group has no natural-key cell in F03's registry (RT-7); a `gifi` row for a code `data/gifi/codes.json` marks `calculatedByCra` (TB-12's totals are Taxprep's to compute); a `taxChoice` row whose identifier template is not in `data/taxprep/tax-choices/<release>.json`, or a cell in that file with no `taxChoice` row (the two must agree, so the trace and the import never read different lists).
  - `copyFor(groupPath, naturalKey, latestExportRows)` (RT-7): the copy index holding that natural key in the latest export, using F03's natural-key helper; returns "no copy" when none holds it; refuses when two copies hold it. `targetIdentifier(row, rowKey, latestExportRows)` gives the concrete identifier with the copy index filled, or "no copy: add the copy by hand in Taxprep, export, then re-import" (trial-dependent, see below).
  - `roundGifi(totals)` (RT-25, ARC-13): takes B01's `gifiTotals` (integer cents, signed by normal side) and returns whole dollars per code, rounded half away from zero through `src/core/money.ts`, with 3680 set to the net income of the rounded Schedule 125 codes (CK-11: 3680 equals 9999), plus one rounding item: the difference that keeps Schedule 100 balanced (total assets equal total liabilities plus equity, in whole dollars) put on the liability code with the largest absolute amount (ties broken by the lower code), never on 3600, 3849 or share capital (CK-11: 3849 equals 3600); with no liability code the difference is not placed and the return is flagged "rounding not placed" for a person. The item names the line, the amount in dollars and the codes whose rounding caused it, so the trace can show it as rounding. A difference larger than one dollar per balance-sheet code is refused as "not a rounding difference" with the amount.
  - `blockedImports(mapping, fromRelease, toRelease)` (RT-22): the mapping rows whose identifiers S02's `blockedBy` reports removed or renamed, with the replacement where the rename table gives one; while any remain, `canImport(release)` returns false with the list. A release marked unconfirmed is allowed in the build and named in the result (LIVE-2 needs a confirmed one at go-live).
  - `rollForwardMap(release)` (RT-24): loads `data/taxprep/rollforward/<release>.json`: rows of this year's identifier, last year's identifier (`fromCell`, for people and a later direct lookup) and the prior-year fact key B03 registers (`priorFactKey`). Refuses identifiers outside the grammar or the release. The file for the trial release is written now holding only what FINDINGS.md confirms, marked `confirmed: false` when it is empty or partial.
  - `taxChoiceCells(release)` (TB-6): loads `data/taxprep/tax-choices/<release>.json`: the cells where the preparer makes a tax choice in Taxprep (CCA claimed per class `CCACat.FD08C[n].FED.Ttw08cA22`; the others as M14 to M21 add them), each with the choice kind (CCA claim, dividend designation, election, business limit share, loss claim, donation claim). The trace (T04) treats a filled cell on this list as an orphan that needs a cite even when Taxprep computed it.
  - Every result carries the release name, the mapping files' fingerprints and this card's code release (ARC-10).
- `src/modules/mapping/index.ts`: the module's public exports.
- The skeleton: the "one mapping row" stub in `e2e/skeleton/stubs.ts` is replaced by a call to `loadMapping` for sample client C01's release; it is removed from `stubs.md`.

## Held for the Lead (review-phase2, red 1)
RT-25 puts the rounding plug on GIFI 3600, but CK-11 (CPA-checked, decision 0012) ties 3849 to 3600 and 3680 to 9999. A plug on 3600 breaks the first tie by the plug amount, and rounding each Schedule 125 code on its own can leave 3680 (rounded from the books) apart from 9999 (which Taxprep adds up from the rounded Schedule 125 lines). Settled 1 Oct by the Lead (amber A245, RT-25 changed, on the CPA check list): 3680 from the rounded Schedule 125 total, plug on the largest liability code; `roundGifi` may be specced with the rest.

## Trial-dependent (FINDINGS.md is interim)

If the final findings show an import creates a copy, a later card adds a "next copy" target.
- The roll-forward map (RT-24, day 3 did not run a roll forward). Fallback: the trial release's file is empty and unconfirmed, so no cell counts as rolled forward and Taxprep's rolled values show as orphans for the preparer to cite (a flag for a person, never a silent pass).
- Whether `CCACat.FD08C[n].FED.Ttw08cA22` (CCA claimed) is on the "Select all input cells" list. Fallback: `taxChoice` rows are accepted on either list.
- The T2 jacket, Schedules 3, 4, 23 and 50 identifiers (FINDINGS section 1, not mapped). This card needs none of them; the schedule cards wait for them or keep `confirmed: false`.
