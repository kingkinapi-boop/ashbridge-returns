## Goal
Trial balances, ledgers and bank downloads arrive as spreadsheets and CSV files. They are read directly, cell by cell, never through OCR, and a value taken from one points to its sheet, row and column (EV-14). This card gives the one reader and the one cell check, in the same spirit as F09's `valueInBox`, so extraction and AI citations judge a cell the same way they judge a box.

## Build
- `src/contracts/sheets.ts`: zod schemas and types. A sheet result for one file: the file fingerprint, the engine name and version (ARC-10; refused without them), the time read (injected clock) and its sheets: name, whether hidden, and cells. A cell: row (1-based), column (letter and 1-based number), the text exactly as stored, the type the file gave (text, number, date, boolean, formula with its cached value, empty), whether its row or column is hidden, and the merged range it belongs to. A cell pointer: file fingerprint, sheet name, row, column (EV-5's "sheet, row and column"); for a CSV the sheet name is the fixed `csv`.
- `cellValueMatches(result, pointer, value)` (EV-6 for cells): true only when the value, normalised with F09A's `normaliseAmount` for money (no amount pattern of its own; any amount format it names comes from F09A's `AMOUNT_FORMATS`) or trimmed and case-folded for text, equals the cell's stored value; otherwise false with the reason ("no such cell", "empty cell", "value differs", "formula cell: cached value differs").
- `src/modules/sheets/csv/`: a CSV reader written here (RFC 4180 quoting, embedded commas, quotes and line breaks). It detects and states the encoding: UTF-8 with or without a BOM, otherwise Windows-1252 (accents read correctly); CRLF and LF both read; the separator is a comma or, when the first line says so unambiguously, a semicolon or tab, and the result names the separator used. Values are kept as stored text: leading zeros stay, "1.2E3" stays text, blank and "0" stay different.
- `src/modules/sheets/xlsx/`: reads .xlsx with one free, open-source library (ExcelJS or similar: no account, no key, no network, exact version pinned, `npm audit --audit-level=high` clean; not the `xlsx` package from npm, whose npm release carries known high advisories). Dates come back as ISO dates (the 1900 date system, including its 29 Feb 1900 quirk, and the 1904 system); formulas keep their cached value and are marked as formulas, never recalculated; hidden sheets, rows and columns are listed as hidden, never dropped. Old .xls and password-protected files are refused with the reason.
- The adapter shape: `read(fileBytes, fileName) -> sheet result | refusal`, engine name, `isLive` false (there is no live side: reading files is local work).
- Same bytes, same result (fingerprint cache like A01's ARC-11 rule).

## Acceptance checks
1. EV-14: reading C01's chequing download returns every cell with sheet `csv`, row and column; the cell holding a known amount from C01's answer key is found by its pointer, and `cellValueMatches` holds for it.
2. EV-14: the BOM, CRLF and Windows-1252 copies give the same cells as the clean file (the payee's accents read correctly) and the result names the encoding; the semicolon copy names its separator.
3. EV-14: the quoted payee with a comma and a line break is one cell; the leading-zero reference keeps its zeros; "1.2E3" stays text; the blank cell and the "0" cell differ.
4. EV-5: a pointer to a sheet, row or column that does not exist is refused with "no such cell"; a pointer without a sheet name is refused by the schema.
5. EV-6: `cellValueMatches` accepts "$1,234.56" against a cell storing 1234.56, refuses 1234.57, and on the formula cell compares the cached value and says so in the reason when it differs.
6. EV-14: the .xlsx fixture returns its dates as the expected ISO dates in both date systems, the formula cell marked with its cached value, the hidden sheet and hidden row listed as hidden, and the merged range on each merged cell.
7. EV-14: the .xls and password-protected files are refused with the reason; nothing is written.
8. ARC-10: a sheet result without engine name and version is refused by the schema.
9. EV-14 property (fast-check, fixed seed): any table of strings written as RFC 4180 CSV (with commas, quotes and line breaks in values) and read back gives the same table.
10. END-8: the new dependency needs no account, key or payment, and `npm audit --audit-level=high` stays clean.
