## Goal
One shape for every check, so each of the 26 check cards can be built side by side against it.

## Build
- The check record of CK-1: id (the clause, for example CK-20), kind (tie, reconciliation, flag, AI), when it applies (a function of the return), inputs, rule, source link, and what it raises.
- A result type: pass; fail with both amounts; "not checked: no evidence" (CK-2); flag (CK-5).
- A reconciliation result: both amounts, the difference, the reconciling items (each typed from a fixed list and sourced), and the unexplained remainder (CK-4).
- An exception type: its dollar amount in cents and an estimated tax effect (CK-6).
- A tie compares to the dollar (CK-3): amounts are integer cents; the comparison uses the one rounding rule in `src/core/money.ts` (GIFI reports whole dollars), so a statement rounded line by line either still ties or carries a recorded rounding item.

## Acceptance checks
1. CK-2: "not checked: no evidence" never counts as a pass in any summary function.
2. CK-4: a reconciliation with items that explain the difference exactly raises nothing; one dollar unexplained raises an exception.
3. CK-5: a flag cannot be turned into a pass by code.
4. CK-1: a check record with no source link fails validation.
5. CK-3, ARC-13 property (fast-check, fixed seed): for any amounts in integer cents, a tie passes if and only if the absolute difference is under 100 cents (amber: "to the dollar" read as a difference under one dollar, not "both round to the same dollar", which would fail 100.49 against 100.51); amounts already rounded to whole dollars (GIFI) compare equal or carry a recorded rounding item.
6. CK-4, ARC-13 property: for any reconciliation, difference equals the two amounts' difference exactly, and the unexplained remainder equals the difference minus the sum of the items, in integer cents.
7. CK-6: an exception with no dollar amount or no estimated tax effect fails validation.
8. CK-4: a reconciling item whose type is not on the fixed list, or that has no source, fails validation.
