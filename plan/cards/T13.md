## Goal
After a return is filed, ops saves CRA's notice of assessment. Returns reads it (E18), compares each assessed amount with the same line of the filed return, saves the assessed amounts as the `assessed` version (LL-1), and moves the return from filed to assessed. An assessment that differs from the filed return opens a follow-up item for a person (FLOW-8), never a silent pass; only the CPA or the owner closes it, with an outcome and a reason. AI never compares, closes or decides anything here.

## Trial-dependent (real notices are not seen until go-live)
- Which lines a notice carries and how they read: the test world's W29 notices set the shape. Fallback in force: `data/assessment/notice-lines.json` maps each E18 notice fact key to a T07 review-line meaning key of the filed return (data, not code); a notice line with no mapping is a difference "not on the filed return" for a person, never skipped; adding a mapping is an amber row.

## Spec
- Fixtures (simulator, S00, test world, pinned clock): C01 taken to `filed` through T09's fixtures (passed check, filing record); W29 notices for C01: one equal to the filed return on every mapped line; one with Part I tax changed by one cent; one with the balance owing changed and a line the mapping file does not name; a scanned copy of the equal notice; the equal notice's bytes saved twice; a notice naming another corporation; a non-PDF file; users: ops, the CPA, the owner, a preparer, an AI actor.
- Classes:
  - FLOW-8 compare (match): the equal notice gives no difference and opens no follow-up item; the compare result names each mapped line with filed and assessed values in integer cents.
  - FLOW-8 compare (differs): each changed line is a difference naming the line, the filed value, the assessed value and the change in cents; the unmapped line is a difference "not on the filed return"; any difference opens exactly one follow-up item listing them all. Property (fast-check, fixed seed): changing any one mapped line by any non-zero amount gives exactly that difference; changing none gives none.
  - The filed side: filed values are T07's `reviewLines` of the check export of T09's passed check for the standing approval (its `check` version), never a later or earlier export.
  - LL-1: a compared notice saves exactly one `assessed` version through N00 (cells from the notice's facts, owner by N00's rule) in the same transaction as the compare result and the move; when that save throws (a fake), nothing is kept and the state is still `filed`.
  - FLOW-2 (filed to assessed): guard `filed_to_assessed` passes only with a notice saved for the return after its move into `filed`, its compare result stored and its `assessed` version saved; each refusal names what is missing. A direct F02 move filed to assessed without them is refused by the guard.
  - FLOW-8 follow-up item: `closeFollowUp` by the CPA or the owner stores the outcome (`accepted`: CRA's figures accepted; `amend`: an amended return to start, T14; `objection`: an objection filed outside Returns) with a non-blank reason; a second close is refused; while an item is open, T10's freeze waits (the close emits the event T10's binder step listens for).
  - EV-2: the notice is stored write-once with its fingerprint; the same bytes saved twice are caught by the fingerprint and linked, not read twice; the scanned copy reaches the same facts through E18 or names what it could not read, and then no compare runs.
  - Refusals: a notice naming another corporation is refused naming it; a non-PDF is refused; a notice for a return in any state other than `filed` is refused naming the state; nothing is stored for any of them.
  - Who (AI-7, SEC-2): a preparer, an AI actor or the system saving a notice or closing a follow-up item is refused with the reason and nothing is stored; ops may save a notice but not close a follow-up item.
  - SEC-7: UPDATE, DELETE and TRUNCATE on every table this card adds are refused (db test on PGlite and Postgres 16).
- Golden file (`src/modules/assessment/__golden__/`): C01's compare result and follow-up item for the one-cent Part I tax change.

## Build
- `src/contracts/assessment.ts` (zod): the notice record, the compare result (lines with filed and assessed cents, differences), the follow-up item and its close (outcome list exactly `accepted`, `amend`, `objection`), and the service interface. It names the ports it takes: the storage contract (A05), E18's reader, T09's passed check and filing record, T07's `reviewLines`, N00's `saveVersion`, F02's lifecycle, V00's access contract.
- `src/modules/assessment/`:
  - `receiveNotice(returnId, bytes, fileName, actor, deps)`: state and actor checks; stores the file write-once (A05, EV-2); E18 reads it into facts; the compare against the filed return through `data/assessment/notice-lines.json`, all money in integer cents through the money helpers; then, in one transaction (FX5's caller transaction): the notice record, the compare result, a follow-up item when any difference exists, N00's `saveVersion(returnId, 'assessed', noticeId, actor)`, and F02's move `filed` to `assessed`. Throws on F02's `{ ok: false }` so nothing is kept.
  - `closeFollowUp(itemId, outcome, reason, actor, deps)`: the CPA or the owner only; refused for AI or system (AI-7); the blank rule from `src/contracts/text.ts` on the reason; emits the "follow-up closed" event through `src/pipeline/handlers.ts`.
  - `openFollowUps(returnId)`: the open items (T10 reads it before freezing).
  - Guard `filed_to_assessed` as above, registered with F02's lifecycle in `src/pipeline/deps.ts`.
  - `// @mutate` on the compare, the mapping loader and the guard (mutation 100 per marked file, ARC-15).
- `data/assessment/notice-lines.json` (E18 fact key to T07 meaning key, with a source per row); refused on load if a row lacks a source or a key is doubled.
- `db/schema/82_assessment.sql`: notices, compare results with their lines, follow-up items and closes; append-only with F01's `refuse_change` triggers, row-level security on, no policies, `is_test`, a foreign key on every return_id, CHECK lists on outcome.
