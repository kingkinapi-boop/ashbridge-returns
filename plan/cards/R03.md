## Goal
The shapes every later module uses: a Taxprep CSV file, a cell identifier, a cell class; an AI output with citations; a check record and its result.

## Build
- Taxprep: a parser and a writer for CCH's CSV syntax: the header `[taxpayer name|return id|language]`; rows of identifier, this year, prior year; dates YYYY-MM-DD; copies as `FORM[n].CELL`; "0" is a value; a blank means "no import". The identifier grammar; a natural-key registry type (form, key fields); the fixed export settings as one constant (amber: pick separators and record why); the cell classes of RT-14.
- AI: one JSON schema per step type (finding, extraction, category proposal, mapping proposal, question slot fill, cause tag), each with a citations array whose items are one of: ledger record, document box with the quoted text, return cell. A version stamp type (model, prompt version, OCR engine, mapping release).
- Checks: the check record of CK-1 (id, kind, applies, inputs, rule, source, raises); a result that is pass, fail with both amounts, "not checked: no evidence", or flag; an exception with its dollar amount and estimated tax effect.
- Import these contracts by their own path; do not edit `src/contracts/index.ts`.

## Acceptance checks
1. RT-3: parsing then writing gives back the same file for rows built on CCH's example (`T4SLIP[1].TOATSC4` with 57,565.00), with a header, a zero, a blank, a date and a copy index.
2. RT-9: a file with other separators or number formats is refused, with a reason.
3. RT-12: a blank value parses as "no import", never as zero.
4. RT-7: two rows of a repeating form with the same natural key are refused as duplicates.
5. AI-1: an output with no citations fails validation; AI-5: a "missing" finding citing where the item should be passes.
6. CK-2: a "not checked: no evidence" result never counts as a pass.
