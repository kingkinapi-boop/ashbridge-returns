## Goal
The simulator can produce every way a real round trip goes wrong that RT-23 names, on purpose and the same way every time, so the cards that must catch them (T01, T02, T04, T09) each have a planted fault to prove against.

## Build
- `src/modules/taxprep-sim/faults/`: one function per fault, each taking a simulated return or an export file and a fixed seed, returning the faulty result plus a fault record (name, what changed, the clause that must catch it). Faults:
  - partial import: only the first n rows of a file are applied, the rest silently missing (RT-14 dropped cells; RT-1);
  - wrong client: an export from a different return, or with another business number or year end in its header (RT-1);
  - reordered copies: copies of a repeating form renumbered after a delete, so copy numbers no longer match the rows that were imported (RT-7);
  - stale export: an export taken before the latest import (RT-1);
  - spreadsheet-mangled numbers: the F03 fault set applied to an export (other separators, scientific notation, lost leading zeros, reformatted dates, a byte-order mark, CRLF endings, Windows-1252 accents, blank against "0") (RT-9);
  - an edit outside the trace: a cell changed by hand after lock, with no import in between (RT-20).
- A catalogue listing every fault with its clause, read by tests elsewhere, so a new fault cannot be added without a clause.
- Faults change only what their record says; everything else stays byte-identical.

## Acceptance checks
1. RT-23: the catalogue holds exactly the six faults above, each with a clause; a fault with no clause cannot be added (the type refuses it).
2. RT-1: the wrong-client export's header differs from the return's in the business number or year end, and nothing else in the file differs.
3. RT-1: the stale export equals the export taken before the latest import, and differs from the current export in exactly the cells that import changed.
4. RT-7: after the reordered-copies fault, a repeating form's rows hold the same natural keys under different copy numbers; their values are unchanged.
5. RT-9: each spreadsheet-mangled export is refused by F03's parser with the reason for that mangling (one test per member of the fault set).
6. RT-20: after the edit outside the trace, the export differs from the last lock export in exactly one cell, and the simulator's event list shows no import between them.
7. Partial import: the import report says all rows applied while the export lacks the dropped rows (the fault hides itself, as the real risk would).
8. Determinism: every fault run twice with the same seed gives the same bytes; a different seed may pick other rows but the fault record always names what changed.

## Not in this card
Catching the faults (T01, T02, T04, T09 do that). Faults the trial adds (S03 extends this catalogue).
