## Goal
Heavy work (reading documents, AI steps, diffs) runs as jobs in one table: each job is idempotent, retried with a limit, never lost, and every return shows the status of its jobs (ARC-5). The runner is behind an interface so it can be swapped. Other modules use jobs only through `src/contracts/jobs.ts`, never by importing this module (F00's boundary rule); the handlers are wired in `src/pipeline/` (F10).

## Build
- `db/schema/80_jobs.sql`: table `returns.jobs`: id, kind (text, `<module>:<step>`), return id (nullable for jobs with no return), idempotency key (unique), input (jsonb), status (`queued`, `running`, `done`, `failed`, `dead`), attempts, max attempts (default 3), run after, lease holder and lease until, result (jsonb), last error (text), the version stamps of whatever produced the result (ARC-10), created_at, finished_at, `is_test boolean not null default true`. Row-level security on, no policies (SEC-6), as every F01 table.
- `src/contracts/jobs.ts`: zod schemas and types for a job, a job status, a handler (`kind`, an input schema, a result schema, an optional lease length, `run(input, ctx) -> result`), and the `JobQueue` interface: `enqueue(kind, key, input, returnId?)`, `claim(workerId, kinds?)`, `complete(id, result, versions)`, `fail(id, error)`, `statusForReturn(returnId)`. The `Runner` interface: `runOnce()` and `runUntilIdle()`.
- `src/modules/jobs/queue.ts`: the Postgres queue. Enqueue with an existing key returns the existing job and writes nothing. Claim takes the oldest queued job whose run-after has passed, with `FOR UPDATE SKIP LOCKED`, and sets a lease (default 10 minutes, from the injected clock; a handler may name its own lease, and `ai:*` handlers name 24 hours, A04's Lead note). A job whose lease ran out is claimable again and keeps its attempt count.
- Retries: a failed run sets `queued` with run-after pushed back by a fixed backoff (1, 4, 16 minutes; no random jitter, so tests are pinned, ARC-16); after max attempts the job is `dead` with its last error, and stays visible. A job is never deleted.
- A result is checked against the handler's result schema before `done`; a result that fails is a failed run with the schema problems as the error. An unknown kind is `failed` with "no handler for <kind>", never claimed forever.
- `src/modules/jobs/runner.ts`: the in-process runner (takes a queue, a handler map, the clock). A second, synchronous test runner in the same folder runs the same handlers, to prove the runner can be swapped.
- `statusForReturn`: counts by status per kind for one return, plus the dead jobs with their errors, and per kind the oldest `created_at` among jobs still queued or leased (the preparer queue, V05, shows "Waiting on AI run" with it for `ai:*` kinds), for the screens later.
- `src/modules/jobs/index.ts`: the module's public exports (queue, runners).
- Version stamps (findings F01-F09, R14): every version stamp this card writes is non-blank scalars only; {}, {"x":null} and {"x":""} are refused by F01's SQL check and VersionStampSchema, so the spec names the stamp's fields and values.

## Acceptance checks
1. ARC-5: enqueueing the same kind and key twice gives one row and the same job id; a different key gives a second row.
2. ARC-5: a handler that throws twice then succeeds ends `done` after three attempts; the run-after times follow the fixed backoff from the pinned clock.
3. ARC-5: a handler that always throws ends `dead` after max attempts, with the last error text; `statusForReturn` lists it under dead.
4. ARC-5: a claimed job is not claimed again while its lease holds; after the pinned clock passes the lease, it is claimable and its attempt count is kept.
5. ARC-5: a result that fails the handler's result schema leaves the job not `done`, with the schema problem in the error; an unknown kind fails with "no handler for" and the kind.
6. ARC-5: the in-process runner and the test runner, given the same jobs, handlers and clock, give the same final statuses and results (deep-equal).
7. ARC-10: `complete` with no version stamp is refused; a done job stores the stamp it was given.
8. ARC-16: the backoff has no randomness: two runs of check 2 give identical rows.
9. SEC-6: row-level security is on for `returns.jobs` and a role with no grants reads zero rows; the table has `is_test` (F01's catalog checks pass with the new table included).
10. ARC-5: a job is never deleted: a DELETE on `returns.jobs` is refused (trigger), and `dead` jobs stay listed.
11. ARC-5: a handler that names a 24-hour lease keeps its job leased at 10 minutes and at 23 hours on the pinned clock and claimable again after 24 hours; a handler with no lease of its own gets the 10-minute default.
12. ARC-5: with two `ai:` jobs for one return enqueued at two pinned times, one queued and one leased, `statusForReturn` gives the earlier time as the kind's oldest open job; once both are done, the kind has no oldest open time.
