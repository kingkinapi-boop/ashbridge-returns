# D01 Staff screen map and navigation

Phase 1. Size M. Deps: TH (test homes: its tests need a Vitest project and the tsconfig include). Where: any.
Paths: design/map/**
Clauses: RV-1, RV-20, RV-30, RV-40, RV-50, RV-51, SEC-2
Read: blueprint 02 (the lifecycle), 06 (screens), 08 (SEC-1, SEC-2), `reference/design-basis.md` section (c).

## Goal
Every staff screen named once, with its address, who may see it, what it is for and how people move between them, so every design card and screen card agrees before anything is drawn.

## Build
- `design/map/screens.md`: one row per screen: name, address, roles that see it (preparer, ops, CPA, owner, per SEC-2), the lifecycle states it serves (blueprint 02), the clauses it meets, its states worth designing (empty, normal, error, flagged, approved, void), and the GOV.UK or MOJ pattern it is built from (design basis section c).
- `design/map/navigation.md`: the service navigation by role, the identity bar on every return screen, where each button leads, what Back does, and the keyboard shortcuts (one list for the whole app).
- A simple diagram of the flow between screens (Mermaid in markdown).

## Acceptance checks
1. RV-1, RV-20, RV-30, RV-40, RV-50: every RV clause in blueprint 06 is met by at least one screen in the map.
2. RV-20, RV-30: every lifecycle state with a person acting (blueprint 02) has a screen where that person acts.
3. SEC-2: no screen is reachable by a role that SEC-2 says may not see it.
4. RV-50: every button and link in the map leads to a named screen (no dead ends).
5. RV-51: every keyboard shortcut repeats a visible control and none clashes with browser or screen reader keys.

## Not in this card
Drawing the screens (D02 to D10).
