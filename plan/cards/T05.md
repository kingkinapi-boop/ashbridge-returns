## Goal
The diagnostics Taxprep shows are read from the printed return and each is handled by its category: errors block, warnings need a named preparer's written reason the CPA will see, information may stay with a logged reason, and nothing hidden counts as cleared.

## Build
- `data/taxprep/diagnostics/categories.json`: each iFirm severity word with its rule (RT-17): `Error` and `Filing error` block with no override; `Warning` needs a written reason by a named preparer, shown in the brief; `Informative` (RT-17's Information) and `Filing warning` may stay with a logged reason; `Hidden` and `Ignored` never count as cleared and are handled by their underlying severity, or as `Error` when none is shown. Each entry cites the trial note it rests on, or says "not seen in the trial".
- `src/contracts/diagnostics.ts` (zod): a diagnostic is severity, code (for example `R2000100`, `M5`, `G123`, `N1`, `P71`), cell identifier when shown, type (EFILE or General), form and text. Its key is code plus cell identifier (FINDINGS: keyed on their ids), so the same diagnostic on a later printed return is matched.
- `src/modules/diagnostics/`:
  - `readDiagnostics(printedReturnId)`: finds the diagnostics page or pages in E00's reading of the printed return and parses each row into the contract; a row it cannot parse is kept as text and treated as `Error` with "not parsed" (a flag for a person, never dropped); a printed return with no diagnostics page gives "no diagnostics page found", which is a blocker, not a clean result.
  - `readPastedDiagnostics(returnId, text, actor)`: the fallback below: the same parser over the text a preparer copies from Taxprep's Diagnostics panel; the result is marked "pasted, not read from the printed return".
  - An unknown severity word is treated as `Error` and named.
  - `explainDiagnostic(returnId, key, reason, actor)`: records a reason with the preparer's name for a Warning, Informative or Filing warning; refused for Error and Filing error, for an empty reason, and for an AI actor (AI-7).
  - `blockingDiagnostics(returnId)`: from the latest printed return (or paste) for the latest lock export: every Error, Filing error, unparsed row, unknown severity, and every Warning without a reason; Informative without a reason is listed but does not block. T12's sign-off reads this.
  - Stored append-only in `db/schema/47_diagnostics.sql` (new file for the module), linked to the printed return and lock export; every result carries the categories file's fingerprint and the code release (ARC-10).

## Trial-dependent (FINDINGS.md is interim)
- Whether the printed return shows open diagnostics, and in what layout (RT-17; day 3 printed an Office copy but could not read it). RULE-2 says CCH confirmed diagnostics print with the return. Fallback in force until a person reads a printed return: the parser takes the row layout of `diagnostics-probe.md` (severity, code, cell, type, form, text), the test-world printed return (T07) uses that layout, and `readPastedDiagnostics` lets a preparer paste the panel's text if the real printed return carries none.
- The final severity list: `Filing warning`, `Hidden` and `Ignored` were not seen; what the panel's "Reviewed" tab does is unknown. Fallback: the rules above; a reviewed diagnostic is treated by its severity, never as cleared.
