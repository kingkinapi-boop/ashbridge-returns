## Goal
The diagnostics Taxprep shows are read from the list the preparer copies from Taxprep's Diagnostics panel and pastes with the lock export (RT-17: the printed return carries none), and each is handled by its category: errors block, warnings need a named preparer's written reason the CPA will see, information may stay with a logged reason, and nothing hidden counts as cleared.

## Build
- `data/taxprep/diagnostics/categories.json`: each iFirm severity word with its rule (RT-17): `Error` and `Filing error` block with no override; `Warning` needs a written reason by a named preparer, shown in the brief; `Informative` (RT-17's Information) and `Filing warning` may stay with a logged reason; `Hidden` and `Ignored` never count as cleared and are handled by their underlying severity, or as `Error` when none is shown. Each entry cites the trial note it rests on, or says "not seen in the trial".
- `src/contracts/diagnostics.ts` (zod): a diagnostic is severity, code (for example `R2000100`, `M5`, `G123`, `N1`, `P71`), cell identifier when shown, type (EFILE or General), form and text. Its key is code plus cell identifier (FINDINGS: keyed on their ids), so the same diagnostic on a later printed return is matched.
- `src/modules/diagnostics/`:
  - `readPastedDiagnostics(returnId, lockExportId, text, actor)` (RT-17): parses the text a preparer copies from Taxprep's Diagnostics panel (All tab, Hidden tab too) into the contract, linked to that lock export; a row it cannot parse is kept as text and treated as `Error` with "not parsed" (a flag for a person, never dropped); an empty paste is refused (a return with no diagnostics at all is not expected: an empty return shows 23 or 24); refused for an AI actor (AI-7). The paste and its author are kept. A later paste for the same lock export is a new version with an event; the earlier one stays, and a key in the earlier list missing from the later one is named "gone since the earlier paste" for a person, so a paste can never quietly shorten the list.
  - An unknown severity word is treated as `Error` and named.
  - `explainDiagnostic(returnId, key, reason, actor)`: records a reason with the preparer's name for a Warning, Informative or Filing warning; refused for Error and Filing error, for an empty reason, and for an AI actor (AI-7).
  - `blockingDiagnostics(returnId)`: from the latest paste for the latest lock export: every Error, Filing error, unparsed row, unknown severity or code, every Warning without a reason, and every "gone since the earlier paste" not acknowledged by a person; "no diagnostics list for the latest lock export" when none is pasted; Informative without a reason is listed but does not block. T12's sign-off reads this.
  - Stored append-only in `db/schema/47_diagnostics.sql` (new file for the module), linked to the lock export; every result carries the categories file's fingerprint and the code release (ARC-10).
