## When it starts
Every screen is designed first and Zo approves the designs before any is built (RV-53, end state item 12). This library is what every screen is built from, so it waits for the approved look: D00 counts as done only when Zo has approved D00's sample page at a design sitting (the Lead marks it done then, as the design family does for D02 to D12). The queue holds U00 until then.

## Goal
The thin React layer every staff screen is built from (RV-52): one typed component per GOV.UK or MOJ component the designs use, emitting exactly the official HTML, styled only by the official packages with the Ashbridge Tax settings (RV-55), and accessible by default (RV-54). Screens never write GOV.UK markup by hand.

## Build
- Dependencies (pinned, `npm audit --audit-level=high` clean): `govuk-frontend` 6.x and `@ministryofjustice/frontend` 11.x (both MIT) and `sass`; `nunjucks` as a dev dependency for the fixture tests. If F00 or D00 already added one, keep its version.
- `src/ui/styles/app.scss`: the only stylesheet. `@use` GOV.UK Frontend with the settings from `design/basis/settings.scss`, then MOJ Frontend, then the `app-` classes listed in `design/basis/parts.md`, and nothing else.
- `src/ui/govuk/<component>.tsx`: one server-rendered React component per GOV.UK component listed in `design/basis/parts.md`, at least: skip link, generic header, service navigation, footer, back link, breadcrumbs, button, text input, password input, textarea, character count, select, radios (including small), checkboxes (including small), date input, fieldset, label, hint, error message, error summary, file upload, summary list, table, tabs, tag, details, inset text, warning text, notification banner, panel, pagination, task list. Props are typed from each component's `macro-options.json`.
- `src/ui/moj/<component>.tsx`: the MOJ parts listed in `parts.md`, at least: identity bar, sortable table, filter and filter a list, side navigation, sub navigation, button menu, timeline, alert, scrollable pane, page header actions, add another.
- Where GOV.UK and MOJ both offer a part, only GOV.UK's is built (tag over badge, service navigation over MOJ primary navigation), as `reference/design-basis.md` decides.
- JavaScript: official GOV.UK and MOJ JavaScript starts in an effect scoped to the component, only where it enhances markup React leaves alone (tabs, character count, button menu, service navigation, file upload). Where it would rewrite DOM React owns (sortable table rows, multi select, conditional reveals), React does the behaviour with the same markup, classes and ARIA. `src/ui/scripts/supported.tsx` writes the `govuk-frontend-supported` class with the inline snippet GOV.UK documents.
- Behaviour the rules need, built once here: the error summary takes focus on render and its links focus their fields (rule 9); a button that waits on the server shows its loading state at once and prevents a double submit (rule 9); no component renders a disabled button (rule 8: the prop does not exist); every table component requires a caption and scoped headers, and money cells take integer cents and print them with tabular figures through one formatter (rule 5); tags and dots take words, never a colour alone (rule 7).
- `src/ui/index.ts`: the public exports. `src/ui/README.md` lists every component with its GOV.UK or MOJ source and its MOJ status.
- `e2e/ui/gallery.spec.ts` with a static gallery page built from every component's fixture examples (rendered with React's server renderer into `e2e/ui/__gallery__/`, styled by the compiled `app.scss`), for the browser checks; no route is added to the app.

## Test fixtures
- GOV.UK's own `fixtures.json` for each component (read from `node_modules/govuk-frontend/dist/govuk/components/<name>/fixtures.json` at test time, never copied). For MOJ parts, option sets written by the spec-writer in `src/ui/moj/__fixtures__/` and rendered through MOJ's official Nunjucks macros at test time.

## Golden files
None (the official fixtures and macros are the expected HTML).

## Acceptance checks
1. RV-52: for every GOV.UK component built, every fixture in its `fixtures.json` (except those marked hidden or for template-only options the component does not offer, each such skip listed with its reason in the test) renders HTML equal to the fixture's `html` after whitespace and attribute-order normalisation.
2. RV-52: for every MOJ component built, each option set renders HTML equal to the official MOJ Nunjucks macro's output for the same options.
3. RV-52: every component named in `design/basis/parts.md` exists in `src/ui/index.ts`, and nothing is exported that `parts.md` does not list.
4. RV-52, RV-55: the compiled `app.scss` contains only `govuk-`, `moj-` and listed `app-` class selectors, uses Roboto and the brand colours, and contains no GOV.UK crown, logotype or GDS Transport font face.
5. RV-54: axe with tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, through JH0's shared axe fixture, finds no violation on the gallery page (cloud).
6. RV-54: on the gallery page, every interactive component is reachable and operable by keyboard alone in a fixed tab order, and the focused element always has a visible focus style not hidden by any other element (cloud).
7. RV-54: the error summary takes focus when it renders and each of its links moves focus to its field; the waiting button shows its loading state and a second click sends nothing (a counter).
8. RV-54: the button component has no `disabled` prop (a type test that fails to compile with one); the table component refuses to render without a caption; the tag and dot components refuse a colour with no words.
9. RV-52: the sortable table sorts by each sortable column with the right `aria-sort` and announces the order, with React owning the rows (no MOJ script touches the table body: a spy).
10. RV-54: at 320 CSS px wide the gallery page scrolls sideways only inside labelled scrollable regions (cloud).
