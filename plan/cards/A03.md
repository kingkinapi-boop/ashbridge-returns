## Goal
A reading engine that replays a stored reading result for a known document, so tests that only need words (extraction, citations, journeys) run fast and identically without running Tesseract, and so a live vendor's answers can later be replayed the same way. A missing or stale recording fails loudly; it never falls back to another engine.

## Build
- `src/modules/ocr/recorded/`: engine `recorded`. A recording is one JSON file: the document fingerprint (sha256 of the bytes), the source engine's name and version, the time it was recorded (from the injected clock, pinned in tests), and the F09 reading result. Recordings live in a folder the caller names (each card keeps its own under its `__recordings__/`).
- `read(document)`: finds the recording by the document's fingerprint and returns its result, validated by F09's schema. The result's engine is `recorded` and its version is `<source engine>@<source version>`, so every derived record still says which engine really read the page (ARC-10).
- No recording for the fingerprint: refused with "no recording for <fingerprint>: re-record". A recording whose stored fingerprint differs from its file name, or whose result fails F09's schema, is refused with the reason. Never a silent fallback to `textlayer` or `tesseract`.
- `record(document, engine, folder)`: runs the given engine once and writes the recording (sorted keys, LF endings, so the file is the same every time). It refuses a document whose made-up data flag is not set by the caller (test world only, SEC-11: the function takes an explicit `testWorld: true`).
- `src/modules/ocr/index.ts`: add `recorded` to the engine switch; the default stays `textlayer`.

## Test fixtures (spec-writer, `src/modules/ocr/recorded/__fixtures__/` and `__recordings__/`)
- A01's one-page fixture PDF (copied by the spec script, not edited) and its recording made with `textlayer`; a second made-up PDF with no recording.

## Golden files (spec-writer, `src/modules/ocr/recorded/__golden__/`)
- The recording file for the fixture, so `record` is proved byte-stable.

## Acceptance checks
1. ARC-6: reading the fixture with `recorded` returns words deep-equal to reading it with `textlayer`, and F09's schema accepts the result.
2. ARC-10: the replayed result's engine is `recorded` and its version names the source engine and version.
3. ARC-16: reading a PDF with no recording fails with "re-record" and the fingerprint; changing one byte of the fixture PDF makes it fail the same way.
4. ARC-16: a recording whose file name and stored fingerprint differ, or whose result fails F09's schema, is refused with the reason; nothing falls back to another engine (a spy on `textlayer` shows zero calls).
5. ARC-16: `record` on the fixture writes a file byte-identical to the golden recording, twice in a row.
6. SEC-11: `record` without `testWorld: true` is refused and writes nothing.
7. ARC-6: switching the adapter to `recorded` and back to `textlayer` works both ways.
