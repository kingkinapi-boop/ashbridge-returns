## Goal
Every record in blueprint 03 exists as a table in schema `returns` and as a TypeScript type, so later cards build in parallel against a fixed shape.

## Build
- One SQL file per module in `db/schema/`: `00_schema.sql` (schema returns), `10_documents.sql`, `20_ledger.sql` (facts, links, events), `30_books.sql` (accounts and adjusting entries as read from QBO, never edited here (TB-1, TB-2); the GIFI mapping record (TB-3); judgment inputs: values typed in Taxprep with their cite (TB-6)), B04 adds `35_qbo.sql` (snapshots), `40_figures.sql`, `50_returns.sql` (returns, state events, holds), `60_versions.sql` (versions, version cells, approvals), `70_checks.sql` (check results, exceptions, answers), `90_learning.sql` (differences, lessons). F07 adds `05_bridge.sql` and F06 adds `80_jobs.sql`; this card writes neither.
- Every table: id, created_at, `is_test boolean not null default true`, and the version stamps blueprint ARC-10 names where they apply.
- Append-only: events, versions, version cells, approvals and entry lines refuse UPDATE and DELETE (trigger). Facts and entries change by writing a new version row.
- Constraints: an adjusting entry counts as explained only when its lines net to zero and it has a type, a reason and at least one source (TB-2); a fact has exactly one source pointer kind; origin is one of the five in EV-10; fact status is one of the three in EV-8; an account has one GIFI code per version.
- Row-level security enabled on every table, no policies (deny-all).
- The first lines of every core file carry `// @mutate` (here `records.ts` and `ids.ts`); `npm run mutate:changed` at least 70 before reporting.
- `src/contracts/records.ts` mirrors the tables; `ids.ts` names the id kinds. `index.ts` re-exports these two only; later contracts are imported by their own path.

## Acceptance checks
1. EV-1, SEC-7: an UPDATE or DELETE of an event, version, version cell or approval fails.
2. TB-2: an adjusting entry whose lines do not net to zero, or with no type, reason or source, cannot be marked explained.
3. EV-5: a fact with no source pointer, or with two, is refused.
4. EV-10: an origin outside the five is refused.
5. EV-8: a fact status outside the three is refused.
6. TB-3: an account with two GIFI codes in one version is refused.
7. SEC-6: row-level security is on for every table in schema returns (a catalog query), and a role with no grants (standing in for the public key) reads zero rows from every table after a row is inserted.
8. ARC-2: every table is in schema `returns`; no table is created in `public` (a catalog query).
9. Every table has `is_test`.
10. ARC-10: facts, figures and check results refuse a row with no version stamp.
11. FLOW-1: a return has exactly one current state (a second current state for the same return is refused), and a state change with no event (who, when, from, to, why) is refused.
12. A test inserts one row into every table from a typed object, so the types and the tables agree.
13. SEC-7, EV-1: TRUNCATE is refused on every append-only table (events, state events, versions, version cells, approvals, entry lines, judgment inputs).
14. TB-2: explaining an adjusting entry is refused when its sources hold `[null]`, `[""]`, `["  "]` or `[{}]`, when it has a single 0-cent line, or when it has fewer than two lines.
15. EV-5, EV-14: a document pointer needs exactly one of (page and box) or (sheet, row and column), and those fields are refused with any other pointer kind; a QBO pointer needs the snapshot and the account (the transaction where there is one); the box is F09's Box shape without the page (fractions 0 to 1, left plus width and top plus height at most 1), never `{x0,y0,x1,y1}`.
16. FLOW-1: two state events in one transaction, a back-dated event, and ids 'se-2' against 'se-10' all resolve to the right current state (order by an identity sequence, never created_at or id); one event licenses one move only; a state outside the 16 is refused in from and to; a return inserted in any state other than intake is refused.
17. EV-1, FLOW-1: a blank or all-space actor, reason or author is refused on events, state events and judgment inputs.
18. ARC-10: a version stamp `{}`, `{"x":null}` or `{"x":""}` is refused by the SQL check and by the zod schema alike (stamps are non-blank scalars).
19. FLOW-4, EV-1: adjusting entries and judgment inputs carry version_no; an in-place UPDATE of a value column on facts, adjusting entries or judgment inputs is refused (status and explained may still change); DELETE is refused on all three; judgment inputs are append-only.
