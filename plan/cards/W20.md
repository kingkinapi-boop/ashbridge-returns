## Goal
One framework every test-document renderer (W21 to W38) uses: lay out a made-up document from test-world data as a born-digital PDF, record every value's page and box in an answer file, and turn any rendered PDF into a "scan" (an image-only PDF) with its boxes carried over. Then reading and extraction are tested against known truth, and every renderer card is small.

## Build
- Free libraries only, exact versions pinned, no account, key or network: `pdf-lib` (writing PDFs) and, for scans, `pdfjs-dist` (already added by A01) with `@napi-rs/canvas` (prebuilt, no build tools) to rasterise pages. `npm audit --audit-level=high` stays clean.
- `testworld/render/_core/layout.ts`: primitives a renderer calls: page (Letter, portrait or landscape), text at a position, a labelled amount, a table with a header row that repeats when it runs onto the next page, lines and boxes, a header and footer with page numbers. Standard fonts only (Helvetica family, WinAnsi), so accented names such as "Société" render and read back.
- Every value placed through `placeValue(key, value, format)` is recorded: key (the fact or figure key from the kind's expected answers), the value (integer cents for money, text otherwise), the printed text, the page, and the box as F09 fractions (from points with F09's converter). Amounts are printed from cents by F09A's `formatAmount` with a format named from F09A's `AMOUNT_FORMATS` (dollar sign optional, thousands commas, two decimals, brackets or a minus for negatives as the renderer asks); W20 keeps no amount format or pattern of its own.
- `testworld/render/_core/answer.ts`: the answer-file schema (zod): document id, document family, client or kind id, page count, fingerprint (sha256 of the PDF bytes), and the placed values. Duplicate keys on one document are refused.
- `testworld/render/_core/render.ts`: `render(doc) -> { pdf: bytes, answer }`, deterministic: fixed creation and modification dates, a fixed document id, a fixed producer string, no clock reads, so the same input gives the same bytes on any machine.
- `testworld/render/_core/scan.ts`: `toScan(pdf, answer, { seed, dpi, skewDegrees, noise })`: rasterises each page, applies a small seeded rotation and seeded speckle, writes a new PDF holding only the page images (no text layer), and returns a new answer file whose boxes are moved by the same rotation (the box becomes the bounding box of the turned rectangle). Same input and seed give the same bytes on the same platform; scan bytes committed anywhere are made on the cloud Linux runner only.
- Made-up data guard (SEC-11): `render` refuses a document whose person or company names lack "(Test)" or whose business number passes its check digit, by calling W00's guard.
- A short `testworld/render/_core/README.md`: how a renderer card uses the primitives (one example renderer in the test folder, not a real document family).

## Test fixtures (spec-writer, `testworld/render/_core/__fixtures__/`)
- A tiny made-up document definition for sample client C01 (`loadClient('C01')`): a header with the company name, a period line, a table of 60 transaction lines (so it runs onto a second page), an opening and a closing balance, one negative amount, and one accented name ending "(Test)".

## Golden files (spec-writer, `testworld/render/_core/__golden__/`)
- The fixture's answer file as JSON (`toMatchFileSnapshot`), and the sha256 of its PDF bytes. Scan bytes are not golden (platform rasterisers differ); the scan's answer file is golden.

## Acceptance checks
1. EV-6: every value in the fixture's answer file is found by F09's `valueInBox` in the words A01 reads from the rendered PDF, at the recorded page and box; none is found when its box is moved one box-width to the right.
2. ARC-16: rendering the fixture twice gives byte-identical PDFs (same sha256), equal to the golden fingerprint; a scan made twice with the same seed gives identical bytes; a different seed gives different bytes.
3. ARC-8 property (fast-check, fixed seed): any integer cents up to 10^13, placed with each format in F09A's `AMOUNT_FORMATS` (the test iterates the exported table, never its own list), prints text that F09A's `normaliseAmount` turns back into the same cents.
4. ARC-8: the 60-line table runs onto page 2 with the header repeated; every box lies inside its page (all fractions 0 to 1) and on the page the value is printed on.
5. EV-6: the scan of the fixture has no text layer on any page (A01 reports "no text layer" for each), and each moved box in the scan's answer file still contains its value's centre on the rasterised image (checked by drawing the box on the image's pixel grid within one percent of the page).
6. SEC-11: a document whose company name lacks "(Test)", or whose business number passes its check digit, is refused with the reason and nothing is written.
7. ARC-8: an accented name ending "(Test)" renders and A01 reads it back exactly.
8. ARC-8: the answer-file schema refuses a duplicate key, a box outside the page and a missing fingerprint, each with the reason.
9. ARC-18: the new dependencies need no account, key or payment, and `npm audit --audit-level=high` stays clean.

## Not in this card
Any real document family (W21 to W36), the scans of chosen test-world documents (W37) and messy files (duplicates, wrong year, tampered, split and merged: W38). Spreadsheet and CSV documents (W25 uses A07's shapes). Reading documents in the product (A01, A02, E00).
