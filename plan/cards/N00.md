## Goal
Every return keeps, automatically and unchangeably, the versions the learning loop compares (LL-1), and every cell in each version says who owns it (LL-2), keyed so two versions can be compared by figure and natural row, never by copy number (LL-3). This card saves the versions phase 2 produces and gives later cards (approval, the check export, the notice) one call to save theirs.

## Build
- `src/contracts/versions.ts` (zod): version kinds exactly `ai-raw-facts`, `ai-draft`, `preparer`, `cpa-final`, `check`, `assessed`; a version cell (identifier, figure key, natural row key, value, owner); owners exactly `ai-filled`, `held-back`, `preparer-only`, `rolled-forward`, `calculated`; the service interface.
- `src/modules/learning/versions/`:
  - `saveVersion(returnId, kind, sourceRef, actor)`: one version per call, with its cells and owners, stored in `db/schema/60_versions.sql` (F01's tables; append-only, SEC-7), each with the version stamps of what made it (ARC-10). A second save of the same kind for the same source is refused; a new source (a new lock export at a later sign-off) makes a new version with an event.
  - `ai-raw-facts`: the first version of every fact on the return whose method is extraction or AI, before any person changed or verified it (from the ledger contract's history), saved with the AI draft.
  - `ai-draft`: import version 1 (T01): every row is `ai-filled`; every mapped figure that was waiting or held back is listed `held-back` with no value.
  - `preparer` (called by T12 at sign-off), and later `cpa-final` (T08) and `check` (T09): from a traced lock or check export (T04): cells classed traced, overridden or dropped are `ai-filled` (Returns imported them; a later compare shows what the preparer changed); orphans, including tax choices and `allowed` cells, are `preparer-only`; rolled forward is `rolled-forward`; calculated is `calculated`; mapped figures never imported are `held-back`.
  - `assessed`: the shape only (cells from the notice, owner by the same rule) for the phase 4 card that reads notices; not called here.
  - `cellsByKey(versionId)` (LL-3): the version's cells keyed by figure key and natural row key; cells with no mapping row are keyed by identifier with the copy index removed and the natural key added where the group has one.
- `src/pipeline/steps/import.ts`: after T01 writes import version 1, it saves `ai-raw-facts` and `ai-draft` (one added call; T01's behaviour is unchanged).
- `src/modules/learning/index.ts`: the module's public exports (N01 and later cards extend it).
- Version stamps (findings F01-F09, R14): every version stamp this card writes is non-blank scalars only; {}, {"x":null} and {"x":""} are refused by F01's SQL check and VersionStampSchema, so the spec names the stamp's fields and values.

## Acceptance checks
1. LL-1: after the `import` step for C01, an `ai-raw-facts` and an `ai-draft` version exist; `ai-raw-facts` holds the facts' first values, including the one the preparer changed before the draft.
2. LL-2: in `ai-draft` every row is `ai-filled` and the waiting and held-back figures are `held-back`; in the `preparer` version the owners match the golden file (traced, overridden and dropped `ai-filled`; orphans and tax choices `preparer-only`; rolled forward; calculated).
3. LL-2: only `ai-filled` cells are returned by the "counts against the AI" query.
4. LL-3: `cellsByKey` on the version before and after S01's reordered copies gives equal keys for the same natural rows, although their copy numbers differ.
5. LL-1: a second `saveVersion` of the same kind and source is refused; a later sign-off on a new lock export makes a second `preparer` version with an event.
6. EV-1, SEC-7: version and version-cell rows cannot be updated or deleted.
7. ARC-10: every version carries the stamps of what made it (mapping release, import version, trace, code release).
