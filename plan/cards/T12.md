## Goal
Every value a person typed in Taxprep gets a source or a written reason in one step, every override gets a reason, every dropped cell is re-imported or explained, and the preparer cannot sign off until all of that is done and no blocking diagnostic remains. Signing off saves the lock export as the preparer version. This is the service behind the cite button (V12) and the checklist's sign-off (V06).

## Build
- `src/modules/roundtrip/resolve/`:
  - `cite(returnId, exportId, cell, choice, actor)` (RT-16, TB-6): `choice` is exactly one of a source pointer as EV-5 lists (a document box, a QBO line, a client answer, a CRA data capture, last year's return) or a written reason. Records a judgment input (cell, value, natural row key, source or reason, author: F01's judgment input table) and a fact through the ledger contract with that pointer, origin from the pointer (a written reason is origin judgment, EV-10), so L01 gives the dot. Refused for a cell not classed orphan, for an `allowed` orphan (needs none), for an empty reason, and for an AI actor (AI-7: the actor type refuses it).
  - `candidateSources(returnId, value)` (RT-16): facts, QBO lines and answers on the return whose amount equals the cell's value exactly (cents equal to the whole dollars), then, listed apart as "rounds to this value", those that round to it; never pre-selects one and never cites by itself.
  - `explainOverride(returnId, exportId, cell, reason, actor)` and `explainDropped(...)` (RT-14): a written reason, recorded with the person; a dropped cell is also resolved when a later re-import and export show it traced.
  - Carry-over: a resolution is keyed by identifier, natural row key and value. On a new lock export, a cell whose class and value are unchanged keeps its resolution; a changed value needs a new one (and the old fact is not reused).
  - `markReady(returnId, actor)` (FLOW-2): the preparer's "Ready" after locking in Taxprep (blueprint 02: prepare leaves when locked and Ready is pressed): asks F02's contract to move the return from prepare to trace; refused for an AI actor (AI-7) and outside prepare. V06's lock step calls it.
  - `blockers(returnId)` (RT-18, RT-17): "no accepted lock export" while the return has none in trace; then, from the latest trace (T04) and diagnostics (T05, which also reports a missing printed return): orphans with no cite (not `allowed`), overrides with no reason, dropped cells not resolved, cells flagged "changed outside the trace" with no reason, and T05's blocking diagnostics; each with the cell, its class and what resolves it.
  - `signOff(returnId, actor)` (RT-18): refused while `blockers` is not empty (listing them) or for an AI actor; otherwise saves the lock export as the preparer version (N00 `saveVersion`, kind `preparer`) and asks the lifecycle (F02's contract) to move the return from trace to respond (FLOW-2), in one transaction. This is RT-18's sign-off of the trace (blueprint 02's trace exit). Registers guards `prepare_to_trace` (passes only for a person's `markReady` in prepare) and `trace_to_respond` (passes only when `blockers` is empty and the preparer version for the latest lock export is saved) with F02's lifecycle in `src/pipeline/deps.ts` (C1 of reports/phase3-card-review-2026-10-03b.md). The preparer's signature that leaves respond for review belongs to the exception cards (phase 3), which must call `blockers` again and refuse while it is not empty; if the return comes back to trace, a new lock export and sign-off save a new preparer version (N00).
  - Resolutions are append-only rows in `db/schema/45_roundtrip.sql`; every write uses the injected clock and has an event.

## Test fixtures (spec-writer)
- T04's C01 fixture trace (an orphan, a typed CCA claim, an override, a dropped cell, an `allowed` orphan, a "changed outside the trace" flag), facts and a QBO line holding the orphan's exact value and one that rounds to it, T05 diagnostics with one Error and one Warning, a second lock export in which the cited cell's value changed; a return in prepare and one in trace with no lock export yet.

## Acceptance checks
1. RT-16, TB-6, EV-5: citing the CCA claim with a written reason records a judgment input and a fact of origin judgment (purple dot through L01); citing the orphan with a document box records a fact with that pointer; each is one call and one event.
2. RT-16: `candidateSources` lists the exact-value fact and QBO line, lists the rounding one apart, and selects none; citing never happens without an explicit call.
3. AI-7: `cite`, `explainOverride`, `explainDropped` and `signOff` with an AI actor are refused by the type and at run time.
4. RT-14: an empty reason is refused; an `allowed` orphan cannot be cited and is never a blocker.
5. RT-18, RT-17: with no accepted lock export, or with any one of a missing printed return, an uncited orphan, an unexplained override, an unresolved dropped cell, an unexplained "changed outside the trace" flag or a blocking diagnostic, `signOff` is refused listing exactly what remains; with all resolved it succeeds, saves the preparer version and the return is in respond.
6. RT-18: a dropped cell re-imported and traced in a new export is no longer a blocker without a written reason.
7. RT-18, RT-16 (carry-over): on the second lock export the unchanged cells keep their resolutions; the cited cell whose value changed is a blocker again.
8. FLOW-2: `signOff` on a return not in trace is refused by the lifecycle; nothing is saved.
9. EV-1: resolutions cannot be updated or deleted.
10. FLOW-2, AI-7: `markReady` moves a return in prepare to trace with one event; it is refused outside prepare and for an AI actor, and nothing changes.
