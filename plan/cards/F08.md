## Goal
The tools that hand out work and report coverage are tested like product code, so a bug in the queue or the matrix cannot silently let two workers collide or a clause look covered when it is not. This extends `tools/test/`; it does not repeat the claim and scope tests P04 wrote.

## Build
- Acceptance tests in `tools/test/*.acceptance.test.mjs`, run by the Vitest config F00 made (add `tools/test/**` to the `unit` project's include if F00 left it out; that one line is in scope through F00's file only if F00 is done, otherwise note it for the Lead).
- Every test copies `tools/` into its own temp folder beside a small `plan/slices.json`, a small `blueprint/` and a few test files, as `queue.test.mjs` does (the tools find their root from their own location). No test reads or writes the real `plan/` or `blueprint/`.
- Two small changes to `matrix.mjs` (amber for the Lead to log when the card lands): a clause counts as covered only when it opens a test name (`test(`, `it(` or `describe(` followed by a string starting with the ID), not when it appears anywhere in the file, so a comment never makes a clause look tested; and a `*.acceptance.test.*` file with a test whose name opens with no clause ID is listed as a problem.
- Clock pinned the way `queue.test.mjs` pins it (`CLAIMS_NOW`); no network; temp folders removed after the run.
- Fix in `tools/*.mjs` only what a failing acceptance test shows is wrong; any fix is listed in the build report.

## Acceptance checks
1. ARC-19 `lib.globToRegExp` and `pathsOverlap`: `src/**` overlaps `src/a/b.ts` and not `srcx/a`; `a/*.ts` does not match `a/b/c.ts`; two disjoint globs never overlap; overlap is symmetric (a fast-check property over generated path lists, fixed seed).
2. ARC-19 `next.mjs`: picks only `carded` cards whose deps are all `done`; never picks two cards with overlapping paths in one run; skips a card whose paths overlap an in-flight card and names it as blocked by paths; never returns more than the slot count; output order is stable for the same input.
3. ARC-19 `next.mjs`: a card that depends on a `parked` card is not picked.
4. ARC-9 `matrix.mjs`: a clause that opens a test name in a `*.test.ts`, `*.test.mjs` or `*.spec.ts` file counts as covered by that file; a clause only in a comment or in the middle of a test name does not; a clause marked "(removed in v...)" is not listed as needing a test; RULE, OUT and LIVE clauses are never listed as uncovered.
5. ARC-9 `matrix.mjs --plan`: exits 1 and names each case for a card citing an unknown clause, a testable clause no card cites, a carded non-family card with no card file or no "Acceptance checks" section, and an unknown dependency; exits 0 on a clean fixture.
6. ARC-12 `matrix.mjs`: a test in a `*.acceptance.test.*` file whose name does not open with a clause ID is reported with its file and name; `plan/MATRIX.md` is written into the temp folder only, with the counts the fixture implies.
7. ARC-19 `status.mjs`: prints the counts per status from the fixture and exits 0; a `slices.json` that does not parse exits non-zero with the file name in the message.
8. The 14 tests in `tools/test/queue.test.mjs` still pass unchanged.
