## Goal
A04's round 4 security findings (3 Oct, A446) have causes that can bite any module that reads a folder another process writes, puts an id in a path, waits in a loop, starts a child process or sets a test flag.

## Spec
Each rule first failing on its plant, KNOWN entries in SC's shape with an open owner card:
- **R93** every fs write, rename, open, mkdir or read in `src/**` whose path holds a non-literal segment sits in a function that first calls a named grammar check (`AiJobIdSchema`, storage `KEY`, `assertSafe`, `realInside`). Plant: a write to `inbox/${id}.json` with none.
- **R94** every file read in `src/**` goes through `readRegularFile`, except a listed repo-data allowlist (db/schema, data/, `__recordings__`), and file names from such a folder are logged quoted. Plant: `readFileSync` of an `outbox/` path. KNOWN: storage/drive, storage/files (owner FX7).
- **R95** every loop that awaits a sleep or timer checks a deadline or abort signal inside the loop. Plant: `for (;;) { await sleep(10) }`.
- **R96** every child process `src/**` starts has a timeout and is stopped by its own PID, never by name. Plant: `spawn` with no timeout (A08's launcher is the first subject; owner A08).
- **R97** `isTest` or `is_test` is written into a job only in `src/pipeline/**`. Plant: a step module building `{ isTest: true }`.
