## Goal
Every Taxprep export the preparer or ops uploads is read once, kept write-once, and accepted only if it is provably this return's export and not an old one. Taxprep checks nothing on import (RT-1), so every identity check runs here, on the export.

## Build
- `src/contracts/roundtrip.ts` (zod): the export record (id, return, kind: lock or check, file key and fingerprint, uploader, time, header name and GUID, release, the parsed cells: identifier, current value, last-year value, description) the service interface, and the `ImportHistory` interface (the latest import of a return: its id, token, the cells it wrote and the cells it changed, with values) that T01 implements; this card's tests pass a fixture implementation. T01, T04, T07 and T12 extend this file one card at a time.
- `db/schema/45_roundtrip.sql`: the roundtrip module's tables (new file, one per module as F01 set): exports, export cells, and the GUID recorded for each return; append-only (EV-1), row-level security on, no policies.
- `src/modules/roundtrip/export/`:
  - `receiveExport(returnId, kind, bytes, fileName, uploader)`: stores the bytes write-once through the storage contract and fingerprints them (EV-2; the same bytes uploaded twice are linked, not read twice), parses them with F03 only (RT-9: any re-saved or mangled file is refused with F03's reason), then runs the identity checks below in this order and stops at the first refusal, naming it. A refused export is kept with its reason and never used.
  - Identity (RT-1): the business number cell `IDENT.Ident7` equals the return's business number, and the year-end cell `IDENT.Ident121` equals the return's year end (YYYY-MM-DD); either missing from the file is refused as "export filter incomplete: add <identifier>". The header GUID is recorded from the return's first accepted export; a later export with another GUID is refused, and an all-zero GUID in an export is refused.
  - Filter completeness: every non-repeating identifier the imports wrote (from `ImportHistory`), and every mapped identifier for copies that exist, appears as a row (Taxprep lists every cell of a filter, empty ones as `""`: FINDINGS section 2). Missing rows are refused as "export filter incomplete" with the list, so a dropped cell is never confused with a cell the filter left out. Repeating groups are different (RT-7, RT-22: a filter lists cells only for copies that exist): imported repeating cells are matched by natural key through F03's helper, never by copy number; a natural key the imports wrote that no copy in the export holds (the preparer deleted the copy) is returned as "missing: <group> <natural key>", for the trace to class as dropped (RT-14: "blank or missing"), and the export is not refused for it.
  - Staleness (RT-2): when the release names a token cell (S00's placeholder in the simulator; a confirmed cell once S03 records one), the export must hold the latest import's token, or it is refused as stale. When no token cell is confirmed (the real release today), the content test runs instead, cell by natural key for repeating rows: the cells the latest import changed are compared with the export. It is refused as stale when none of them holds import N's value and every one of them still holds its value from before import N (from the previous accepted export, or empty when there was none); otherwise it is accepted and the cells that differ from import N are returned as "differs from import N", for the trace to class as overridden and for the sign-off to require a reason (T04, T12). So an import that changed one cell which the preparer then typed over is accepted with that cell overridden, not refused.
  - Byte equality (RT-20): an export whose bytes equal the return's last accepted export of the same kind is recorded as "no change" with a pointer to it.
  - Release (RT-22): every identifier in the export is looked up in the release's lists; identifiers on neither list are returned as "not in release <name>" for the Lead (a sign of a new release), never dropped silently.
- `src/modules/roundtrip/index.ts`: the module's public exports (this card creates it; T01, T04, T07 and T12 extend it).

## Trial-dependent (FINDINGS.md is interim)
- The token cell (Q23 open). Fallback in force: the content test above; the placeholder token runs only in the simulator.
- Negatives in calculated cells exported as `'-1356` with the default "-123" setting (day 3, one cell). The parse is F03's; this card's check 9 needs F03 to read `'-123` in an export as -123 and never write it. If F03's re-spec does not include it, this card's spec job reports it to the Lead before writing tests. If later trial days show the apostrophe in input cells too, nothing here changes.
- Whether the lock filter can include `IDENT.Ident7` and `IDENT.Ident121` in the same saved "Select all" filter as the review lines (RT-10). Fallback: the identity check refuses an export without them, naming them, so a wrong filter is caught on the first upload.

## Acceptance checks
1. RT-1: the wrong-client export is refused naming the business number, and a copy with only the GUID changed is refused naming the GUID; nothing from either reaches the export cells of the return.
2. RT-1: the export with `IDENT.Ident121` missing is refused as "export filter incomplete: add IDENT.Ident121"; an export whose year-end cell holds another year end is refused naming both dates.
3. RT-1: the first accepted export records its GUID; an export with an all-zero GUID is refused.
4. RT-2: with the simulator's placeholder token, the stale export is refused as stale; the good export is accepted.
5. RT-2 (content test, no token cell): the stale export (no changed cell holds import N's value) is refused as stale; the export with one cell typed over is accepted and returns exactly that cell as "differs from import N"; the one-cell import whose cell was typed over (holding neither the old nor the new value) is accepted with that cell as "differs from import N".
6. RT-9, ARC-14: each spreadsheet-mangled export is refused with F03's reason for it; the good export's record equals the golden file.
7. RT-20: the second identical export is recorded "no change" with a pointer to the first, and no cell comparison runs.
8. RT-14: the export missing an imported non-repeating cell's row is refused as "export filter incomplete" listing that identifier.
9. RT-9: a calculated cell exported as `'-1356` is stored as -1356 (needs F03, see above).
10. RT-22: the identifier on neither list is returned "not in release" by name; the export is still accepted.
11. EV-1, EV-2: the same bytes uploaded twice give one stored file and two upload events; a refused export is kept with its reason; updating or deleting an export row fails.
12. RT-7, RT-14: after S01's reordered copies with one imported CCA copy deleted, the export is accepted; the deleted class is returned as "missing: CCACat.FD08C <class>"; the class renumbered from [2] to [1] is matched to its import by natural key and is neither missing nor "differs from import N".
