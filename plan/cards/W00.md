## Goal
The typed model every test-world kind is written in, loaded first with the ten sample clients exactly as `reference/sample-clients/` holds them, so every later card proves itself on the same made-up companies the Taxprep trial and the QBO sandbox use. There is never a second invented set (ARC-8).

## Build
- `testworld/model/`: zod schemas and types for a test-world client: the corporation (name ending "(Test)", made-up business number, year start and end), shareholders and related companies, onboarding answers (the client app's hand-over), accounts and transactions, statement balances by month, adjusting entries (lines, type, reason, sources), the trial balance by account and GIFI code, the T2 inputs, HST, and the flags that must fire, each with the clause that raises it when the sample data names one.
- Money as integer cents everywhere (ARC-13). The sample files hold dollars with two decimals; one converter turns a decimal string into cents without floating point and refuses three decimals or a thousands separator.
- `testworld/clients/C01` to `C10`: thin loaders that read each folder of `reference/sample-clients/` (answer key, onboarding, profile, the account CSVs and the QBO CSVs) into the model. They read the files in place and never copy or rewrite them; a change to a sample client is made there and regenerated with its own script. Loading goes by folder number for every numbered folder present, so folders 11 to 15 (W14, W15) load with no change here; a folder with no account files (12, K05) loads with an empty account list, and an answer key's `prior_year` block (11, K01) loads when present.
- Model checks run on load and fail with the client, the record and the reason: entries net to zero; the trial balance balances (debits equal credits); each account's monthly balance rolls (opening plus activity equals closing) except where the client's planted fault says it does not, and then the fault must be listed; every transaction has an account; every GIFI code is four digits; every adjusting entry has a type, a reason and at least one source.
- Made-up data guard (SEC-11): every person and company name ends in "(Test)" (or carries TEST inside a bank description, as the README says); every business number and SIN fails its check digit; no e-mail address outside a reserved test domain; no phone number outside the 555-01xx range. A loader that meets anything else refuses the client.
- The fault catalogue: a typed list of planted faults (client or kind, what is planted, the exact flag or exception it must raise, the clause) that W01 to W13 add to through `testworld/kinds/<kind>/faults.ts`; here it holds the faults the ten sample clients already plant (their `flags` and the profile's planted issues).
- The kinds register: K1 to K13 from blueprint 00 with the sample client each starts from (or "new"), so W01 to W13 slot in; a kind with no folder yet reports "not built", never passes. Ids are two-digit, `K01` to `K13`, matching the W cards and `testworld/kinds/<kind>/` (blueprint 00's K1 is K01); client ids are `C01` upward, one per folder.
- `testworld/index.ts`: `loadClient(id)`, `loadKind(id)`, `listKinds()`, `faults()`; everything deterministic (no clock reads, no random without the client's fixed seed).
- `testworld/generate.ts`: re-runs `reference/sample-clients/generate.mjs` and `make-csv.mjs --check` into a temp folder and fails if the output differs from what is committed (byte-identical regeneration), so the sample clients cannot drift from their generator.

## Acceptance checks
1. ARC-8: all ten sample clients load through the model with no validation errors, and their names, year ends and account counts equal the README table.
2. ARC-13 property (fast-check, fixed seed): any decimal string with up to two decimals converts to cents and back to the same string; "1,234.56", "1.234" and "1e3" are refused with a reason.
3. ARC-13: for every client, the adjusted trial balance's debits equal its credits in cents, and every adjusting entry nets to zero, and each account's adjusted balance equals the answer key's trial balance line (what `verify.mjs` checks, now in cents through the model).
4. ARC-8: a client with one transaction removed (built in the test from C04) fails the roll check for that account and month with the reason; C10's missing May is accepted only because its fault is listed.
5. SEC-11: a client whose owner name lacks "(Test)", or whose business number passes its check digit, is refused by the loader with the reason; every one of the ten real sample clients passes.
6. END-9: `listKinds()` returns K01 to K13 with the starting sample client the blueprint 00 table names; a kind with no folder yet reports "not built" and any test that asks for it fails, never skips.
7. ARC-8: every flag in each answer key appears in the fault catalogue with a non-empty expected result.
8. ARC-16: loading the same client twice gives deep-equal results; `generate.ts` reports byte-identical regeneration on a clean checkout and names the file when one sample file is changed by a byte.
