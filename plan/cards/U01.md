## Goal
Staff work many returns a day, so screens are keyboard first (RV-6, RV-51): next flag, next number, open source, comment, reviewed and next section, approve. This card gives one registry every screen uses, so every shortcut repeats a visible control, is announced and listed, stays out of the way while typing, can be turned off when it is a single key, and never lets one key approve, send, unmark or delete.

## Build
- `src/ui/keyboard/`:
  - `shortcuts.ts`: the app's shortcut list, read from D01's `design/map/navigation.md` table into typed data (key, action name, kind: `move` or `focus` or `activate`, the screens it applies to). A key that clashes with a browser or screen reader key on the list in the same file is refused at load.
  - `useShortcut(actionName, targetRef)`: binds a key from the list to a visible control on the page. The control must exist and be visible when the key is pressed; the hook sets `aria-keyshortcuts` on it. A shortcut with no visible control on the page is refused in development and fails the tests (rule 10).
  - Keys do nothing while focus is in a text input, textarea, select or editable region (rule 10).
  - Single-character shortcuts can be turned off by the person, in a "Keyboard shortcuts" settings control; the choice is kept per browser in local storage with a safe default (on) when storage is unavailable (WCAG 2.1.4).
  - Rule 22: an action of kind `activate` that approves, sends, unmarks or deletes may not be bound to a single key; such actions are `focus` only (the key moves focus to the control and the person presses it). "Reviewed, next" marks and moves on and never unmarks. The registry refuses a list that breaks this.
  - `ShortcutsHelp`: the "Keyboard shortcuts" list component (a GOV.UK details or summary list from U00), showing only the shortcuts active on the current screen, with the switch for single keys.
- `e2e/ui/keyboard.spec.ts`: a browser check on a test page under `e2e/ui/` built from U00 components and these hooks (no app route).

## Acceptance checks
1. RV-6: on the test page, each shortcut moves focus or acts on its visible control exactly as listed, and the control carries `aria-keyshortcuts` with the key.
2. RV-54: with focus in a text input, a textarea and a select, no shortcut fires (a counter on each action stays at zero).
3. RV-54: turning single-key shortcuts off stops every single-character shortcut and leaves modified ones working; the choice survives a reload; with local storage unavailable the page still works with shortcuts on.
4. RV-6: the test list with a single-key `approve` of kind `activate` is refused with the reason; a list with the clashing key is refused naming the clash; a shortcut whose control is not on the page fails with its name.
5. RV-6: "Reviewed, next" bound to its key marks and moves on, and pressing the key again on a marked section does not unmark it.
6. RV-51: `ShortcutsHelp` lists exactly the shortcuts active on the test page, and every key in D01's list appears in the parsed `shortcuts.ts` data (none dropped).
