## Goal
No model or prompt change reaches the product until a fixed test set from the test world has run on it and no score dropped (AI-11). The harness runs an AI step's cases, scores them, compares the scores with the approved baseline and only then adds the (step type, prompt version, model id) triple to A04's approved list. The same scores give LL-9's AI measures on made-up data.

## Build
- `data/ai/evals/sets/<step>.json`: one fixed set per AI step type (and per topic for findings). Each case names a test-world client or kind and its inputs by reference (ids `loadClient` and `loadKind` resolve), never copied values, and its expected answer from the answer keys and `faults()`: the expected facts (extraction), the planted faults a finding must raise, the kinds that must stay silent. A set's version is the sha256 of its canonical content; changing a set needs an amber row.
- `src/modules/ai/evals/score.ts`: scores as integer basis points, `floor(10000 * hits / cases)`, and "no cases" when there are none (never zero): extraction accuracy on raw facts by document type; planted faults found; false alarms per check on kinds without the fault; citation failure rate (items dropped by AI-4 over items returned); "I can't tell" rate; red-team hit rate (items that match a planted fault CRA would adjust, over items).
- `src/modules/ai/evals/run.ts`: `evaluate(step, promptVersion, modelId, engine)`: runs every case through A04's runner (`recorded` in tests; `project` for real runs on the subscription through A08, made-up returns only). An output whose stamp lacks a part, or names another model id or prompt version than the triple, fails its case (AI-10). Writes `data/ai/evals/results/<step>-<prompt version>-<model id>.json`: the set version, the scores and each case's outcome, never inputs or values.
- `src/modules/ai/evals/gate.ts`: `gate(result, baseline)` (AI-11): a result on another set version is refused; any score below the baseline's blocks, listing each one; with no drop it adds the triple to `data/ai/approved.json` in A04's strict shape (sorted) and copies the result to `data/ai/evals/baselines/<step>.json`. A step's first triple has no baseline: it is approved only when every case ran and the call names the amber row that allows it, which the baseline records.
- `src/modules/ai/evals/repo.check.ts` (AI-11): every triple in `approved.json` has a result file at the current set version, so no change reaches the list without a run.
- `src/modules/ai/evals/cli.ts`: runs and gates one triple from the command line; prints the scores and the decision only.
- `// @mutate` on `score.ts` and `gate.ts`; mutation 100 per marked file (ARC-15).

## Acceptance checks
1. AI-11: a recorded run of the fixture step equal to its baseline is approved and its triple appears in a temp copy of `approved.json`; A04's runner, pointed at that copy, accepts the triple and still refuses an unlisted one.
2. AI-11: a recorded run with one score one basis point below the baseline is blocked naming that score, and the temp `approved.json` is byte-unchanged.
3. AI-11: a result scored on an older set version is refused; editing one case of a set changes its version.
4. AI-11: a planted `approved.json` triple with no result file at the current set version fails the repo check.
5. LL-9: on a fixture set, extraction accuracy by document type, false alarms per check and red-team hit rate equal hand-computed values (golden file); a measure with no cases reads "no cases".
6. LL-9 property (fast-check, fixed seed): every score is an integer from 0 to 10,000 and equals `floor(10000 * hits / cases)` for any hits up to cases.
7. AI-4: an output with a failed citation counts in the citation failure rate and does not count as a found fault.
8. AI-10: an output whose stamp lacks the OCR engine, or names a model id other than the triple's, fails its case with the reason.
9. ARC-16: two runs of the same recorded set give byte-identical result files.
10. SEC-11: every case input resolves to a made-up test-world record (W00b's guard passes on it); the `project` engine refuses a case whose return is not `is_test`.
