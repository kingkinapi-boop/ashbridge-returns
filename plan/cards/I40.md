## Goal
No model or prompt change reaches the product until a fixed test set from the test world has run on it and no score dropped. The harness runs each AI step type on its cases, scores it, compares with the approved baseline, and only then adds the (step type, prompt version, model id) triple to A04's approved list. The same scores give the AI measures of LL-9 on made-up data.

## Build
- `data/ai/evals/sets/<step>.json`: the fixed test set per step type: case ids naming test-world clients and kinds, the inputs (by test-world reference, never copied values) and the expected answer from the test world's answer keys (expected facts, planted faults and the flags they must raise). Each set carries a version (a hash of its content); changing a set needs an amber row.
- `src/modules/ai/evals/score.ts`: per step type: extraction accuracy on raw facts by document type; findings found and missed against planted faults; false alarms on kinds without the fault; citation failure rate (AI-4); "I can't tell" rate; red-team hit rate. Scores in basis points, integers, so comparison is exact.
- `src/modules/ai/evals/run.ts`: `evaluate(step, promptVersion, modelId, engine)`: runs every case through A04's runner (`recorded` in tests; `project` for real runs on the subscription, made-up data only), checks each output's stamp (AI-10), scores it and writes `data/ai/evals/results/<step>-<prompt version>-<model>.json` with the set version.
- `src/modules/ai/evals/gate.ts`: `approve(result, baseline)` (AI-11): compares each score with the baseline for that step (the last approved result); any drop blocks, listing each dropped score; with no drop, adds the triple to `data/ai/approved.json` and the result becomes the baseline. A result from a different set version is refused. The first triple of a step has no baseline: it is approved only with every case run and no citation failure left unexplained, and an amber row.
- `src/modules/ai/evals/cli.ts`: run and gate one triple from the command line; prints scores and the decision, never inputs or values.
- `// @mutate` on `score.ts` and `gate.ts`; mutation 100 per marked file (ARC-15).

## Acceptance checks
1. AI-11: a recorded run of the fixture step on its set equal to the baseline is approved and its triple appears in `approved.json`; A04's runner then accepts that triple and still refuses an unlisted one.
2. AI-11: a recorded run with one score one basis point lower is blocked, names the dropped score, and leaves `approved.json` unchanged.
3. AI-11: a result scored on an older set version is refused; editing a set changes its version.
4. LL-9: on a fixture set, extraction accuracy by document type, false alarms per check and red-team hit rate equal hand-computed values (fixed golden file).
5. AI-4, AI-10: an output with a failed citation counts against the citation score; an output missing a stamp part fails its case.
6. ARC-16: two runs of the same recorded set give byte-identical result files.
7. SEC-11: the `project` engine refuses any case whose return is not made up (`is_test`).
