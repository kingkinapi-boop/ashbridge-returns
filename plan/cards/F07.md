## Goal
Turn what the client app hands over into returns here, correctly for every case it can send, using made-up data shaped exactly like the client app's tables, so switching to the live database at go-live changes the source and nothing else.

## Build
- `src/contracts/bridge.ts`: the shapes this system reads (from `reference/onboarding-contract.md`, with the client-app migration number and commit it was written against, f87a0043 or later) and the shared hand-off table it writes (question lists and approval summaries as ids, slots and numbers).
- `src/modules/bridge/`: reads a made-up client-app snapshot and creates returns. What the client app leaves unclear is never guessed (END-1): a year end the client never confirmed, unfiled years held only as text, the same year bought twice. Each becomes an "ops confirms" item, and the return waits for it.
- Personal returns only, or a company with no T2 bought: skipped without error and without stopping the others (OUT-6).
- Associated companies (K7) become linked returns (FLOW-11).
- Each return carries what later cards read from the bridge contract: the incorporation date (B05's first-year opening check) and the books source (`firm-books` when the firm keeps the client's books in QBO from bank statements, from the bookkeeping service line; `client-qbo` otherwise; anything unclear is an ops-confirms item, never guessed). B07 matches bank lines only for `firm-books` returns.
- Sensitive fields listed as "never read" in the contract are not in the shapes at all.
- `db/schema/05_bridge.sql`: the hand-off table in schema `returns`.

## Acceptance checks
1. END-1: a snapshot with one company and one T2 year creates one return with no typing.
2. END-1: an unconfirmed year end, unfiled years as text, and a duplicate year each create an ops-confirms item, never a guessed return.
3. OUT-6: a T1-only client and a company with no T2 are skipped; the rest of the batch still goes through.
4. FLOW-11: two associated companies create linked returns.
5. END-1: a return carries its incorporation date and books source; a corporation with the bookkeeping service gets `firm-books`, one without gets `client-qbo`, and one whose services do not say becomes an ops-confirms item.
6. ARC-2: no field from the contract's never-read list exists in any shape (a test reads the list).
7. ARC-2: the contract file names the client-app commit and last migration it was written against.
8. ARC-2: the hand-off table is in schema `returns`, row-level security on with no policies, and holds no free-text column (ids, slot values and numbers only; a catalog query lists every column and its type).

## Not in this card
Connecting to the live database (go-live, LIVE-4, LIVE-6). Any client-app change. An amalgamation or wind-up mark: the client app holds none, so B03 reads a fact a preparer enters with a reason.
