## When it starts
This card waits until D02 and D08 are approved by Zo at a design sitting (RV-53); the Lead marks them done then.

## Goal
The CPA comments on a number with a type and a severity; the comments go to the preparer when the CPA sends the return back; the preparer sees them grouped by topic and answers each; after rework the CPA sees only the changed cells, before and after, in sections whose marks came off.

## Build
- `src/modules/comments/` (`// @mutate` on the rule files; mutation 100 per marked file, ARC-15):
  - `addComment(returnId, cell, type, severity, text, cpa)` (RV-7): type one of error, question, missing evidence, presentation; severity one of must fix, should fix, note (firm list in the module, codes never renumbered); a cell of the latest accepted lock export; CPA role only, refused for AI or system (AI-7) and outside review. A changed comment is a new row that supersedes. A comment on the cell of an accepted-risk exception may name that exception; it then records V03's `judgeRisk(exceptionId, 'comment')` with the comment id in the same transaction. Until `sendForRework`, a round's comments are shown only to the CPA and the owner; the preparer and every other role see none of them (a draft is not sent).
  - `sendForRework(returnId, cpa)`: moves review to rework through F02 (guard `review_to_rework`: the CPA, at least one unsent comment this round) and releases the round's comments to the preparer, in one transaction.
  - `respond(commentId, kind, text, preparer)`: the assigned preparer answers each comment, `done` (names what changed) or `answered` (a reply); refused for AI. `resolve(commentId, cpa)` closes a comment on re-review; only the CPA closes one, AI never.
  - Guard `rework_to_review`: every comment of the round has a response; when any response is `done`, a lock export accepted after `sendForRework` exists and the trace and checks have run on it; and V09's `readyForReview` passes. The sign saves that lock export as a new preparer version (N00 `saveVersion` kind `preparer`, RT-18) and makes F02's move in one transaction (FX5's caller transaction). The preparer's "Sign and send to review" calls it. Both guards are registered with F02's lifecycle in `src/pipeline/deps.ts`.
  - `topicsOf(returnId)` (RV-25): comments grouped by the RV-1 section of their cell, in section order, then severity, then time.
- `db/schema/75_comments.sql`: comments, responses, resolutions and rounds, append-only with F01's `refuse_change` triggers, row-level security on, CHECK lists on type, severity and response kind.
- Screens, built to the approved designs, through V00's access rules:
  - Comment on a number (D02, CPA and owner): the "Comment" control in V03's pane action bar (`actions.tsx`) and its form (radios for type and severity, none preselected; text area; GOV.UK error summary); shortcut `c` through U01.
  - Send for rework: where D02 places it; the page lists the round's comments first.
  - Rework changes (D02, `review/changes`): V03's `sectionChanges` as one table of changed cells with before and after, sections whose marks came off listed as links; after an approval void, T08's stored changed cells the same way (FLOW-5); each comment of the round with a response shows Resolve (CPA only).
  - CPA comments (D08, `prepare/comments`, assigned preparer, CPA, owner): one h2 per topic, a summary card per comment with type and severity tags in words, its cell linked to the source viewer, the response form in place (rule 19), and "Sign and send to review" only when the guard would pass, otherwise what remains as links (rule 8). The comment card is `comment-card.tsx` (V13 adds the draft fix to it).

## Spec
- Fixtures: C01 in review; a second lock export after rework changing two cells in one section and none elsewhere; a voided approval with one changed cell; a return assigned to another preparer.
- Classes: RV-7 (each type and severity stored; a fifth type, a blank text or a missing severity refused with the GOV.UK error pattern; the rework view shows exactly the changed cells with before and after and only sections whose marks came off; property over cell edits with a fixed seed); RV-25 (topics in RV-1 order, golden ARIA snapshot); FLOW-2 (send moves review to rework; sign moves rework to review only when every comment is answered and V09's check passes; each refusal names what remains; a `done` response with no new lock export refuses the sign naming it; a passed sign stores exactly one preparer version (property over response mixes, fixed seed); resolve by the CPA closes the comment; by a preparer, AI or system it is refused); EX-1 (a comment naming an accepted-risk exception records V03's `comment` judgment with its comment id in the same transaction; a failure keeps neither); RV-6 (the `c` shortcut opens the comment form on the focused number); FLOW-5 (a voided approval's changed cells show the same way); AI-7 (an AI or system actor cannot comment, respond, resolve or move the state; a code sweep finds no other writer); SEC-7 (UPDATE, DELETE, TRUNCATE refused on the new tables); SEC-2 (preparer B gets "not found" on A's comments; a preparer cannot comment; before `sendForRework` the assigned preparer and ops see none of the round's comments on any page or server action, and after it the assigned preparer sees them all); RV-53 (matches D02 and D08 within the visual threshold and their budgets for "comment on a number" and "answer a comment"); RV-54 (U02's sweeps; keyboard alone).
