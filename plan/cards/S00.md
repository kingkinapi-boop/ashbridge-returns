## Changed 1 Oct 2026 (trial findings; day 5 clauses added the same day: no token cell, next-copy import, apostrophe on exported negatives, the eight contact cells, "Cell not available.")
The import behaviour now follows the Taxprep trial, not CCH's help page: a blank value clears, the header is not read, the report lists only cells that already held a value, cents are refused in amount cells, contact cells are skipped with no report row. Any spec written before this change is void.

## Goal
A stand-in for Taxprep that behaves as the trial recorded (`reference/taxprep/FINDINGS.md`), so the import writer, the export reader and the trace are built and tested end to end without the real product. It computes no tax.

## Build
- An in-memory simulated return per (business number, year end): a return name, a GUID (from the injected id source), a release name, input cells keyed by identifier (with repeating-form copies), the year start and end set by a separate "by hand" call, a lock flag, and an event list of what changed each cell (import, typed by hand, cleared by hand).
- Uses F03's parser and writer only; no second CSV reader.
- `importCsv(return, bytes)`: the target is the return the call names; the file's header is parsed but never compared with the return (trial: a wrong name or GUID is applied silently). Each row:
  - an identifier on the release list: a value sets the cell; `""` or `" "` clears it (RT-12); `"0"` sets zero;
  - an amount cell given cents: refused for that row, report line "The value <v> could not be imported in this cell because it was invalid." (RT-25);
  - the year-start and year-end identifiers and the contact-synchronised cells (F03's ignored-on-import list): nothing changes and no report line (RT-13; trial: silent);
  - a copy index of a repeating group one above the copies the return holds: creates that copy and sets the cell, with no report line (RT-7, trial day 5); a gap index (further above): refused with "Cell not available." (unconfirmed: the trial has not tried one; the test is named "unconfirmed");
  - an identifier not on the release list: nothing changes, and a report line "Cell not available." with Form, Description and Box `--` and no identifier (trial day 5, O4).
- The import report imitates the trial (RT-26): one line per cell that already held a value ("The value of this cell has been replaced by a new imported value." or "This cell has been emptied by the import."), one line per refused row, no line for a cell that was empty before, no counts; when there are no lines it says "Data imported successfully".
- The identifier list for the release comes from a constructor argument: identifier, description, kind (amount, text, date, yes-no, rate) and order. The default is the list built from `reference/sample-clients/lib/taxprep-cells.json` (its `confirmed` flags kept). S02 replaces the default with release lists; S03 with the trial's cell map. The default list holds the iFirm contact cells `IFirm.ContactPartner` and `IFirm.ContactID`. There is no token cell (RT-2): `IFirm.ContactPartner` takes an imported value and exports it until `openReturn()` (opening the return in Taxprep, which runs the contact synchronisation) wipes it to `""`, as the trial saw; `IFirm.ContactID` holds the return's client code.
- `typeCell`, `clearCell`: what a preparer does by hand in Taxprep; recorded as such so tests can plant orphans and overrides.
- `lock()` and `unlock()`; `exportCsv(return, filter)` with two filters: "entered" (Taxprep's default "Entered this year or last year": cells holding a value plus the eight creation and contact cells `IDENT.Ident120`, `Ident121`, `Ident311`, `Ident230`, `Ident451`, `Ident492`, `IFirm.ContactPartner`, `IFirm.ContactID`, even when empty) and "all input cells" (every cell on the release list, empty ones as `""`). Written with F03's fixed settings: header `[<return name>|0|0|<GUID>],"Current Year","Last Year",""`, the description column filled from the release list, rows in the release list's order, and every negative value written with one leading apostrophe (`"'-1299"`), as Taxprep's default "-123" setting does (RT-3, trial days 3 and 5). No calculated cells yet (S03 adds them).
- The first lines of every core file carry `// @mutate` (every non-test `.ts` file under `src/modules/taxprep-sim/core/` and `index.ts`); `npm run mutate:changed -- S00` scores 100 on every marked file (ARC-15, DG) before reporting.
- Deterministic: no clock or id reads except through the injected clock and id source; no randomness.

2. RT-3, ARC-14: export then import into a fresh return then export again gives the same bytes apart from the header's name and GUID (the import reads the apostrophe-carrying negatives through F03's strip).
3. RT-12, RT-8: a row with `""` and a row with `" "` each clear a cell typed earlier, with the report line "This cell has been emptied by the import."; `"0"` sets the cell to zero with the "replaced" line.
4. RT-13: rows for the year-start and year-end identifiers and for `IDENT.Ident311` change nothing and produce no report line; the year dates set by hand are unchanged.
5. RT-26: importing into an empty return gives "Data imported successfully" and no per-cell lines; importing again with one value changed gives exactly one "replaced" line for that cell and one for each other cell that already held a value.
6. RT-25: a row of 7693.52 in an amount cell is refused with the trial's wording and changes nothing; the rest of the file still imports.
7. RT-1 (as Taxprep behaves): a file whose header names another return and another GUID is applied to the return the call names, and the report says nothing about it.
8. RT-23: a cell typed by hand after import appears in the "entered" export and in the event list as typed by hand; a cell cleared by hand is absent from the "entered" export and listed as `""` in the "all input cells" export.
9. RT-23: an identifier not on the release list gives "Cell not available." with `--` and no identifier, and the rest of the file imports; RT-7: with two copies of `CCACat.FD08C`, a row for `CCACat.FD08C[3].FED.Ttw08cA1` creates a third copy with no report line; (unconfirmed) a row for `[5]` is refused.
10. RT-3 property (fast-check, fixed seed): for any list of valid rows over the release identifiers (with copies), import then export holds exactly the last value written for each identifier (a clear removes it), and every value round-trips byte for byte.
11. RT-23: two exports with nothing changed between them are byte-identical.
12. RT-2, RT-23: a value imported into `IFirm.ContactPartner` appears in the next export, and after `openReturn()` that export lists it as `""`; `IFirm.ContactID` holds the client code in every "entered" export; the module exports no token constant.
