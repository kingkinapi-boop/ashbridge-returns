## Goal
A stand-in for Taxprep that follows CCH's published CSV rules, so the import writer, the export reader and the trace are built and tested end to end long before anyone touches the real product. It imitates only what CCH documents and, after S03, what the trial records; it computes no tax.

## Build
- An in-memory simulated return per (business number, year end): a release name, input cells keyed by identifier (with repeating-form copies), the year start and end set by a separate "by hand" call, a lock flag, and an event list of what changed each cell (import, typed by hand, cleared by hand).
- Uses F03's parser and writer only; no second CSV reader.
- `importCsv(return, bytes)`: applies each row; returns an import report modelled on CCH's (the cells modified with old and new value, and each error with its row and reason). Rows: an identifier not in the release's identifier list is an error and changes nothing; a blank value is not imported and leaves the cell as it was (RT-12); "0" sets zero; the T2 year-start and year-end identifiers are reported as ignored and change nothing (RT-13); a header naming another return is refused whole.
- The identifier list for the release comes from a constructor argument; the default is the placeholder list built from `reference/sample-clients/lib/taxprep-cells.json` (every entry marked unconfirmed). S02 replaces the default with release lists; S03 with the trial's cell map. The default list also holds one placeholder token cell (RT-2: "until then the simulator uses a placeholder cell"), named in one exported constant and marked placeholder; it imports and exports like any input cell, so T01 can write the token and T02 can refuse a stale export before the trial names the real cell.
- `typeCell`, `clearCell`: what a preparer does by hand in Taxprep; recorded as such so tests can plant orphans and overrides.
- `lock()` and `unlock()`; `exportCsv(return, filter)`: the "all input cells" filter as the trial plan names it, written with F03's fixed export settings, rows in a stable order (form, copy, cell). No calculated cells yet (S03 adds them when the trial shows how).
- Deterministic: no clock reads except through the injected clock; no randomness.

## Golden files (spec-writer, `src/modules/taxprep-sim/core/__golden__/`)
- For sample clients 01, 05 and 08: their `reference/sample-clients/<client>/taxprep/import.csv` imported into an empty return, then exported: the expected export file and the expected import report.

## Acceptance checks
1. RT-3: importing sample client 01's `import.csv` then exporting gives the golden export; every row of the import appears with the same value.
2. RT-3, ARC-14: export then import into a fresh return then export again gives the same bytes.
3. RT-12: a row with a blank value leaves a cell typed earlier unchanged, and the import report lists it as not imported; "0" sets the cell to zero.
4. RT-13: rows for the year-start and year-end identifiers are listed as ignored and the year dates set by hand are unchanged.
5. RT-23: an identifier not in the release list is an error in the report with the row number, and no cell changes for that row; the rest of the file still imports.
6. RT-23: a file whose header names another return is refused whole, with the reason, and the return is unchanged.
7. RT-23: a cell typed by hand after import appears in the export and in the event list as typed by hand; a cell cleared by hand is absent from the export.
8. RT-3 property (fast-check, fixed seed): for any list of valid rows over the release identifiers (with copies), import then export holds exactly the last value written for each identifier, and every value round-trips byte for byte.
9. RT-23: importing the same file twice gives the same return and an import report with no modified cells the second time.
10. RT-2: a row for the placeholder token cell imports, appears unchanged in the export, and the constant naming it says it is a placeholder.

## Not in this card
Faults (S01), release lists and their diff (S02), the trial's findings (S03: the real token cell, roll-forward, diagnostics, calculated review lines, printed return). The import writer (T01) and export reader (T02). Any tax calculation.
