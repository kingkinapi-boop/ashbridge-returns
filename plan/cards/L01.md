## Goal
Every number on a staff screen carries a dot that says how strong its evidence is, set by code from the origin of each source and the written rules for when two sources agree. An open exception is a separate red flag, never a dot. Rules that change are data, not code.

## Build
- `data/ledger/origins.json`: the origin of each source kind (EV-10): document kinds (bank, lender and card statements, OHIP remittance advice, slips issued to the company, CRA records: third party; HST returns, payroll remittances, T4 and T5 summaries: client filed with CRA; trial balance, financial statements, invoices issued, QBO books: client prepared), client answers (client said), reasons a person wrote (judgment), last year's assessed return (its own entry, for the grey rule). An unlisted document kind has no origin and is refused, never guessed.
- `data/ledger/agree-rules.json` (EV-13): each "agrees with" rule by id: the two source kinds, the comparison (equal to the dollar under F05's 100-cent rule, or equal after removing listed item kinds), and its source in the blueprint or a CRA guide. Starts with the rule EV-13 names (bank deposits agree with revenue only after known non-revenue items are removed) and the plain "equal to the dollar" rule for a third-party statement against the same amount in QBO.
- `src/modules/ledger/dots/`:
  - `originOf(sourcePointer, documentKind?)` from the data file.
  - `linkAgrees(a, b, ruleId, actor, why)`: writes an "agrees with" link through L00's contract only when the rule exists and the comparison holds for the two values; otherwise refused with the reason. No rule id, no link (EV-13).
  - `dotOf(factId)`: green when a third-party source agrees with it through a link; grey when its single source is third party, or last year's assessed return; amber when it rests only on the client (prepared, filed or said); purple when it rests on judgment (EV-11).
  - `dotOfFigure(figureKey)`: the weakest dot among every source `sourcesOf` returns (EV-11), strength in the order green, grey, amber, purple (purple weakest).
  - `flagsOf(figureKey or factId)` (EV-12): open exceptions on the number, returned separately from the dot; the dot function never reads exceptions.
- Each result names why: the deciding source and, for green, the rule id, so screens can say it in words (staff-screens rule 7).

## Acceptance checks
1. EV-10: every source kind in `origins.json` maps to exactly one of the five origins (or the assessed-return entry); an unlisted document kind is refused with "no origin for this kind".
2. EV-11: the four C01 cases give green (statement agrees with QBO under a rule), grey (statement alone; last year's assessed return alone), amber (client-said only; client-prepared only), purple (judgment).
3. EV-11: the figure built from a green and an amber source is amber; one built from amber and purple sources is purple; property (fast-check, fixed seed): a figure's dot is never stronger than its weakest source and equals it.
4. EV-13: bank deposits linked to revenue under the EV-13 rule agree only when the known non-revenue items are removed, and fail with the difference when not; `linkAgrees` with no rule id, or an unknown one, is refused and writes no link; a fact whose third-party source matches but has no agrees-with link stays grey, never green.
5. EV-12: an open exception on a green figure leaves its dot green and returns one red flag from `flagsOf`; closing the exception removes the flag and the dot is unchanged.
6. Every dot result names its deciding source, and green names its rule id.

## Not in this card
Raising and closing exceptions (the check cards, Q00 and EX). How dots and flags are drawn (U00, V cards). Writing facts and links other than "agrees with" (L00).
