## Goal
The simulator knows which input-cell identifiers each Taxprep release has, as data, and can say what changed between two releases, so the mapping's drift check (M00) has releases to compare from day one and the trial's real list drops in as one more data file.

## Build
- `data/taxprep/releases/<release>.json`: release name, product year, whether it is confirmed, the source (placeholder or trial capture with its date), and two identifier lists in Taxprep's export order (RT-22): input cells (from a "Select all input cells" filter) and calculated cells (the extra cells a "Select all" filter gives). Each identifier keeps Taxprep's description and a kind (amount, text, date, yes-no, rate); each repeating group path (for example `CCACat.FD08C`, `FDONE.SLIPA`) keeps its natural-key cell (RT-7) and copy limit, and is listed by its cells under copy `[1]`, since Taxprep lists cells only for copies that exist.
- Two placeholder releases, both marked unconfirmed: `SIM-2025.1` expanded from `reference/sample-clients/lib/taxprep-cells.json` (templates filled for every GIFI code and list position the ten sample clients use), and `SIM-2025.2` made from it with one identifier removed, one renamed (listed in a `renamed` table in the file) and one added, so the diff has something to find.
- `loadRelease(name)` validates the file (zod) and refuses duplicate identifiers, an identifier on both lists, or identifiers F03's grammar refuses. `isInput(id)` answers for any copy index of a repeating group (RT-4: the import writer refuses anything else).
- `diffReleases(from, to)`: added, removed and renamed identifiers (renamed only when the newer file's `renamed` table says so; otherwise a rename shows as one removed and one added).
- `blockedBy(usedIdentifiers, from, to)`: the used identifiers that the new release removed or renamed (RT-22), with the replacement where the rename table gives one.
- The simulator's "all input cells" export for a reference return lists exactly the release's identifiers (S00's export on an empty return with every cell set), so a captured trial list and a release file compare the same way.

## Acceptance checks
1. RT-22: `diffReleases(SIM-2025.1, SIM-2025.2)` returns exactly the one removed, one renamed and one added identifier.
2. RT-22: `blockedBy` with a used list holding the removed and the renamed identifier returns both, the renamed one with its replacement; a used list touching neither returns none.
3. RT-21: every identifier the ten sample clients' `import.csv` files use is in `SIM-2025.1`.
4. RT-23: a release file with a duplicate identifier, an identifier on both the input and the calculated list, or one F03's grammar refuses, is refused on load with the identifier named.
5. RT-22: the "all input cells" export of a reference return in `SIM-2025.1`, read back through F03, gives the same identifier set as the release file.
6. Every placeholder release says `confirmed: false`, and any test that runs against an unconfirmed release names it in its output.
7. RT-4: `isInput` is true for `CCACat.FD08C[3].FED.Ttw08cA1` when the release lists `CCACat.FD08C[1].FED.Ttw08cA1`, and false for every calculated identifier.
