## Goal
Returns builds every figure the mapping names from its sources and writes the Taxprep import file, so nobody types the numbers (END item 4). The first file is the AI draft; every later file sends only the cells that changed, and removes a value only by a deliberate, recorded clear. A figure with no verified source is left out, never written blank.

## Build
- `src/modules/roundtrip/figures/` (the `figures` pipeline step):
  - `buildFigures(returnId, release)`: for each mapping row of the return's release (M00):
    - `gifi`: the code's whole-dollar amount from M00's `roundGifi` over B01's `gifiTotals`; built from the accounts B01 lists (TB-9, in account order) and, on the plug line, the rounding item as its own "built from" source (RT-25);
    - `fact`: the fact's value, only when its status is preparer-verified or CPA-accepted (RT-4); a proposed fact leaves the figure "waiting on verification" with the fact named;
    - `taxChoice` and `never`: no figure (TB-6, RT-13).
  - A figure record (`db/schema/40_figures.sql`, F01's table): figure key, row key, value in whole dollars as cents, identifier template, status (ready, waiting, held back), and its "built from" links through the ledger contract (`linkBuiltFrom`, TB-9). A rebuild writes new versions only for figures whose value or sources changed (EV-1 through L00).
  - Repeating rows (RT-7): the target copy comes from M00's `targetIdentifier` against the latest accepted export (T02): the copy holding the natural key, or, for a key no copy holds, the next free index (copies in that export plus one; several new keys take the following indexes in the mapping's order), which the import creates (trial day 5). With no export yet, the figure is "held back: export once, then re-import" (the writer cannot count the copies). A gap index is never written.
- `src/modules/roundtrip/import/` (the `import` pipeline step):
  - `writeImport(returnId, actor)`: writes one file through F03's writer only: header `[<return name>|0|0|<GUID>]` with the GUID T02 recorded from the first export, or all zeros before one exists (RT-3); rows for ready figures in the release's order; no row for a waiting or held-back figure, a `taxChoice` cell or an RT-13 cell (the writer also refuses them); every identifier checked with `isInput` and M00's `canImport` first, and the whole file refused if the release is blocked (RT-22, RT-4).
  - First file (version 1) is the AI draft and holds every ready figure. Later files (RT-8) hold only cells whose value differs from the last value Returns imported for that cell, plus clears.
  - Clears (RT-8, RT-12): a cell that an earlier import filled and whose figure no longer exists (its source was removed) gets a clear row `""` only through `requestClear(returnId, identifier, actor, reason)` (named apart from the simulator's by-hand `clearCell`, S00), which records the person and reason and is refused for an AI actor (AI-7); nothing else ever writes an empty value. A figure that goes back to "waiting on verification" is not cleared either. Both kinds are listed by `stillHeld(returnId)`: "Taxprep still holds <value> from import <n>", with why (source removed, or waiting on verification), for the preparer to clear with a reason (V06) or leave.
  - No token (RT-2: the trial found no cell that keeps one). No file holds a token row; staleness is T02's content test.
  - File name (RT-5): `<client_ref>-<year end YYYYMMDD>-v<n>.csv` (for example `ASH-0001-20251231-v1.csv`); `client_ref` comes from the bridge (F07).
  - Each file is stored write-once (A05), fingerprinted, and recorded in `db/schema/45_roundtrip.sql` as an import version (number, kind `ai-draft` or `re-import`, author, time, rows with identifier, value or clear, and for clears the reason), with an event. Implements T02's `ImportHistory` (the cells each import wrote and changed).
  - Every figure and file carries the mapping release, the mapping fingerprints and this card's code release (ARC-10).
- The lifecycle (FLOW-2): once import version 1 is stored (the AI draft saved), the `import` step asks F02's contract to move the return from build to prepare (blueprint 02: build leaves when the import file is written); later files do not move the state.
- `src/pipeline/steps/figures.ts` and `import.ts` replace F10's placeholders; the skeleton's "one figure, the import file" stubs are removed from `stubs.ts` and `stubs.md`.
