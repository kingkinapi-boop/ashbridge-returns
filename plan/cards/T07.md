## Goal
The calculated lines the brief and the review show (net income for tax, taxable income, each tax, the balance) are read from the same lock export as the input cells, so the CPA approves numbers Taxprep calculated and not numbers we recomputed. The printed return the preparer uploads with it is kept as the record of the full return, readable page by page.

## Build
- `data/taxprep/review-lines/<release>.json` (RT-10): each review line with a meaning key (`net_income_tax`, `taxable_income`, `part1_tax`, `ontario_tax`, `instalments`, `balance_or_refund`, plus any line a brief or review section names), its identifier, its form and whether it is confirmed. The trial release holds `FDONE.Ttwone66` (net income for tax, confirmed, day 2 and day 3); the rest stay unconfirmed placeholders until the trial names them.
- `src/modules/roundtrip/reviewlines/`: `reviewLines(exportId)`: each review line's value from the accepted lock export (T02), keyed by meaning; an export missing a review line's row is refused as "lock filter incomplete: add <identifier> (Select all on <form>)"; every identifier must be on the release's calculated list (RT-22), or the data file is refused on load, except a row the file marks `input: true` (a line the review shows that the preparer enters in Taxprep, for example instalments paid), which must be on the input list instead; a row whose mark disagrees with the release lists, or an identifier on neither list, is refused. Values are whole dollars as integer cents. The result carries the release and the code release (ARC-10).
- `src/modules/roundtrip/printed/`: `receivePrintedReturn(returnId, lockExportId, bytes, fileName, uploader)` (RT-11): a PDF only (any other type refused); stored write-once and fingerprinted (EV-2) and passed through document intake (E00) so its pages and words are ready at once (ARC-11); linked to the lock export it came with (one printed return per lock export; a second upload for the same export is a new version with an event). Identity: the reading must hold the return's business number and the year end; if neither is found it is flagged "printed return not checked: business number not read" for a person (not refused), and if another business number is found it is refused naming it. A return with no business number entered (RT-1: every test return, since the test world's numbers fail Taxprep's check digit by design) is checked on the year end and the corporation name and carries T02's "business number not entered" flag, never a silent pass. The printed return carries no diagnostics (RULE-2, trial day 5); nothing here reads any.
- `testworld/taxprep/printed/`: makes a made-up printed return PDF with W20's framework from a simulated return: a cover with the corporation name ending "(Test)", business number and year end, the "Do Not Submit" watermark, pages listing the review lines; no diagnostics page (the real printed return has none, RT-17); a business number only when one is given. Text layer on by default; a scanned copy through W20's `toScan`.

## Trial-dependent (FINDINGS.md is interim)
- Which forms hold taxable income and each tax (RT-10: the T2 jacket, Schedules 3 and 4). Fallback in force: those review lines are placeholders marked unconfirmed in the simulator release; their tests are named "unconfirmed".
- Whether the printed return's text can be read (day 3: the walker could not read the Office copy's fonts). Fallback: E00 reads it through the text layer, or through Tesseract (A02) when the text layer is missing or garbled; if the business number is still not found, the "not checked" flag above, never a silent pass.
- Which print format the preparer uploads (Client, EFILE, Government, Office copy). Fallback: any; the checklist (V06) asks for the Government copy, Taxprep's default.

## Acceptance checks
1. RT-10: `reviewLines` on C01's export returns each review line by meaning with the export's value; the negative one exported with a leading apostrophe is read as the negative amount; the export missing `FDONE.Ttwone66` is refused naming it and the filter fix.
2. RT-22: a review-lines file naming an input-list identifier without `input: true`, a calculated identifier marked `input: true`, or one not in the release, is refused on load naming it; an input-list row marked `input: true` loads.
3. RT-11, EV-2: C01's printed return is stored once, fingerprinted, linked to its lock export, and its pages and word boxes are ready when the call returns (ARC-11); a second upload for the same export is a new version with an event.
4. RT-11: C01's printed return with no business number is accepted, checked on year end and name, with the "business number not entered" flag; the printed return with another business number is refused naming it; the garbled one is accepted with the "not checked" flag; the scanned one is read through Tesseract and accepted; the non-PDF file is refused.
5. SEC-11: every printed return the test world makes names a corporation ending "(Test)" and carries the watermark.
6. ARC-10: every result carries the release and code release; unconfirmed review lines are named in the result.
