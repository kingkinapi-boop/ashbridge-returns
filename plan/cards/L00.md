## Goal
The one service every other card uses to record what Returns knows: facts with exactly one source pointer, "built from" links from figures to their sources, an event for every change, the fact status path, and the two resets (a replaced document, late evidence after lock). Nothing is ever overwritten. Extraction (E01), the books (B05), the gap pass (G00), the checks (Q00), the trace (T04) and every screen read and write through it.

## Build
- `src/contracts/ledger.ts`: the service interface and its input and result types; other modules take it as a parameter (F10's rule) and never import this module.
- `src/modules/ledger/core/`:
  - `proposeFact(input, actor, why)`: a new fact (fact key, value, exactly one source pointer as EV-5 lists, origin, method, version stamps) with status `proposed`, and one event. A fact with no pointer or two, or with no version stamp (ARC-10), is refused.
  - `changeFact(factId, change, actor, why)`: writes a new version, never updates the old row, and resets status to `proposed` (EV-8), with one event holding from, to and why.
  - `verifyFact(factId, preparer)` moves `proposed` to `preparer-verified`; `acceptFacts(returnId, approvalId, cpa)` moves every verified fact on the return to `cpa-accepted` at approval and refuses if any fact is still `proposed` (it names them). Status never moves any other way, and never by an AI actor (AI-7: an AI actor is refused by the actor type).
  - `linkBuiltFrom(figureKey, sources[], actor, why)`: a figure built from many facts, accounts, adjusting entries or judgment inputs (TB-9), stored in the given order with one event. "Agrees with" links are L01's.
  - `sourcesOf(figureKey)` (TB-9): every source behind a figure, depth first through facts built from other facts, in a fixed order (link order, then fact id), each with its pointer, so the trace can step through them one by one.
  - `fedBy(documentId)`: every fact sourced from the document and every figure built from those facts, directly or through other facts.
  - `previewReplace(oldDocumentId, newDocumentId)` (EV-9): returns the full impact (`fedBy`) and a preview token tied to a hash of that impact. `replaceDocument(previewToken, actor, why)` resets each affected fact to `proposed` (one event each) and links the new document; it is refused without a token, and refused with "impact changed, preview again" if the impact differs from the preview.
  - `lateEvidence(returnId, documentId, lifecycle, actor)` (FLOW-6): after lock, resets only the facts the document touches; if any of them feeds a figure, it asks the lifecycle (F02's contract, passed in) to send the return back to prepare naming only those figures; otherwise it attaches the document and the state does not change.
- `db/schema/20_ledger.sql` (F01 wrote the tables): add anything the service needs (indexes, a view for the current version of each fact), keeping F01's append-only triggers. No update or delete path exists in the service.
- Every write uses the injected clock and is one transaction: the version row and its event land together or not at all.
- Box (findings F01-F09, RC2): every box this card writes, stores or reads is F09's Box shape (page plus left, top, width and height as page fractions, BoxSchema from src/contracts/reading.ts), never its own {x0,y0,x1,y1}.
- Every write (`acceptFacts` and the rest) takes an optional caller transaction and uses it when given, so T08 can approve in one transaction (reports/phase3-card-review-2026-10-03.md fix 2, A397).

## Acceptance checks
1. EV-1, SEC-7: `changeFact` writes a new version and an event and leaves the old version byte-equal; a direct UPDATE or DELETE on facts' versions or events through the database fails.
2. EV-5: a fact with no source pointer, with two, or with a pointer kind outside EV-5's six is refused with the reason.
3. EV-8: a fact goes `proposed`, `preparer-verified`, `cpa-accepted` only in that order; any change to the fact or its evidence resets it to `proposed`; `acceptFacts` refuses while any fact is `proposed` and names those facts; an AI actor cannot verify or accept.
4. EV-8 property (fast-check, fixed seed): for any sequence of proposes, changes, verifies and accepts, the number of events equals the number of successful writes, no version is ever lost, and a fact's status after its last change is `proposed`.
5. TB-9: `sourcesOf` for each C01 figure equals its golden file; a figure built from five sources lists all five in link order.
6. EV-9: `previewReplace` lists every fact and figure the document feeds (including the one through an intermediate fact); `replaceDocument` without the token is refused; after another fact is linked to the document, the old token is refused with "impact changed, preview again"; with a fresh token, exactly the listed facts reset to `proposed`, each with an event.
7. FLOW-6: after lock, late evidence touching a fact that feeds a figure resets only that fact and asks the lifecycle to send the return back to prepare for exactly that figure (a spy on the passed-in lifecycle); late evidence touching no figure attaches the document and makes no lifecycle call.
8. ARC-10: a fact or link written without a version stamp is refused.
9. EV-1: every write is atomic: a failure injected between the version row and its event leaves neither (a test-only fault hook in the transaction).
