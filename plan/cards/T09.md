## Goal
Just before ops transmits from Taxprep, ops uploads a check export. Returns first re-reads the books (B06), then compares the check export with the approval fingerprint cell for cell. A match is recorded and saved as the `check` version; a mismatch blocks transmit, voids the approval and sends the changed cells back through trace to review (FLOW-5). Ops then records the confirmation number, and the return moves to filed only when a passed check for the standing approval exists. Returns never transmits anything itself (OUT-3).

## Trial-dependent (FINDINGS.md is interim; day 6 covers the check export)
- Whether Taxprep changes cells by itself between lock and transmit. Known: `IFirm.ContactPartner` is wiped when the return is opened (Q23). Fallback in force: `data/transmit/ignore-cells.json` lists the cells the compare skips, each with its reason and trial source; it starts with `IFirm.ContactPartner` only, every other cell is compared, and adding a cell is an amber row (data, not code). Day 6 findings that add a cell go to the Lead, never straight into this file by a builder.
- Whether the check export uses the same saved filter as the lock export. Fallback: it must (T02's filter completeness runs on it); a check export missing a fingerprinted cell's row is a mismatch naming the cell, never a pass.

## Spec
- Fixtures (simulator, S00, pinned clock): C01 approved (T08's fixtures) and moved to `ready_to_file`; check exports: byte-identical to the approved lock export; same cells but re-exported (different bytes, RT-20); one input cell changed; one review line changed; a repeating group's copies renumbered with the same values; a fingerprinted cell's row missing; one cell filled that was empty at approval; `IFirm.ContactPartner` wiped to `""`; a negative exported as `'-1356` equal to the approved -1356; S01's wrong-client export; a B06 stand-in change that feeds a figure; a B06 unmapped new account.
- Classes:
  - RT-19, END-4 (match): the byte-identical export passes with no cell compare (RT-20) and a pointer to the approved lock export; the re-exported one passes after a full compare; the renumbered copies pass (LL-3: by figure key and natural row key, never copy number); the apostrophe negative passes (compare after T02's strip); the wiped `IFirm.ContactPartner` passes because it is on the ignore list, and the result names the ignored cell.
  - RT-19, END-4 (mismatch): each of the changed input cell, the changed review line, the missing row and the newly filled cell fails naming exactly those cells with approved and check values. Property (fast-check, fixed seed): changing any one fingerprinted cell's value in the check export (any cell not on the ignore list) fails naming exactly that cell; changing none passes.
  - RT-19 with FLOW-5: a mismatch voids the approval through the pipeline (no direct call in the test; the test runs F06's queue to idle before asserting the void), the return is in `trace`, and T08's changed-cells store holds the mismatched cells before and after; transmit stays blocked. With `IFirm.ContactPartner` wiped and one input cell changed, the void names only the changed cell.
  - TB-11 order: B06 runs before the cell compare; a B06 change that feeds a figure ends the check as "books changed after approval" with the approval voided (the test runs F06's queue to idle before asserting the void) and no compare run; B06 `blocked` ends the check as blocked naming the flag; the state is unchanged.
  - RT-1: the wrong-client check export is refused by T02 with its reason; nothing is compared or recorded as a check.
  - LL-1: a passed check saves exactly one `check` version through N00 in the same transaction; when that save throws (a fake), no check result is kept.
  - FLOW-2 (the filed gate): guard `ready_to_file_to_filed` passes only with a passed check whose approval still stands, whose check export is the latest export accepted for the return (no lock or check export after it), made no more than the firm parameter (24 hours, `data/transmit/settings.json`) before the move, and a confirmation number recorded after that check; each refusal names what is missing. A passed check for an approval later voided, or followed by a later export, does not count.
  - Filing record: `recordFiling` stores the confirmation number as typed (non-blank, no other format rule until a real one is seen), the transmit date, who and when, and moves the return to `filed` through F02 in the same transaction; it is refused before a passed check, in any state other than `ready_to_file`, and a second filing record for the same return is refused.
  - States and who (AI-7, SEC-2): a check or a filing record from a preparer, an AI actor or the system is refused with the reason and nothing is stored; a check in any state other than `ready_to_file` is refused naming the state.
  - SEC-7: UPDATE, DELETE and TRUNCATE on every table this card adds are refused (db test on PGlite and Postgres 16).
  - OUT-3: no file under `src/modules/transmit/` imports a network client or names a CRA or Taxprep host (a source scan through `readOwnSource`, with a sentinel).
- Golden file (`src/modules/transmit/__golden__/`): the check result for C01's one-cell mismatch (cells, values, ignored cells, approval id).

## Build
- `src/contracts/transmit.ts` (zod): the check result (`passed`, `mismatch`, `books-changed`, `blocked`, with cells, ignored cells, B06's result, approval id, check export id), the filing record, and the service interface. - `src/modules/transmit/`:
  - `checkBeforeTransmit(returnId, bytes, fileName, actor, deps)`: state and actor checks; T02's `receiveExport(returnId, 'check', ...)`; B06's `recheckBooks`; then, unless B06 voided or blocked, the cell compare against the standing approval's cell items in T08's canonical form (figure key and natural row key; value bytes as exported after T02's strip; the ignore list applied and named). Passed: the result row and N00's `saveVersion(returnId, 'check', checkExportId, actor)` in one transaction. Mismatch: the result row, then the "check export accepted" trigger to `approval-watch.ts`, which calls T08's `checkAgainstApproval` with the mismatched cells only (ignored cells are never passed).
  - `recordFiling(returnId, confirmationNumber, transmittedOn, actor, deps)`: the filing record and F02's move `ready_to_file` to `filed` in one transaction (FX5's caller transaction); throws on F02's `{ ok: false }` so nothing is kept.
  - Guard `ready_to_file_to_filed` as above, registered with F02's lifecycle in `src/pipeline/deps.ts`.
  - `// @mutate` on the compare, the ignore-list loader and the guard (mutation 100 per marked file, ARC-15).
- `data/transmit/ignore-cells.json` (identifier, reason, source) and `data/transmit/settings.json` (the 24-hour window); both refused on load if a row lacks a reason or a source.
- `db/schema/78_transmit.sql`: check results with their cells, filing records; append-only with F01's `refuse_change` triggers, row-level security on, no policies, `is_test`, a foreign key on every return_id.
- `src/pipeline/steps/approval-watch.ts`, `src/pipeline/handlers.ts`: the "check export accepted" trigger (T08's step; B06 adds the books trigger first).
