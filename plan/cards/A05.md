## Goal
Two adapters every later card uses for bytes, each with a free local stand-in and a live slot that is off with no key: file storage (where Returns keeps documents, page images, exports and binders) and client documents (the firm's Google Drive Shared Drive, read-only). Other modules reach them through `src/contracts/storage.ts`, never by importing this module.

## Build
- `src/contracts/storage.ts`: the two interfaces. File store: `put(bytes, meta) -> { key, sha256 }`, `get(key)`, `has(key)`, `list(prefix)`. Client documents: `listFolder(corporation, taxYear)`, `getFile(driveFileId) -> { bytes, name, mimeType, sha256 }`. No delete and no overwrite on either.
- `src/modules/storage/files/`: the local-folder file store under a root the caller names. Keys are content-addressed (`sha256/<first two hex>/<sha256>`), so the same bytes are stored once; putting the same bytes again returns the same key and writes nothing. A stored file is never overwritten or deleted through the adapter (write-once, which FLOW-9's frozen binder relies on later). Writes go to a temp name and are renamed, so a crash never leaves half a file under a real key. `get` re-hashes the bytes and refuses a file whose hash no longer matches its key ("stored file changed").
- `src/modules/storage/drive/`: the Drive stand-in: a local folder shaped like the Shared Drive the client app writes (`<legal name> (<first 8 hex of corporation id>)/<tax year>/`, from `reference/onboarding-contract.md`), with a small index file mapping made-up `drive_file_id`s to file names. Read-only: the adapter has no write method. Filling stand-in folders from the test world for journeys is the job of the renderer cards and the harness, never of product code (nothing under `src/` imports `testworld/`).
- Paths: every key and file id is checked; anything that would resolve outside the root (`..`, an absolute path, a drive letter, a symlink out) is refused with the reason.
- Both adapters have an engine switch with `local` (default) and `live` (a named slot that is off, holds no key and refuses with "live storage is off until go-live"; GL1 builds it). Settings are read by name through `src/core/env.ts`; no value is ever printed (SEC-10).
- SEC-11: the Drive stand-in refuses a folder whose company name lacks "(Test)".
- `src/modules/storage/index.ts`: the module's public exports.

## Acceptance checks
1. ARC-6: putting bytes returns a key and their sha256; getting the key returns the same bytes; putting the same bytes again returns the same key and writes no new file (a file count).
2. ARC-6: there is no way to overwrite or delete a stored key through the adapter; changing the bytes on disk behind it makes `get` refuse with "stored file changed".
3. ARC-6: keys and file ids holding `..`, an absolute path or a drive letter are refused with the reason and nothing is read or written outside the root.
4. ARC-6: the Drive stand-in lists C01's folder for its tax year in the client app's folder shape and returns each file with its name, type and sha256; it has no write method (the type has none, and a test calls every exported function to prove none writes).
5. SEC-11: the folder for a company without "(Test)" is refused with the reason.
6. ARC-6, END-8: both adapters default to `local`; switching to `live` with no key fails with "live storage is off until go-live", and switching back to `local` works (both directions tested).
7. SEC-10: the adapters log settings by name only: a planted setting value never appears in the log output.
8. ARC-6: a write interrupted after the temp file is written (a test hook throws before the rename) leaves no file under the real key, and the next put succeeds.
