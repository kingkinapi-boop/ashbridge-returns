## Goal
QBO makes the GIFI mapping; the preparer downloads the .GFI file from QBO and uploads it, and Returns reads it and keeps it as the return's own mapping record (TB-3). From it, each GIFI figure is the sum of its mapped accounts' balances, and anything a person must look at is flagged: an account mapped to no code or to more than one, an account mapped differently from last year, and any account mapped to a total code CRA calculates, which is refused (TB-12).

## The file's layout is not confirmed (the contract must say so)
No source gives the .GFI columns (research open point 1), and no made-up company can be opened in Workpapers yet (open point 3, red, Zo's). So:
- The layout is data: `data/gifi/gfi-layout.json` names the assumed account-level layout (account number, account name, GIFI code, amount, and whether a sign-reversal column exists), marked `"confirmed": false` with the research file and date. The reader takes the separator and encoding from A07's CSV reader.
- A file that does not fit the layout is refused with what did not fit, never guessed. A file that holds code totals only (no account column) is refused with "this file has GIFI totals only; the mapping needs accounts (TB-3)", and the Lead is told through the books result.
- `testworld/qbo/gfi.ts` writes stand-in .GFI files in the assumed layout from the answer keys' trial balance (account, GIFI code, adjusted balance). When a real Workpapers file is seen, the Lead adds a card to confirm the layout and re-make these files.

## Build
- `data/gifi/codes.json`: every GIFI code from RC4088 (the edition named in the file): code, name, statement (balance sheet, income statement, retained earnings), normal side (debit or credit) for the sign, and `calculatedByCra: true` for the totals CRA calculates (for example 1599, 2008, 2589, 2599, 3499, 3620, 3640, 8089, 8299, 9367, 9368, 9999), each with its RC4088 reference. A code marked "confirm" in the answer keys stays a valid code; whether it is the right code is the CPA's.
- `src/modules/books/gifi/`:
  - `importGfi(returnId, fileBytes, fileName, uploader)`: fingerprints the file, stores it write-once through the storage contract, reads it with A07's reader under `gfi-layout.json`, and writes the return's mapping record: one row per account with its GIFI code, the file's amount when the layout has one, the sign-reversal mark when it has one, the file's fingerprint, and a pointer to the file's sheet, row and column (EV-14). A second upload writes a new version of the mapping record with an event; the old one stays.
  - TB-12: an account mapped to a code with `calculatedByCra` is refused for that account with "GIFI <code> is calculated by CRA; map the account to its component codes (RC4088)", and the account counts as unmapped until a new file fixes it. A code not in `codes.json` is refused the same way with "unknown GIFI code".
  - TB-3 flags for a person, each with the account and the reason: an Account from B05 with no mapping row; an account with more than one code in the file; an account mapped differently from last year's mapping record for the same company (when one exists in Returns; otherwise "not checked: no prior mapping"); a mapping row whose account is not in the trial balance.
  - `gifiTotals(returnId)`: for each code, the sum of its mapped accounts' year-end balances in integer cents, signed by the code's normal side (contra accounts such as accumulated amortisation come out negative on asset codes); each total keeps the list of accounts it was built from, in account order, for `linkBuiltFrom` (TB-9) by the figure card. Where the file carries an amount, the file's amount is compared with the computed total; a difference is flagged with both amounts, and a difference equal to twice the amount is reported as "sign reversed?" for a person.
  - Every result carries the layout version, the codes version and this card's code release (ARC-10).
- `src/modules/books/index.ts` gains the GIFI exports (B05 created the file; both cards run one after the other).

## Test fixtures (spec-writer)
- Stand-in .GFI files made with `testworld/qbo/gfi.ts` for C01 and C05 at test time, and changed copies made in the test: an account mapped to 2008; an unknown code; an account missing from the file; an account listed twice with two codes; a file amount with its sign reversed; a totals-only file (code and amount columns only); a file with a column the layout does not name; a prior-year mapping record for C01 with one account on a different code.
- RC4088's worked example from the research file: buildings 1680 = 400,000.00 and 1681 = -100,000.00, equipment 1740 = 50,000.00 and 1741 = -20,000.00.

## Golden files (spec-writer, `src/modules/books/gifi/__golden__/`)

## Acceptance checks
1. TB-3: C01's file is read into a mapping record with one row per account and a sheet, row and column pointer each; `gifiTotals` equals its golden file and each total equals the sum of the answer key's adjusted balances for the accounts mapped to that code, in cents.
2. TB-12: the account mapped to 2008 is refused with the RC4088 reason and counts as unmapped; with RC4088's worked example mapped to component codes, no account is refused and the totals are 1680 = 40,000,000, 1681 = -10,000,000, 1740 = 5,000,000, 1741 = -2,000,000 cents.
3. TB-3: the missing account, the account with two codes and the account mapped differently from last year are each flagged for a person with the account and the reason; with no prior mapping the result says "not checked: no prior mapping"; a clean C01 and C05 file raise none of these flags (no false alarm).
4. TB-3: the file amount with its sign reversed is flagged "sign reversed?" with both amounts; matching amounts are not flagged.
5. EV-14: the totals-only file and the file with an unknown column are refused, each with what did not fit; nothing is written to the mapping record.
6. ARC-13 property (fast-check, fixed seed): for any set of accounts with balances in cents and any mapping of each to one component code, every account appears in exactly one total, and the totals turned back to debit-positive sum to the same cents as the accounts they were built from (zero for a balanced trial balance).
7. TB-3: a second upload writes a new mapping version with an event and leaves the first unchanged; every result carries the layout, codes and code-release versions.
8. TB-12: every code in `codes.json` is four digits and every `calculatedByCra` code cites RC4088.
