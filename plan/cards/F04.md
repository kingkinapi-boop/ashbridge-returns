## Goal
Every AI step in the product returns data in one checked shape, with citations code can verify, so no AI text is ever trusted on its word.

## Build
- One zod v4 schema per AI step type (the JSON Schema for structured outputs comes from `z.toJSONSchema()`; objects allow no extra properties): finding, extraction, category proposal, GIFI mapping proposal, question slot fill, cause tag, red-team item.
- Each has a `citations` array. A citation is exactly one of: a ledger record (kind and id), a document box (document id, page, box, and the quoted text), a page (`{ kind: 'page', documentId, page }`: no quote and no box), a return cell (figure key).
- A finding may be of type "missing", citing where the item should be (AI-5). Every citation of a "missing" finding is a document box, a page or a return cell (never a ledger record); the page kind is allowed only on a "missing" finding (findings wave 2, RC6). Whether the page exists is I00's check, not this card's.
- Every object is strict at runtime (`z.strictObject` or `.strict()` at every depth, including the box, each citation kind, each step's items and the stamp), not only in the JSON Schema: zod's default drops unknown keys silently (findings wave 2, RC2).
- "I can't tell" is a valid answer for every step type (AI-6).
- A version stamp type: exact model id, prompt version and hash, input hash, OCR engine and version, mapping release (AI-10).
- Note for later cards: Claude's own citations feature cannot be combined with structured outputs, so citations are ours and code checks them (reference/build-practices.md 4.2).
- A function that validates raw model output against the schema and returns either the data or the list of problems.
- The first lines of every core file carry `// @mutate` (here `ai.ts`); `npm run mutate:changed` at least 70 before reporting.

## Acceptance checks
1. AI-1: output with no citations fails validation, with a plain reason.
2. AI-5: a "missing" finding that cites where the item should be passes.
3. AI-10: output with no version stamp fails.
4. AI-6: "I can't tell" passes for every step type and is marked to go to a person.
5. AI-1: a citation that is two kinds at once fails; an output with a property the schema does not name fails.
6. AI-4: a document-box citation without its quoted text, page or box fails, so code always has something to check against the words in the box; its box is F09's box schema, imported from `src/contracts/reading.ts`, never a second box shape.
7. AI-1: every step type's JSON Schema from `z.toJSONSchema()` sets `additionalProperties: false` on every object (one test over all step types).
