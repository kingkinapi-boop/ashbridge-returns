## Goal
For each return, code decides which facts the return needs and whether each is found, missing, conflicting or weak. For every fact not found, it picks questions from the approved bank and drafts the question list (ids and empty slots) for the preparer to review. AI only fills slot values afterwards (G02). When the preparer signs the list, it goes to the client app as ids and slot values, the return moves to qa, and "waiting on the client" is a dated flag, not a state.

## Build
- `data/gaps/required.json` (data, not code): the required facts, each a fact key with the condition that makes it required, written over the return's facts and the bridge's onboarding data (for example: every return needs each bank account's closing balance; a company with payroll needs the T4 summary totals; a company that paid dividends needs the T5 summary; HST-registered needs the HST returns for the year; a vehicle in onboarding needs its business-use share), and whether a client-said answer is enough or a document is needed (`needs`: document, third party, or any). Each entry cites its reason (a CRA form line, a clause or the answer key flag it serves).
- `src/modules/gaps/core/` (ledger, lifecycle and bridge through contracts):
  - `gapPass(returnId)`: for each required fact whose condition holds, one status, decided by code only (AI-12):
    - `found`: at least one fact for the key that is not suspect and meets `needs`;
    - `missing`: no fact for the key;
    - `conflicting`: two or more facts for the key (same row key) whose values differ (money by more than 100 cents under F05's rule; other types by value);
    - `weak`: facts exist but every one is suspect, or rests only on a client answer where `needs` asks for a document or a third party.
    Each status carries its reason and the pointers of the facts it looked at. Writes a gap list version with an event; a later pass writes a new version.
  - `draftQuestions(returnId)`: for each gap not `found`, the bank items `pick` returns for its fact key, as a draft question list (item id, gap, empty slots). A gap with no bank item is listed "no question in the bank" for the preparer, never dropped.
  - `signAndSend(listId, preparer, deps)`: refused unless the actor is a preparer holding the return (FLOW-10) and the list has at least one question; writes the hand-off rows through G01's `toHandOff` into F07's table, moves the return gaps to qa through the lifecycle contract (FLOW-2), and sets the dated "waiting on the client" flag (FLOW-3). A list with nothing to ask moves the return gaps to build instead, with the reason "nothing to ask".
  - No fact status changes here (EV-8: verifying facts is the preparer's in the screens).
- `src/modules/gaps/index.ts` gains the gap pass exports.

6. Property (fast-check, fixed seed): for any set of facts for a required key, exactly one status is given, and adding a non-suspect fact that meets `needs` to a `missing` key makes it `found`.
7. A second gap pass writes a new gap list version with an event and leaves the first unchanged.
