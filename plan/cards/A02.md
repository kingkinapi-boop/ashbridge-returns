## Goal
The free reading engine for scanned pages: the pages A01 reports as "no text layer" are rasterised and read by Tesseract, returning every word with its box and confidence in F09's shape, behind the same reading adapter. No paid service, no key, no network.

## Build
- `tesseract.js` (Apache 2.0) at an exact pinned version, with the English language data from a pinned npm package (for example `@tesseract.js-data/eng`) loaded from `node_modules` by a local path; the worker and core files are local too, so nothing is fetched at run time. The cache folder is a private temp folder.
- `src/modules/ocr/tesseract/`: rasterises each requested PDF page at 300 dpi with `pdfjs-dist` and `@napi-rs/canvas` (added by W20), page rotation applied, then reads it. Image files (PNG, JPEG, TIFF first page) are read directly. Words come back with boxes converted from pixels to F09 fractions (F09's converter) and confidence turned from 0 to 100 into 0 to 1, in Tesseract's reading order.
- The result is stamped with engine `tesseract`, the tesseract.js version and the language data version (ARC-10). Words below confidence 0.6 keep their low confidence; nothing is dropped or "corrected".
- `read(document, { pages })`: reads only the pages asked for (intake asks for the pages A01 found without a text layer; combining the two engines' pages for one document is E00's job).
- ARC-11: results are stored per document fingerprint and page, so a second read of the same bytes does not run Tesseract again.
- `src/modules/ocr/index.ts`: add `tesseract` to A01's engine switch; `textlayer` stays the default; `live` stays off.
- One Tesseract worker per process, created lazily and reused; a page that takes longer than 60 seconds is refused with "page took too long" rather than hanging.

## Test fixtures (spec-writer, `src/modules/ocr/tesseract/__fixtures__/`)
- Made by a committed script with W20's framework: a one-page made-up statement for sample client C01 (company name ending "(Test)", ten amounts including "$1,234.56" and a bracketed negative, a date), its scan through W20's `toScan` (fixed seed, 300 dpi, skew under one degree), the scan's answer file, a page turned 90 degrees, and a blank page. The scan PDF is generated in the test run (scan bytes are platform-specific, W20); only the definitions and answer files are committed.

## Golden files
None (Tesseract output is checked against the answer file, not frozen bytes).

## Acceptance checks
1. EV-6: on the fixture scan, F09's `valueInBox` finds at least 9 of the 10 amounts at their answer-file boxes, and "$1,234.56" and the bracketed negative are always among them; every miss is listed by key in the test output.
2. ARC-6: the result passes F09's schema; every word has a box inside its page and a confidence between 0 and 1.
3. ARC-6: the page turned 90 degrees gives boxes in the upright frame (its amounts are found at the upright answer boxes, same threshold as check 1).
4. ARC-6: a blank page returns zero words and is reported as "no words found" for that page, not as an error and not as a success with made-up text.
5. ARC-10: the result carries engine `tesseract`, the tesseract.js version and the language data version; a result without them is refused by F09's schema.
6. END-8: with every network call blocked in the test (a guard that throws on any outbound request), reading the fixture still works.
7. ARC-11: a second read of the same bytes returns the stored words without calling the recogniser again (a counter or spy shows one call per page).
8. ARC-6, END-8: switching the adapter to `tesseract` and back to `textlayer` works both ways; `live` stays off and refuses with "live reading is off until go-live".
9. ARC-11: in the cloud, the one-page fixture reads in under 20 seconds (a timing check, cloud only).
10. END-8: the new dependencies need no account, key or payment, and `npm audit --audit-level=high` stays clean.
