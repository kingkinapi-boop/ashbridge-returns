## When it starts
This card waits until D07 (gap review) is approved by Zo at a design sitting (RV-53); the Lead marks D07 done then.

## Goal
The preparer reviews the draft question list before anything goes to the client: each question beside the evidence that raised it, and for each one keep, edit slot values, merge, drop, or add another from the bank; then sign, which sends the list to the client app as ids and slot values. The screen shows staff labels only; the client's wording lives in the client app.

## Build
- `src/app/(staff)/prepare/gaps/` (a tab of the return record shell, V00), built to D07's approved design:
  - The gap list from G00 (status found, missing, conflicting or weak with its reason, in words and a non-colour cue) and, for each gap not found, its draft questions with their staff labels, slot values (G02's fills with their citations, or empty) and G02's observations.
  - Each question's evidence beside it: the facts and pointers G00 looked at; any pointer opens in the source viewer (V01, rule 20).
  - Actions in place (rule 19): keep; edit slot values (typed by the slot's type; a money or date value typed by the preparer needs no citation but is marked as typed by the preparer); merge two questions that resolve the same fact into one; drop with a reason; add from the bank (search G01's bank by topic or fact key; only bank items can be added, so no free-text question exists). Each change writes a new version of the list with an event.
  - "Sign and send": through G00's `signAndSend` (the preparer must hold the return); refused with the GOV.UK error pattern when a required slot is empty, naming each one. A list with nothing to ask offers "Nothing to ask" instead, which moves the return to build.
  - Nothing on this screen shows or edits client wording (END-7).
- Shortcuts through U01: next question, keep, open evidence; drop and sign are `focus` only (rule 22).

## Acceptance checks
1. RV-23: each draft question shows beside its gap and evidence; opening a piece of evidence opens the source viewer at its box.
2. RV-23: keep, edit a slot value, merge the two questions on one fact, drop with a reason, and add an item from the bank each work in place and write one new list version with an event; focus moves to the result and it is announced.
3. AI-12: there is no way to add a question that is not in the bank (the add control lists bank items only, and a forged request with an unknown id is refused).
4. RV-23: signing with an empty required slot is refused, naming the slot; with all slots filled, signing sends the hand-off rows, the return moves to qa and the queue shows "waiting on the client since <date>"; the all-found return offers "Nothing to ask" and moves to build.
5. END-7: the page and the hand-off rows hold no client wording: labels only on the page, ids and slot values only in the hand-off.
6. FLOW-10: a preparer who does not hold the return sees the list read-only with who holds it, and cannot sign.
7. RV-53: the gap review matches D07's approved pages within the visual threshold, and D07's budgets hold.
8. RV-54: U02's sweeps pass; the whole review and signing work by keyboard alone; the golden ARIA snapshot matches.
