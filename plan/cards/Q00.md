## Goal
One engine runs every check on a return the same way: it finds the checks that apply, gives each its inputs, records "not checked: no evidence" where evidence is missing, turns fails and unexplained remainders into exceptions with their dollar amount and tax effect, sends every flag to a person, and hands the review one list sorted red first, then by dollar effect. The thirty-odd check cards then only write a record and a rule.

## Build
- `src/modules/checks/engine/registry.ts`: finds check modules by folder (`src/modules/checks/{ties,reconciliations,flags}/ck<NN>/index.ts`, and AI checklist topics registered through I01), each exporting a F05 `CheckRecord`, its `run(inputs)` and a severity (`red` or `amber`). A record that fails F05's validation, a duplicate id, or a missing severity stops the run with the reason. Check cards never edit engine files.
- `src/modules/checks/engine/run.ts`: `runChecks(returnId, deps)`: for each check whose `appliesTo` holds, loads its named inputs through the ledger contract and T07's review lines; any input missing gives `not checked: no evidence` without calling the rule (CK-2). A tie result uses F05's tie comparison (CK-3); a reconciliation uses F05's `reconcile` and raises only the unexplained remainder (CK-4). A fail or remainder becomes an exception with its amount in cents and an estimated tax effect (CK-6, F05's validator). A flag result is stored as a flag for a person; nothing in the engine turns a flag into pass or fail (CK-5).
- `src/modules/checks/engine/taxEffect.ts`: `estimateTaxEffect(amount, returnFigures)`: the amount times the return's own rate (Part I tax plus Ontario tax over taxable income, from T07's review lines); with no review lines yet, the firm parameter default rate named on screen as the firm's own (data in `src/modules/checks/engine/parameters.json`, changed only by an amber row). Integer cents, half away from zero, one rounding at the end.
- `src/modules/checks/engine/order.ts`: `orderForReview(items)` (EX-4): red before amber, then by absolute estimated tax effect, then absolute dollar amount, then check id (stable, so the same inputs give the same order).
- `db/schema/70_checks.sql`: a check run (return, time, the version stamps of its inputs, ARC-10) and one append-only result row per check per run (status, amounts, exception, flag, severity); a new run never edits an old one.
- `src/pipeline/steps/checks.ts` replaces F10's placeholder; the skeleton's "one tie" stub is removed from `stubs.ts` and `stubs.md`.
- `// @mutate` on `run.ts`, `taxEffect.ts` and `order.ts`; mutation 100 per marked file (ARC-15).

## Acceptance checks
1. CK-1: three fixture checks (a tie, a reconciliation, a flag) placed in the folder layout are found and run; a fixture with no source link, a duplicate id or no severity stops the run naming the module.
2. CK-2: with one named input missing, the result is `not checked: no evidence`, the rule is not called, and no summary counts it as a pass.
3. CK-3, CK-4: the fixture tie fails one dollar apart and passes at 99 cents; the fixture reconciliation with items explaining the difference raises nothing and with one dollar unexplained raises an exception of exactly 100 cents.
4. CK-5: a flag result is stored as a flag whatever the rule returns alongside it; no engine function produces pass or fail from a flag (a sweep over the module's exports).
5. CK-6, ARC-13 property (fast-check, fixed seed): every exception carries an amount and a tax effect in integer cents; the tax effect equals the amount times the rate, rounded once.
6. EX-4: a mixed list orders red first, then by absolute tax effect, then amount, then id; shuffling the input gives the same order (property).
7. ARC-10, SEC-7: every run stores its input version stamps; result rows refuse UPDATE and DELETE.
8. SK0: the skeleton's "one tie" stub is gone, the C01 skeleton journey still passes, and its tie now runs through the engine.

## Ambers for the Lead
- Check modules are found by folder convention, so check cards never share a file.
- Each check declares its severity (red or amber); a missing one stops the run.
- Tax effect: the return's own rate from its review lines, else a firm default rate as data; "dollar effect" in EX-4 read as tax effect, then amount.
