## Goal
One shape for what any reading engine returns (the PDF text layer, Tesseract, recorded results, a live vendor later), and one code check that a value really sits inside a box, so extraction (EV-6) and AI citations (AI-4) are judged the same way whatever engine read the page.

## Build
- zod schemas and types: a reading result for one document (document fingerprint, engine name and version, page count, the time it was read from the injected clock) holding pages (number, width and height in points, rotation already applied, whether a text layer was found) and words (text, a box, confidence 0 to 1, the engine's reading order).
- A box: page number plus left, top, width and height as fractions of the page (0 to 1, origin top left), so every engine's boxes compare. Converters from points (PDF, origin bottom left) and from pixels (images, origin top left).
- The engine and its version are stamped on every result (ARC-10); a result with no engine version is refused.
- `wordsInBox(result, box)`: the words whose centre lies inside the box, in reading order.
- `normaliseAmount(text)`: strips dollar signs, commas, spaces and a trailing CR or DR; reads brackets and a leading or trailing minus as negative; returns integer cents, or "not a number" with the reason. No floating point on the way.
- `valueInBox(result, box, value)` (EV-6): true only when the value, after normalising both sides, is found among the words in the box (a value may span adjacent words, such as "1 234.56" or "$ 1,234.56"); otherwise false with the reason ("no words in box", "value not found", "box on another page"). Text values compare after trimming and folding case and spaces.
- The adapter interface every reading engine implements (ARC-6): `read(document) -> reading result`, an engine name, and an `isLive` flag. No engine here.

## Acceptance checks
1. EV-6: `valueInBox` finds 1234.56 in a box holding "$1,234.56", and in a box holding "1,234" and ".56" as two adjacent words; refuses it when the same words sit just outside the box, and when the box is on another page.
2. EV-6: `normaliseAmount` reads "(1,234.56)", "-1234.56", "1,234.56-" and "1,234.56 CR" as the cents the bank layouts mean (state each sign rule in the test), and refuses "1.234,56", "1.2E3" and an empty string with a reason.
3. EV-6 property (fast-check, fixed seed): for any integer cents up to 10^13, formatting it with a dollar sign, thousands commas and two decimals, then normalising, returns the same cents.
4. EV-6 property: for any set of words and any box, `wordsInBox` returns exactly the words whose centre is inside, and moving the box off the page returns none.
5. EV-5: a box pointer that names no page, or a page beyond the result's page count, is refused by the schema.
6. ARC-10: a reading result without the engine name and version is refused.
7. Converting a box from PDF points to fractions and back returns the same box (property, tolerance of one hundredth of a point).
