# A06 findings review (round 1; A06's first failure)

Inputs: reports/A06-security.md (M1, L1 to L4), card A06, reports/A06-check.md (PASS, cloud-dea37c) and the code at origin/claude/A06, blueprint SEC-1, SEC-7, SEC-10, SEC-11, ARC-6, ARC-20, END-8, `.claude/rules/testing.md`. Claims: spec reported, check PASS, build released for these findings; no earlier fix round, so this is the **first** failure. All five findings reproduce in the code (engine.ts:88, 147-151, 165-179; index.ts:18). The card is right in substance; one acceptance line changes (amber, below). Nothing here is red.

## Root causes
**RC1. A stand-in is chosen by silence, and nothing stops it in production** (M1). `createAuth` reads `AUTH_ENGINE ?? 'testusers'` (index.ts:18) with no look at NODE_ENV, and the engine seeds nine test users, three of them owners, into whatever database it is handed (engine.ts:88); credentials are public by design. Same fallback elsewhere: A01 `OCR_ENGINE ?? 'textlayer'` read raw from process.env, not through env.ts (src/modules/ocr/index.ts:17); A05 unset means `local` (src/modules/storage/safe.ts:47); coming: A02 and A03 (join the OCR switch), A04 (AI runner), B04 (`QBO_ENGINE`), GL1 (the live side of all of them). No go-live switch exists anywhere yet, so "while go-live is off" (SEC-11) is unconditional.
**RC2. A "once" or "at most N" rule is a JavaScript read then a write, with nothing in the database to enforce it** (L1, L2). Lock-out: `isLocked` then scrypt then `record` (engine.ts:148-151, 165); code reuse: read used steps, insert session, then write the success event (170-179). Parallel calls all read before any write. Can also bite: F06 (claiming a job; attempts at most 3), F10 and E00 (enqueue once per idempotency key), E01 ("no second fact"), L00 (the preview token of `replaceDocument`), N00 (next version number), Q00 (one result per check per run), F02 and V00 (holds and approvals), and GL1, which copies this lock-out for real passwords.
**RC3. A refusal path does less work and keeps more than the success path** (L3, L4). Unknown, locked and non-test users return before scrypt (147-150), so time tells. For an unknown user the typed text goes to the append-only `sign_in_events.user_id` (no foreign key) and to the log under `userId`, which the logger does not redact (log.ts redacts by key name only). Can also bite: V00 (sign-in screen and source log: typed text written before it is matched), T02 (an uploaded export's GUID and file name into append-only tables), F07 and G00 (A381: SIN-shaped digit runs accepted into the hand-off table, the same family), any append-only text column fed from user input.

## Fix list for the builder (round 2, in this order)
1. RC1: in `createAuth`, when NODE_ENV is `production` an unset or blank `AUTH_ENGINE` is refused naming the setting (never a value); `testusers` stays the default only outside production. Keep the rule in the factory, not in env.ts's schema (else every `readSettings` call in production throws). Before seeding, the testusers engine refuses to start, and writes nothing, if `staff_users` holds any row with `is_test = false`.
2. RC2 lock-out: run `startSignIn` and `finishSignIn` for a known user inside `db.transaction`, taking `select ... from returns.staff_users where id = $1 for update` first; every read and write inside (eventsOf, record, refuse, the session insert) uses the transaction handle. A query on `db` inside a PGlite transaction waits on its own lock forever: this is the most likely new bug.
3. RC2 code reuse: `15_auth.sql` adds `create unique index ... on returns.sign_in_events (user_id, code_step) where outcome = 'success' and code_step is not null`; write the success event before the session, in the same transaction; a 23505 becomes refusal `code reused` (recorded after the rollback).
4. RC3 timing: every `startSignIn` refusal runs exactly one scrypt, against a fixed dummy hash when there is no real one, before it returns.
5. RC3 typed text: an unknown user's event has `user_id` null and its log line has no user id; add `references returns.staff_users (id)` to `sign_in_events.user_id` so nothing but a real id can land there (staff users are then never deleted, only switched off: a note for V00 and GL1).
6. Card A06 (Lead, amber): acceptance 7 reads "testusers by default outside production; in production `AUTH_ENGINE` must be set"; GL1 gains "the go-live switch makes every stand-in refuse to start", the one place SEC-11 becomes a real switch.

## Acceptance tests to add (spec job, `auth.acceptance.db.test.ts`; clock pinned; races assert an invariant that holds for every interleaving, so they cannot flake)
- ARC-6, SEC-11: `createAuth({ env: { NODE_ENV: 'production' } })` rejects naming AUTH_ENGINE and `staff_users` stays empty; `{ NODE_ENV: 'production', AUTH_ENGINE: 'testusers' }` works; on a clone holding one `is_test = false` staff user, testusers rejects and inserts no row.
- SEC-1 lock-out race: 8 parallel `startSignIn` with wrong passwords for one user: at most 5 events say `wrong password`, the rest `locked`; then the right password and code are refused until 15 minutes on the pinned clock. Same with 8 parallel wrong codes on 8 challenges.
- SEC-1 code race: two challenges, `Promise.all` of `finishSignIn` with the same code: exactly one session row, one `signed in`, one `code reused`; a direct second success insert with the same (user_id, code_step) fails 23505.
- SEC-1 equal work: with `node:crypto`'s `scryptSync` wrapped to count calls (a library, not our module), an unknown user, a locked user, a non-test user and a wrong password each cost exactly one call.
- SEC-10: `startSignIn('PLANTED-pw-in-id-box', 'x')` leaves the planted text in no log line and no column of any auth table; the event's `user_id` is null; an insert of an unknown user id into `sign_in_events` fails 23503.
- Every test also runs on Postgres 16 in the cloud check (row lock and partial index parity).

- **R66** every text column of a table with a `refuse_change` trigger has a foreign key, a CHECK list or format, or a line in a reviewed free-text list with its reason (FLOW-1 reasons go there). Planted: an append-only `user_id text` with none.
