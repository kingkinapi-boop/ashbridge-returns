## Root causes (2)
1. **State that outlives its owner, with a cleanup that swallows failure.** The handle's role and settings are copied to a pooled connection at session scope before `begin` (A419 asked for `set local`), and `reset role; reset all` runs under `.catch(() => undefined)` before a plain `release()`. A failed reset (for example `fn` rolls back, then leaves an aborted block) returns a dirty connection to the pool; `reset all` never touches `session_authorization` (findings 1, 2). Where else: `dropOwnedRoles` (index.ts:206) runs `reset role` only, so a handle under `set session authorization` fails every `drop role`, swallowed, and the role outlives the run in the cluster (roles are cluster-wide; `dropRunDatabases` drops databases only). Fixed role names in tests (db16_tx, anon_test, nobody_test, auth and jobs roles) collide across parallel workers once one leaks. Callers that inherit a leak under pg16: src/modules/jobs/queue.ts, bridge/run.ts, lifecycle/index.ts, auth/testusers/engine.ts, and the `set role` tests in records, auth and jobs acceptance: a leaked restricted role can turn a denial test falsely green. Later: any live adapter over a pooler (Supabase, RLS cards A06, B04, V00, X00) has the same trap.
2. **The copy works from a partial model of session state, and nothing compares the result with the handle.** Identity is modelled as `set role` only (copied when current_user differs from session_user), so `set session authorization` on the handle leaves the transaction as the superuser login and bypasses row-level security (finding 3). Custom settings are found by regex over SQL text, which misses `set_config($1, ...)` (finding 4, fails closed but silently). The A419 test checks only role, a literal set_config and sequential reuse that may land on another pool connection.

## Consolidated fix list (spec patch first, then build round 5)
1. Spec job (Opus, core-grade): add tests T1 to T5 below to pg16.acceptance.db.test.ts (spec-owned); pg16-only where PGlite's single session makes them vacuous (gate with `ON`, as the race test does); each shown failing on 36672c88.
2. Build, `transaction`: `begin` first, then copy inside it with `set local session authorization` (when the handle's session_user differs from the login user), then `set local role` (when current_user differs from session_user), then `set_config(name, value, true)` for every session-source setting except `role` and `session_authorization`, and every tracked custom name.
3. Build, release: after commit or rollback run `discard all`; on any failure in rollback, discard or the copy, `client.release(err)` (destroy). Never a bare `release()` after a swallowed error. Acceptable simpler form: always `release(true)` (a new local connection per transaction; record the test:flake time).
4. Build, `tracked(c, sql, params, run)`: `set_config($n, ...)` takes the name from params[n-1]; a `set_config(` whose name is neither a literal nor `$n` marks the handle opaque, and the next `transaction` is refused with a message naming that statement (the spec allows refusal; it must name what it could not carry).
5. Build, `dropOwnedRoles`: `reset session authorization; reset role` first; a failed `drop role` fails `close()` naming the role (no swallow).
6. Lead: add to .claude/rules/code.md: "a pooled connection carries only transaction-local state (`set local`, `set_config(..., true)`), or it is destroyed on release; never swallow a failed reset". Add it to the card that builds the live database adapter when carded.
7. Lead: landing rule on this card: new parity edge cases found at the next check go to SC11, not DB16 (known ones now: a temp table made in a transaction is not visible to the handle on pg16; statements after `tx.rollback()` autocommit; named prepared statements after `discard all`).
