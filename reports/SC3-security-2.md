## New lows from the fix rounds
- **N1 a bracket counts as a format.** formatPattern (harness.ts:483-494) treats every bracket expression as a format, so `^[^\s]+$`, `^[\s\S]+$`, `^[^<]*$` and `^[[:print:]]+$` vouch, while `^\S+$` and `^.+$`, the same non-blank match G2 refuses, do not (probed; on scratch PGlite a CHECK `k ~ '^[^\s]+$'` took `x<script>|;DROP`). Scenario: L00 deletes its eight KNOWN entries and gives facts.source_qbo_snapshot_id that check instead of a key; R66 goes green and a source pointer can dangle. Nothing on main relies on it (jobs.kind's `^[^:[:space:]]+:[^:[:space:]]+$` has a literal colon and is a real format). Smallest fix: a negated bracket, or one holding \S, \W, \D, [:print:] or [:graph:], counts as a wildcard when repeated unless the pattern holds a literal outside brackets; plants for the three spellings. Accepted for boarding: the exposure starts with the owners' builds; T08 (sha256 hex) and FX17 (keys, planted refusals) already name real constraints; L00 and B05 need one card line.
- **N2 AFTER guards are missed.** appendOnlyTables requires BEFORE timing (:444) and the unit twin pins that (:486, :508-509; its comment "refuses nothing in time" is wrong). On scratch PGlite an AFTER DELETE and an AFTER TRUNCATE trigger that raise refused both, yet the table was not in the set and the sentinel stayed silent because the message lacked "append-only". No table on main uses one; both house guards say "append-only", so their misuse is caught; T08's card requires refuse_change. Fix: count DELETE and TRUNCATE triggers of either timing (main's set is unchanged) and flip the twin.
- **N3 the rule logic is open to four owners.** harness.ts is in the Paths of L00, B05, T08 and FX17. The test file pins every list (FREE_TEXT, KNOWN columns per owner, notAdapter, sentinel, LANDING, FORMAT_FUNCTIONS, NEVER_FORMAT, NOT_SETTINGS, behindFactory names) but not the functions or the behindFactory module paths. A narrow edit (freeText skipping one table, plus deleting that table's FREE_TEXT and KNOWN lines, which the pins allow) passes every test, since the twins use planted names. Accepted: it is a weakened check (A329) and shows in the owner's diff. Smallest fix: pin a sha256 of harness.ts with the KNOWN block blanked in security-rules.test.mjs, or move KNOWN to its own file and give owners only that file.
- **N4 tags are case-sensitive.** MENTION (harness.ts:195) misses `@Once` and `@ONCE`: neither a tag nor a problem (probed). Fix: the `i` flag, so STRICT reports it. Accepted: an unlikely spelling.
- **N5 vouching ignores boolean structure.** checkVouches reads text, not the expression: `(actor = ANY (...)) OR (other IS NOT NULL)` and `(actor ~ '^[a-z]+$') IS NOT TRUE` both vouch (probed). Accepted: closing it needs a SQL parser, the edit is visible in a schema diff, and FX17's own tests refuse unknown actors.
