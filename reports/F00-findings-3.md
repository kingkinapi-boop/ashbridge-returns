## Root causes
1. **The build has no written rule that nothing leaves the machine unpinned or unasked** (findings 1, 2, 4, 5). CI was hand-written: a curl with no checksum, actions on moving tags, the job token left in `.git/config`, Next.js telemetry on in `build`, `dev`, `e2e` and Playwright's `next start`. Nothing in testing.md's "no network in tests" is enforced at run time either. Where else: every later step added to `.github/workflows/**`; D00 and U00 (Roboto: `next/font/google` would fetch at every `next build`; it must be a self-hosted file); a future `npx playwright install` (downloads browsers); Stryker's `dashboard` reporter (today `clear-text`/`json`, nothing stops it); npm's update notifier; B04 and A08 (paid services behind adapters: a test that forgets the stand-in would call out silently).
2. **Redaction is a guessed regex over spellings, not the known list of personal-data kinds, and messages are free text** (finding 3, plus DOB and bank numbers inside messages). It misses `clientSin`, `bankAccount`, `transitNumber`, `institutionNumber`, every credential (`password`, `token`, `accessToken`, `refreshToken`, `codeHash`, `secret`, `authorization`) and number-typed SINs; it over-redacts GL data (`accountNo: "6100"` is a GL code in every sample client's answer key). The security review's "contains `sin`" fix would also redact `businessNumber`, `business_use_percent` and `claims_small_business_deduction` (b-u-SIN-ess), and "contains `account`" would hide every GL account; match whole word parts instead. Where else: A06 (passwords, codes, tokens: SEC-10 acceptance 6 assumes the logger is safe), B04 (QBO tokens and settings, acceptance 9), A08 (planted SIN), E00 (document text), V00 (source log), every module that logs.
3. **Scripts build shell command lines from data** (finding 6). `tools/mutate-changed.mjs:29` and `tools/test-flake.mjs:13` use `shell` on Windows only to find `npx.cmd`. Where else: `tools/heavy.mjs:55` (`shell: true` by design: the Lead's tool, outside F00; allowlist it), every later tool in `tools/` (F08's matrix changes, queue tools).
4. **The canary has two equivalent mutants** (check note 1, security item 8; Lead A248 accepted 75). A canary below 100 cannot tell "one mutator family silently off" from "equivalent mutants". Cheap to fix now while a spec job runs anyway; reversing A248 is the Lead's amber call.

## Fix list for the builder, in order (all six findings fixed now; all are cheap)
1. `checks.yml`: `actions/checkout` and `actions/setup-node` pinned by full commit SHA with a `# v4.x.y` comment; checkout `persist-credentials: false`; gitleaks downloaded to a file, `sha256sum -c` against the pinned SHA-256 from v8.28.0 `checksums.txt` (write the source in the build report), then extract; job `env: NEXT_TELEMETRY_DISABLED: '1'`.
2. `tools/run-next.mjs` (new, plain Node; not `tools/next.mjs`, which is the Lead's queue tool): sets `NEXT_TELEMETRY_DISABLED=1`, runs `node_modules/next/dist/bin/next` through `process.execPath`, `shell: false`. Scripts `dev`, `build`, `e2e` use it; Playwright `webServer.command` uses it and `webServer.env` sets the variable. `.npmrc`: `update-notifier=false`, `fund=false`.
3. `src/core/log.ts`: one exported data list `SENSITIVE_KINDS` (sin, social insurance, date of birth/dob/birth date, bank transit, bank institution, bank account, account number, ontario company key, password, token, access/refresh token, token/code hash, secret, api key, authorization). Keys are split into word parts (camel, snake, kebab, spaces, upper) and redacted when their parts contain a kind's parts in order; `account`, `accountNo`, `acct`, `glAccount`, `gifi*`, `businessNumber` stay visible (amber below). Strings and numbers both pass the SIN pattern. Depth cap 20 and cycle-safe. Add `// @mutate` to `log.ts`.
4. Production code logs only through `makeLogger`, and the message is a constant string: ESLint `no-restricted-syntax` refuses a template literal with expressions or a `+` as the first argument of `.info/.warn/.error` on a logger, and `no-console` in `src/**` (override for `src/core/db/global-setup.ts`).
5. A run-time network guard: `src/core/test-no-network.ts` in `setupFiles` of the `unit`, `db` and `evals` projects and `vitest.mutate.config.ts`; it wraps `fetch` and `net.Socket.prototype.connect` and refuses any host other than loopback with "network blocked in tests: <host>" (file: and data: URLs pass).
