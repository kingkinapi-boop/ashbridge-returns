## Root causes (all three are inside A07C's named classes)
- RC0 (process, behind all five rounds): specs plant the check's last example plus a narrow property; the Opus read samples the whole class and finds the next point (large magnitudes, then mixed signs, then 1e-9, then self-closed `<f/>`, now quoted names, 1e21, nesting). The R2-1 spec planted only `ROW()*5`, a formula with no references, so the slider was never tested.
- RC1, class 2: `slide()` in raw.ts is a regex over a grammar it does not model. It slides inside quoted sheet names (`'Q4 FY2026'!B1` gives `'Q5 FY2027'!B2`) and skips whole-column and whole-row references (`SUM(A:A)`, `1:1`). The round-2 build also made `raw.formula` win for every shared child, not only hyperlinked ones, so the fault reaches unlinked cells too (a scope widening with no baseline that had references).
- RC2, class 1: snapSums visits cells row by row, not in dependency order. An outer SUM above or left of an inner SUM sees unsnapped text and is never snapped.
- RC3, class 1: number text is specified and tested only on the money band. At the edges it falls through to hand-written paths: `plain()` expands any value of 1e21 or more through BigInt, and the 4-ulp band snaps subnormals to "0".
- Not a defect: the check's soft cancellation case (a stale 0.014 rewritten to "0.01") is inside the card's own rule ("within the sum's own rounding", capped at half a cent, which is what a two-decimal display shows). No fix; A07D states it.
