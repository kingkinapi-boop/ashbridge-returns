## Root cause (1, two faces): scope.mjs guesses spec ownership from text that does not carry it
- (a) R82 as built: any file token in the Spec prose is spec-owned, so a Spec that describes the build's own file fails the build. Of 47 card files with a `## Spec` section, those naming a non-expectation Paths file: open FX2 (src/core/env.ts; build open, fails the moment CQ4 lands), CQ4 (tools/scope.mjs), SC9 (tools/test/lib/walk.mjs, the build's walker); done or parked CQ1, CQ2, BL0, DG2, F03R, F09A, F09B, F01C. Excluding files the Build names is not enough: DG2, F09B, F01C and SC9 name build files in Spec only. What R82 must protect (FX8-findings root cause 2) is the expectation class: tests, fixtures, goldens, verify scripts, README counts.
- (b) Landed R19: a file a `spec(<card>):` commit touched stays spec-owned for all time, reports/** included, so the spec job's own later commits (wip, its report, the Spec commit line of spec-writer.md step 7) fail. Open branches hit today: DB16 (b14182c, 49cd785, 8924d4e), FX2 (1 report commit), S00 (4). Checkers then clear it by hand, the drift R82 was meant to end.
- Other places the same guessing bites: the card text comes from the current checkout, so run in a build worktree it reads the branch's card (an allowed path: a builder can unname a file); the `--cc` merge check covers Spec-named files only, so a hand-resolved conflict in an acceptance test passes; scope reads only origin/claude/<id>, so W16 (claude/W16-r2) and FX8 (claude/FX8-r2) are judged on stale round-1 branches (W16's shows 562b3494's old README edit); R82 reaches only cards with a `## Spec` heading (29 of 241 open; 162 family cards have no card file, 50 card files use other headings). FX8's README count is spec-owned by its bold directive only, so R82 cannot see it.
