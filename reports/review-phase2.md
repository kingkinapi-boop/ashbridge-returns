## Proposed ambers (what; why; reverse)

1. T02 filter completeness covers non-repeating cells only; repeating cells are matched by natural key and a key no copy holds is "missing", classed dropped by T04. Why: a filter lists only copies that exist (RT-22), so a deleted copy is a dropped value (RT-14 "blank or missing"), not a wrong filter. Reverse: refuse the export and tell the preparer to re-add the copy.
2. T02's content test refuses as stale only when no changed cell holds import N's value and every changed cell still holds its value from before import N. Why: a one-cell import typed over by the preparer was refused as stale, with no way forward. Reverse: back to A212.
3. T01 `stillHeld` lists cells Taxprep holds whose figure is gone or waiting; `requestClear` (renamed from `clearCell`) needs a person and reason and refuses AI; V06 offers the clear. Why: RT-8 clears need a person and reason, and no card let one be asked for. Reverse: the preparer clears by hand in Taxprep and the trace classes it.
4. T01's `import` step moves the return from build to prepare after version 1. Why: blueprint 02's build row; no card did it. Reverse: a pipeline-level move in F10.
5. T12 `markReady` moves prepare to trace, called by V06's "Ready" button. Why: blueprint 02's prepare row ("Ready pressed"); no card did it. Reverse: move to trace when the first lock export is accepted.
6. T12's `signOff` is the trace sign-off (trace to respond) and saves the preparer version there; the respond-to-review signature belongs to phase 3 and re-runs `blockers`. Why: blueprint 02 puts "preparer signs" on respond's exit while RT-18 and LL-1 tie the preparer version to "sign-off"; the lock export cannot change between the two without a return to trace. Reverse: save the preparer version at the respond-to-review signature.
7. T12 `blockers` includes "no accepted lock export"; T05 reports "no printed return for the latest lock export". Why: blueprint 02's trace exit needs both uploaded. Reverse: V06 alone stops sign-off without them.
8. T05 accepts a paste only when the printed return gave no diagnostics page (or unparsed rows); the paste keeps its author and the "pasted" mark. Why: otherwise a paste could hide an Error the printed return showed. Reverse: accept any paste, marked.
9. M00 `loadMapping` refuses a `taxChoice` row missing from the tax-choices file and a file cell with no row. Why: A231 keeps two lists; the trace (T04) and the writer (T01) must read the same one. Reverse: derive the file from the rows (A231's reverse).
10. T07 review lines may be input cells when marked `input: true` (for example instalments paid). Why: the brief shows instalments, which the preparer types; RT-10's lines are mostly but not only calculated. Reverse: drop instalments from the review lines.
