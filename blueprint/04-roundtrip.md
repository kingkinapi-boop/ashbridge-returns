# 04 Taxprep round trip

## Two exports prove what Taxprep holds (decision 0008, F4)

| Export | When | Proves |
|---|---|---|
| Lock export | after the preparer locks, uploaded with the printed return | the preparer's final values, traced cell by cell |
| Check export | just before transmit | nothing changed since the CPA approved |

More exports are added only if the Taxprep trial shows a need. The token and the gate details are settled on the Taxprep trial.

## Import and export

- **RT-1** An export that does not carry the latest import's token, or does not match the return's business number (IDENT.Ident7) and year end (IDENT.Ident121), or whose header GUID differs from the one recorded from the return's first export, is refused, with the reason. Taxprep itself checks nothing in the import file's header: the target return is the one picked in the import dialog, and a file naming another return is applied silently (trial, 1 Oct), so every identity check runs in our code, on the export.
- **RT-2** The token sits in a cell that is never sent to CRA. The trial found a candidate, IFirm.ContactPartner (an iFirm-side contact cell that takes imported text), but has not shown it is never transmitted; until CCH's own wording or support confirms a cell, the simulator uses a placeholder cell and the real import writes no token. If no safe cell is confirmed, the token is dropped and RT-1's staleness test runs on content instead: an export follows import N only if every cell that import N changed holds import N's value or is classed overridden with a reason (RT-14); otherwise it is refused as stale.
- **RT-3** The import file follows the shape Taxprep's own export writes (trial, release CCH iFirm 2026.20.198267): a header `[<return name>|0|0|<return GUID>],"Current Year","Last Year",""` (the GUID recorded from the return's first export, or all zeros before one exists); then one row per cell: the cell identifier unquoted, then this year's value, last year's value and a description, each in double quotes, the description left empty on import. Dates YYYY-MM-DD; yes or no cells `Y` or `N`; copies of repeating forms inside the identifier as `FORM[n]` (RT-21). The import ignores extra trailing columns and does not read the header (RT-1). CCH's help page (`[taxpayer name|return id|language]`) describes another shape and is not followed.
- **RT-4** The import writes input cells only, never calculated cells, and only facts a preparer has verified. Unverified facts wait. The writer refuses any identifier that is not on the release's input-cell list (RT-22), because Taxprep accepts text into a calculated cell without a word in its report (trial).
- **RT-5** The import file's name carries the client number, the year end and the version. Each import file is saved as a version; the first is the AI draft.
- **RT-6** (removed in v1.1 alignment, amber A30)
- **RT-7** Rows of repeating forms are matched by a natural key (CCA class, shareholder, slip issuer and so on), never by copy number: Taxprep renumbers copies after a delete, with no gaps (trial, Q21: class 8 moved from copy 2 to copy 1). The mapping table names the natural key of each repeating form and the cell that holds it (for CCA, `CCACat.FD08C[n].FED.Ttw08cA1`, the class number). Before an import writes to an existing copy, the copy holding each natural key is found from the latest export; a write whose target copy holds a different key is refused. Whether an import can add a new copy is settled on the Taxprep trial; until then new copies are added by hand in Taxprep and only then filled by import.
- **RT-8** Re-imports send only changed cells. A value to be removed is cleared by an import row with an empty value, written only for that cell, with the person and reason recorded (RT-12; trial, Q20: the report says "This cell has been emptied by the import"). The next export must show it gone; a cell still there is cleared by hand in Taxprep and checked the same way.
- **RT-9** Export and import settings are fixed and are Taxprep's defaults: comma separator, negatives as -123, period decimal, no thousands separator, Windows-1252 text, CRLF line ends on every line, every value in double quotes, no byte-order mark. The writer encodes Windows-1252 and refuses, with the row, any character outside it (a UTF-8 file imports without a warning but garbles accents: trial, Q24). The parser refuses any other format, and any file that looks re-saved by a spreadsheet program or another editor (a byte-order mark, LF-only lines, unquoted values, (123), thousands separators, scientific notation, UTF-8 byte sequences).
- **RT-10** The lock export and the check export also hold the calculated review lines (taxable income, each tax, balances, and every line the brief and review screens show). One saved filter holds them: a filter built with "Select all" (not "Select all input cells") exports calculated cells with their values in the same file (trial, Q22: Schedule 1 net income for tax, `FDONE.Ttwone66`). The export does not mark which cells are calculated; the release lists say so (RT-22). Which forms hold taxable income and each tax (the T2 jacket, Schedules 3 and 4 and the rest) is settled on the Taxprep trial.
- **RT-11** The printed return PDF uploaded with the lock export is the record of the full return and goes in the binder.
- **RT-12** An empty value, or a single space, in an import row clears the cell; "0" stores zero (trial, Q20; CCH's help says blank cells are not imported, and the trial showed otherwise). So the writer never writes an empty or blank value except a deliberate clear (RT-8), and a cell with no verified fact is left out of the file, never written blank.
- **RT-13** T2 year-start and year-end cells are ignored on import (CCH), and so are the cells synchronised from the iFirm contact while the import's "Exclude the values associated with the synchronized contact information" box is ticked, its default (the corporation's name `IDENT.Ident311` and others: trial, skipped with no report row). The writer leaves these cells out; they are set in Taxprep or iFirm by hand and checked by export. The box stays at its default.
- **RT-25** Amount cells take whole dollars only: a value with cents is refused for that row (trial). The mapping rounds each GIFI code to whole dollars, half away from zero, and puts the rounding difference that keeps Schedule 100 balanced on one line the mapping names (GIFI 3600, or the largest liability or equity line when there is none), shown in the trace as rounding.
- **RT-26** The import report is never proof of what was imported: it lists only cells that already held a value, gives no counts, and says nothing about cells it skips (trial). Only an export compared cell for cell with the import proves it (RT-14, dropped cells).

## Trace (after the lock export)

- **RT-14** Each cell in the lock export gets one class: traced (imported, unchanged); overridden (imported, then changed: needs a reason); dropped (imported, but blank or missing: blocks sign-off until re-imported or explained); rolled forward (not imported, and equal to the value last year's return facts give it through the roll-forward map, RT-24: registered as a fact sourced to last year); orphan (filled, not imported, not rolled forward, not calculated: needs a source); calculated (a review line, RT-10).
- **RT-15** Only cells on the allowed-typing list (Taxprep settings and e-file options) may be typed in Taxprep without a source. The list also holds the cells Taxprep fills when a return is created or from its iFirm contact (trial: `IDENT.Ident120`, `Ident121`, `Ident311`, `Ident230`, `Ident451`, `Ident492`, `IFirm.ContactPartner`); the year dates, name and business number among them are still checked against the return (RT-1, RT-13).
- **RT-16** The preparer sources each orphan, including every tax choice typed in Taxprep, with the cite button: a document box, a QBO line, an answer, or a written reason; the system may list sources that hold the exact value but never pre-selects one.
- **RT-17** Diagnostics are read from the printed return by iFirm category: an Error or Filing error blocks sign-off with no override; a Warning needs a named preparer's written reason, shown to the CPA in the brief; an Information or Filing warning may stay with a logged reason; a Hidden or Ignored diagnostic never counts as cleared; whether the printed return shows open diagnostics and their category, and the final list, are settled on the Taxprep trial.
- **RT-18** The preparer cannot sign off while any orphan, unexplained override or dropped cell remains, and the lock export at sign-off is saved as the preparer version.

## The check before transmit, and outside edits

- **RT-19** Just before transmit, ops uploads a check export, which must match the approval fingerprint (FLOW-4) cell for cell; a mismatch blocks transmit and sends the changed cells back to review (the gate details are settled on the Taxprep trial).
- **RT-20** Any change after lock means unlock, fix, re-lock and a new lock export, and an export that differs from the last recorded one with no recorded import in between is flagged "changed outside the trace". Two exports of the same filter and settings with nothing changed are byte-identical (trial), so equal bytes prove no change; unequal files are compared cell by cell.

## Mapping

- **RT-21** A mapping table links each figure key to a Taxprep cell identifier, for a named Taxprep release. It is the only Taxprep-specific part. Identifiers are Taxprep's internal ones, not box or line numbers: dot-separated parts, each a name with an optional copy index `[n]` (n from 1), for example `IDENT.Ident120` (line 060), `GFBGII[1].GFGIJ.Ttwgij104` (GIFI 8141), `GFGBA.Ttwgba64` (GIFI 1002), `FDONE.Ttwone5` (Schedule 1 line 124), `FDONE.SLIPA[n].TtwoneA2`, `CCACat.FD08C[n].FED.Ttw08cA1`. Each row also keeps, for people, the form's jump code, the line or GIFI code and Taxprep's description. The GIFI code of each GIFI cell is read from the description Taxprep exports ("GIFI code 8141 - Amount - ...").
- **RT-22** For each Taxprep release, the full list of input-cell identifiers is exported from a reference return (a saved filter with "Select all input cells" on every form lists every cell, empty or not), and a second list with "Select all" gives the calculated cells. A repeating form lists cells only for copies that exist, so the reference return holds at least one copy of each. The lists are compared with the last release; a removed or renamed identifier that the mapping uses blocks imports until it is remapped.
- **RT-23** In the build, a Taxprep simulator stands in for Taxprep. It follows what the Taxprep trial recorded (`reference/taxprep/FINDINGS.md`) and, where the trial is silent, CCH's published rules. It imitates the trial's quiet behaviour: a header it does not read, an import report that lists only cells that already held a value, cents refused per row in amount cells, text accepted into calculated cells and contact cells skipped with no report row, UTF-8 accents garbled, copies renumbered after a delete. It can inject faults: partial import, wrong client, reordered copies, a stale export, spreadsheet-mangled numbers, an edit outside the trace.
- **RT-24** The mapping table also names, for each cell Taxprep rolls forward, the cell of last year's return that feeds it (the roll-forward map, settled on the Taxprep trial); with no prior-year facts, no cell counts as rolled forward.
