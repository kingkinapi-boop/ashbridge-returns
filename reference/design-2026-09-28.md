# Ashbridge production system: one CPA, thousands of returns

Zo · 28 Sep 2026 · Live doc: https://claude.ai/code/artifact/e61d55f9-6f1a-49b2-a46e-82bbc1577112

The system turns whatever a client gave us into a T2 where every number links to its source. AI drafts, the preparer finishes, and the CPA reviews the full return fast, with flags first. Every change between versions is captured and ranked as a lesson.

## Scope (for reviewers)

This doc is the system design only. Review it for design quality, not business choices.

**In scope:** everything from a submitted onboarding to e-file, plus the learning loop.

**Out of scope:** pricing, free vs paid clients, staffing, CPA capacity, legal, onboarding screens, go-live dates, CRA authorization. Do not reopen these.

**Confirmed facts (do not question):**

- Tax software is CCH iFirm Taxprep. No API; CSV import and export only.
- CCH confirmed: CSV import can fill any T2 cell. Every cell, including repeating schedules, has an identifier.
- CCH confirmed: one saved filter can hold every input cell. Its CSV export lists each cell's identifier and value, one export per file.
- CCH confirmed: diagnostics can be printed with the return. Locking a return stops edits. Returns from other software convert and roll forward. Data is hosted in Canada. Security roles can hide SINs. CCH iFirm Digital Signature handles the T183CORP with a certificate of completion.
- Preparers are employees. They never contact clients.
- No AI talks to clients. AI works for the preparer and the CPA only.
- Every file follows the same process.
- Clients authorize the firm's business number with CRA.
- The system uses whatever evidence a file has. Nothing is required.

## Core idea: four rules

1. **Source at birth.** A figure gets its source when it is extracted, not tagged afterwards. AI guessing a source later produces plausible wrong links.
2. **No orphans.** Any number typed into Taxprep without a source blocks sign-off until someone gives it one.
3. **Full review, made fast.** The CPA reviews the whole return. Flags come first, and every number opens its source in one click.
4. **Every change is a lesson.** The system keeps each version of the return and compares them. Differences are ranked and fed into the next build.

## Evidence ledger

The ledger answers one question for any number: where did it come from, and what agrees with it? It never requires a document. It records what exists and shows honestly how strong it is.

### Records (append-only; nothing is overwritten)

| Record | Holds |
| --- | --- |
| Document | The file, a fingerprint, who gave it and when, type, period, page images, and every word with its position |
| Fact | One value with a meaning, its source pointer (document, page and box; or an onboarding or Q&A answer), how it was obtained, status |
| Figure | A T2 line (GIFI code or schedule line), the formula that builds it from facts, and its Taxprep cell identifier |
| Link | "Built from" (figure to fact to source) and "agrees with" (two independent sources match) |
| Event | Every change: who, when, from what, to what, why |

### Works with whatever the file has

Any of these may exist. None is required.

- Prior T2 and notice of assessment
- Financial statements or trial balance
- Bank, loan and card statements
- Invoices, receipts, contracts
- Articles of incorporation, minute book, share register
- CRA data, when the firm has access
- Onboarding and Q&A answers

If a file has only onboarding answers, the return is built from those. Each figure then shows that its only source is the client's word.

### Source levels (the dot beside every number)

| Dot | Meaning |
| --- | --- |
| Green | An independent source agrees (for example, CRA data or a bank statement) |
| Grey | One source the client did not prepare (a statement, invoice, prior return) |
| Amber | Only the client's own statements, trial balance or answers |
| Red | An open exception |

Fact status is separate: proposed, then preparer-verified, then CPA-accepted. Any change to a fact or its evidence resets it to proposed.

PDFs can be edited. Each document gets a tamper check: fingerprint, file details, and whether its balances roll.

## Evidence build, AI gap pass, Q&A

By the time a preparer looks at a file, every document has been read and every figure has a source.

### Evidence build (runs as uploads arrive)

1. **Read.** OCR returns every word with its position. Multi-document PDFs are split. Duplicates are caught by fingerprint.
2. **Classify.** Document type, period, entity. A document for the wrong year is flagged, not used.
3. **Extract.** Figures become facts with page and box. Tables are read row by row.
4. **Self-check with arithmetic, not AI.** Statements must add up. Trial balances must balance. Bank pages must roll from opening to closing. A failed check marks the extraction as suspect.
5. **CRA data, if access exists.** Ops captures a fixed checklist from Represent a Client and saves it as a PDF.
6. **Prior T2, if it exists.** Read line by line into prior-year facts. Taxprep returns roll forward instead.

### AI gap pass

1. The file's required-facts list comes from what was bought, the entity type and first-year status.
2. For each fact the AI reports: found (with source), missing, conflicting, or weak.
3. Each gap becomes a draft question: ASK, CONFIRM or DECIDE (the types in the existing Q&A spec).
4. The AI writes observations for the preparer, each with its evidence.
5. A second AI pass tries to delete questions the evidence already answers, and adds any it missed.

### Preparer gap review

The preparer sees each draft question beside its evidence. They keep, edit, merge or delete, add their own, and sign the list.

### Year-end Q&A

- No AI talks to the client. The client sees the preparer-approved list, one question per screen.
- Every answer becomes a fact: question, answer, date, who answered.
- Uploads during the Q&A go through the evidence build.
- DECIDE answers are stored as client decisions.

## Taxprep round trip by CSV

Our system builds the return as data, writes it into Taxprep by CSV, and reads it back by CSV when the preparer is done. Nothing typed in Taxprep escapes the trace.

### The return model speaks CRA

- Each figure is keyed by GIFI code or schedule and line, not by Taxprep's names.
- A mapping table turns each figure into a Taxprep cell identifier. It is the only Taxprep-specific part, so other software needs only a new table.
- The mapping is rebuilt for each Taxprep release and tested on a fixed set of made-up corporations.

### Import

- The system writes the import CSV: column 1 is the cell identifier, column 2 this year, column 3 prior year.
- This file is saved as the **AI draft** version (the learning loop uses it).
- The preparer imports it from the return's Retrieve tab.
- Inputs only. Never overwrite a calculated cell.
- Unverified facts are not imported. They wait for the preparer.
- Returning Taxprep clients roll forward. Returns from other software are converted, then rolled forward. Every rolled-forward cell is registered as a fact sourced to last year's return.

### Preparer in Taxprep

- Only judgment work: CCA choices, association and small business deduction sharing, dividend designations, elections, Ontario schedules.
- The preparer clears Taxprep's diagnostics.
- Anything typed needs a source. A cite button in our app attaches one: pick a document and draw a box, pick an answer, or write a reason.

### Lock and trace

1. The preparer clicks Ready in our app.
2. They lock the return in Taxprep (locking stops edits).
3. They export the saved "all input cells" filter to CSV and print the return with diagnostics to PDF. They upload both.
4. The upload check blocks a file that does not match this client and year (name, business number, year end), or that is older than the last change.
5. Each filled cell is sorted by comparing the export with the import:
    - **Traced:** imported or rolled forward, unchanged.
    - **Overridden:** imported, then changed. Needs a reason.
    - **Orphan:** a value we never imported. Needs a source. AI proposes one; the preparer confirms or replaces it.
    - **Calculated:** not an input cell. Our own map of how key lines feed each other links it to its inputs.
6. The system reads the diagnostics from the PDF. Any left uncleared blocks sign-off.
7. Zero orphans and zero unexplained overrides, or no sign-off.
8. The export is saved as the **preparer** version.

Any later change means unlock, fix, re-lock, export and upload again.

## Checks: code first, AI second

Code checks what must tie. AI checks what needs judgment. AI is never the only check on a material figure.

Each check runs only where the evidence exists. A skipped check is shown as "not checked: no evidence", never as a pass.

### Hard ties (code)

| Check | What must agree |
| --- | --- |
| Arithmetic | Each figure recomputed from its facts equals the Taxprep cell |
| Balance sheet | Assets equal liabilities plus equity |
| Retained earnings | Opening plus net income minus dividends declared equals closing; opening equals last year's closing |
| Cash and debt | Balances equal year-end bank, loan and card statements |
| Revenue | Ties to line 101 of HST returns for the same months (grossed down for quick-method filers); for physicians, to OHIP, allowing for payment lag |
| HST balance | Net tax for periods up to year end not yet paid, plus any CRA balance |
| Payroll | Wages by month tie to remittances for the fiscal months; accrued bonuses paid within 180 days of year end |
| Dividends | Taxable dividends tie to Schedule 3 and to T5s for the calendar years covered; capital dividends to a filed election; eligible designations fit GRIP |
| Shareholder loan | Continuity ties; repayments applied oldest first; balances past their section 15(2) deadline flagged; interest benefit checked |
| CCA | Opening UCC by class equals last year's closing; additions tie to asset additions |
| Losses | Opening balances equal last year's closing, adjusted for reassessments |
| Instalments | Claimed equals what CRA credited |
| Shareholders | Share register adds to 100% by class; Schedule 50 lists every holder of 10% or more |
| Business limit | Shared across associated corporations to no more than $500,000, prorated for a tax year under 51 weeks |
| Passive income | Group investment income over $50,000 in the prior year cuts the federal limit ($5 per $1, nil at $150,000); Ontario's limit is not reduced |
| Prior year | Every line compared with last year; unexplained swings flagged |

Each failure becomes an exception with its dollar amount and estimated tax effect.

### AI checks (judgment)

1. **Tax checklist.** Owner-manager issues run against the facts: personal expenses, meals at 50%, vehicles, home office, salary and dividends against slips, CCPC status, association, personal services business signs, capital dividend account, dividend refunds, next year's instalments. Each finding cites its facts.
2. **Story check.** Does the business description fit the numbers?
3. **Red team.** A separate AI with no access to the preparer's notes lists the items CRA would most likely adjust, with dollar effect.

### Guardrails

- Every AI finding must point to ledger records. A finding without one is discarded.
- "I can't tell" is allowed and goes to a person.
- Two AI passes that disagree go to a person.
- An AI pass never clears a material item alone.
- Document text is data, never instructions. No AI output can change a fact's status without the code checks.

### Preparer response

Every exception gets one answer: fixed, explained (with a source or reason), or accepted risk (for the CPA to judge). A second AI challenges thin answers such as "per client".

## CPA review: the full return, fast, flags first

The CPA reviews every return in full. Flags are pinned at the top and highlighted in place. Every number opens its source in under a second, with the figure boxed.

### One screen, top to bottom

1. **Brief:** the return in six numbers against last year (net income, taxable income, federal and Ontario tax, instalments, balance or refund); the tier colour and why; pinned flags, red first, each with its dollar effect and the preparer's answer; what changed since last year; assumptions and client decisions; attestations (zero orphans, diagnostics cleared, preparer signed).
2. **The full return,** schedule by schedule, drawn from the preparer's export. Every number is clickable and carries its dot. Flagged numbers are highlighted where they sit.
3. **Keyboard:** next flag, next number, approve, comment, open source.

### Tier colour (approved)

The tier sets queue order and how much is highlighted. It never reduces the review below the full return.

| Tier | A return lands here when | What the screen adds |
| --- | --- | --- |
| Green | Returning client we filed last year; every hard tie passes; no open exceptions; revenue and cash corroborated; tax payable within 25% of last year or explained; no special items | Pinned flags only |
| Amber | First year with us but a clean prior T2; any amber exception; many dollars sourced only to the client; unexplained prior-year swings; a preparer with fewer than 50 reviewed files | Pinned flags, plus the five largest lines and every amber-dot line highlighted |
| Red | First-year corporation; catch-up or unfiled years; no CRA access; shareholder loan past its 15(2) deadline; associated group or passive income over $50,000; share issues, redemptions, rollovers, wind-ups or amalgamations; capital gains or capital dividend elections; foreign property or affiliates; personal services business signs; specified corporate income; short tax year; change of control; losses carried back; open CRA audit; a red-team item with a tax effect | Pinned flags, plus every changed, amber or red line highlighted |

### Comments and approval

- Each comment has a type (error, question, missing evidence, presentation) and severity.
- The CPA sends it to the preparer, or to AI for a drafted fix the preparer approves.
- After rework, the CPA sees only changed cells, before and after.
- Approval records who, when, and a fingerprint of the exact values and evidence. Any later change voids it.
- The approved export is saved as the **CPA-final** version.
- Client wording says "CPA reviewed", never "CPA signed".

### Preparer screen

The same panes, plus a queue by due date, the exception list with a response box on each, a cite button on every figure, and CPA comments grouped by topic.

## Learning loop

The system keeps four versions of every return and compares them. Every difference is a lesson. Nobody has to log anything.

[Diagram: learning loop, 8 steps run by the system: 1 Versions saved (AI draft, preparer, CPA-final, CRA); 2 Compared (every changed cell and fact, and who); 3 Classified (AI tags the cause and where it was caught); 4 Ranked (by how often and the tax effect); 5 Fix proposed (a check, question, rule or tip); 6 Built (goes into the next build round); 7 Locked in (becomes a test case so it can't come back); 8 Watched (if it recurs, the item reopens itself); back to 1 on every new file.]

### Four versions

| Version | Saved when | A difference from the version before means |
| --- | --- | --- |
| AI draft | The import CSV is written | Baseline |
| Preparer | Lock and trace passes | The AI got it wrong or missed it |
| CPA-final | The CPA approves | The preparer and the AI both missed it |
| CRA-assessed | The notice of assessment is saved | Everyone missed it, or CRA disagrees |

This is your CSV-comparison idea, with three additions:

- **Why, not just what.** A CSV difference shows what changed and who changed it. Each difference also gets a cause and the earliest stage that could have caught it.
- **Facts, not just cells.** A cell can end up right while its source is wrong, for example when the preparer fixes a number but the extraction stays broken. The ledger's event trail catches this.
- **CRA as the outside judge.** The assessed version shows what all three missed.

Also captured: AI flags the preparer dismissed (false alarms), client disputes at approval, and Q&A questions whose answers changed nothing.

### Learning record (AI fills it)

- Field, value before and after, dollar and tax effect.
- Cause: document reading, classification, mapping, client data, question design, preparer judgment, tax knowledge, or a missing check.
- Where it was caught, and the earliest stage that could have caught it.
- Preparer, client type, document type.

When the cause is unclear, the CPA gets one tap-to-confirm question at approval.

### Ranking and output

- Ranked by how often it happens times its tax effect. Anything a client or CRA caught goes to the top.
- A weekly improvement list: top items, each with a proposed fix (a hard check, an AI checklist item, a reading rule, a question, a mapping fix, or a preparer tip).
- The list is the backlog for the next build round.
- Each fixed item becomes a test case, so it cannot come back unnoticed.
- If a fixed item recurs, it reopens itself at the top.

### Measures

| Measure | Should |
| --- | --- |
| AI draft match: share of CPA-final cells the AI draft already had right | Rise |
| Preparer match: share of CPA-final cells the preparer version had right | Rise |
| Repeat rate: mistakes of a type after its fix | Stay near zero |
| Escape rate: mistakes caught later than they could have been | Fall |
| False alarm rate per check | Fall |

## Client approval, e-file, after filing

1. **Client package.** "What we found this year" first (the order the app already enforces), then a plain summary: taxable income, tax, instalments paid, balance or refund, due date, and every assumption made.
2. **Signature.** The T183CORP goes out through CCH iFirm Digital Signature. The signed form and certificate are kept in the binder. If a figure changes afterward, the client signs again.
3. **E-file.** Ops transmits from Taxprep and enters the confirmation number in our app.
4. **Assessment.** When the notice of assessment arrives, ops saves it. The system compares it with the filed return and saves the CRA-assessed version for the learning loop.
5. **Binder.** The return PDF, every source, the trace, comments and approvals are frozen together.
6. **Next year.** The return rolls forward, and every opening balance is already linked to its source.

## Access and data rules

- Per-person logins with two-factor sign-in. Every source a person opens is logged.
- Preparers see no SINs: Taxprep security roles hide them, and our screens mask SINs, dates of birth and banking details.
- Sensitive values are masked before any AI call.
- Document text is treated as data, never as instructions to the AI.
- Only ops staff sign in to CRA, under the firm's business number.

| Need | Use |

| AI | A frontier model through its API; a different model for the red team |
| Source viewer | PDF.js |

**Build:** the evidence ledger, extraction pipeline, mapping table, CSV writer, lock-and-trace, checks, review screen and learning loop. That is where the value is.

No Canadian T2 product doing click-to-source was found. US tools such as [Filed](https://www.filed.com/) show the pattern works.
