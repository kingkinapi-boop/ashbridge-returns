# Staff UX patterns for the T2 review system
Research of 29 Sep 2026 for the Lead. Labels: [fact KEY] = read that day; KEY is a full URL or a base plus path listed under Sources. [inference] = my reading of facts. [guess] = no evidence found.
Vendor pages are marketing: their numbers are claims, not tests. Dates are given for anything older than 2024; newer sources were used where they exist. I also read blueprint/06-screens.md, .claude/rules/staff-screens.md and reference/design-basis.md, so nothing here repeats them.

## 1. Answer in brief
Verdict: keep GOV.UK and MOJ as the base layer (page frame, tokens, forms, errors, tags, task list, alert, timeline, short tables). Build three surfaces from our own app- parts on the same tokens:
the three-pane CPA review with source viewer, the preparer queue, and dense tables. None of the GOV.UK, MOJ, DWP, HMRC or Home Office lists has a pattern for them, and the best tax and review tools do not look like question pages.
RV-52 already allows this. [inference from sections 2, 3, 5]
The three patterns that matter most:
1. A number opens its source in one key, in a synced view, already fetched (TaxCycle F6 and DoxCycle follow mode; Juno boxes; Fieldguide highlights; Superhuman preloads). Aim well inside NN/g's 1 s limit.
2. Explicit review state per item, with progress, who and when, that resets when the number changes (GitHub Viewed; TaxCycle first and second review marks; DoxCycle blue and green ticks), plus typed comments back to the preparer.
3. Ordered by need, never hidden: mandatory before advisory (Taxprep), low confidence first (Juno), Enter to the next unresolved field (Rossum), triage keys (Linear). Tiers matter because people ignore flat alert lists (AHRQ).
Plan points worth a look, all [inference]:
- RV-5 says reviewed once the CPA "moves past" a section. If that means scrolling, it is weaker than the explicit mark every tool below uses (a clause change is red).
- MOJ sortable table sorts one page only. The identity bar must stay a quiet reference strip (DWP retired a similar bar, its Key details bar, for banner blindness).
- MOJ Frontend 12.0.0-beta.1 (29 Sep) stops configuring GOV.UK Frontend, so pin 11.x. A GOV.UK table row is about 46 px, so dense screens need a modifier.

## 2. Government guidance on staff and caseworking tools
- [fact https://www.gov.uk/service-manual/design/services-for-government-users] Civil servants are users too; same standards. "A user of an admin system might need to repeat and switch between tasks quickly", so one thing per page might not suit all pages. Test with people who do the real tasks, on realistic data.
- [fact https://designnotes.blog.gov.uk/2015/09/25/design-principles-for-admin-interfaces/] The nearest statement on who patterns were shaped for: "Our patterns are mainly optimised for the public, who don't use government services all that often."
  Admin users are in the tool all day: more than one thing per page, full browser width. It dates from 2015; no 2025 or 2026 page repeats or reverses it. The Design System home says it is "for everyone that works on government services" and names no research audience [fact GOVUK home, patterns/].
- [fact GOVUK patterns/question-pages/, components/radios/] Grouping questions is fine for "an internal service for government users who need to repeat and switch between tasks quickly"; "Small radios can work well on information dense screens in services designed for repeat use, like caseworking systems."
- [fact DWP get-started/internal-systems, get-started/data-interfaces, research/data-interfaces/workshop (Mar 2024)] DWP questions one thing per page for experts but says not to drop user-centred standards.
  Showing database rows with buttons is "lazy"; move from data to information to actionable information; put task context inside the task; summaries first, detail on demand.
- [fact DWP components/key-details-bar, components/quick-reference, components/quick-reference/user-research] DWP retired its Key details bar in Sep 2024 for Quick reference, which is less prone to "banner blindness" and is "a place for background information rather than a way to make something prominent". Its research came from agent services only (updated 4 Aug 2025).
- [fact https://design.homeoffice.gov.uk/design-system/get-started, DWP service-type/internal, HMRC hmrc-design-patterns/internal-header/ and caseworker-guidance-banner] Home Office: internal services cannot use the crown or Transport. DWP internal header and footer carry no GOV.UK branding. HMRC's internal header keeps the HMRC logo.
  HMRC's caseworker banner says "avoid overuse" and "we need more research". The Home Office (https://design.homeoffice.gov.uk/design-system/patterns) and HMRC (HMRC hmrc-design-patterns/) pattern lists have nothing for split views, document viewing, tables or keyboard use.
- [fact https://designnotes.blog.gov.uk/2022/03/21/going-beyond-the-gov-uk-design-system-for-moj-forms-professional-users/] MoJ Forms (Mar 2022) added inline editing, hierarchical menus and modals for professional repeat users: "our tool has to be fast"; testing found no problems.
  MoJ runs a professional action group and a cross-government Designing Caseworking Systems meetup (its Medium notes returned 403, unread). [fact https://designnotes.blog.gov.uk/2019/02/14/how-the-gov-uk-design-system-can-work-alongside-other-government-design-resources/] Departments publish what GOV.UK lacks, such as headers, footers and type for internal services.
- [fact https://amyhupe.co.uk/articles/why-you-dont-need-a-separate-design-system-for-internal-services/] (2020) Accept heavier screens on first use for a faster return visit.

## 4. Expert users, tables, split views
- [fact NNG complex-application-design (Nov 2020)] Users plateau at "mediocre performance", so teach faster methods in context; allow non-linear paths; keep secondary information reachable without leaving the primary screen; cut clutter by staged disclosure; make key items salient.
  [fact NNG ui-accelerators (Oct 2024)] Add accelerators for repeated tasks, show them in menus and hints, never require them, do not override common keys.
- [fact NNG data-tables (2022)] Human-readable first column; freeze header rows and columns; row detail in a nonmodal panel, not a modal, so the table stays visible; batch actions by checkbox with select all; one or two inline actions, the rest in a menu.
- [fact NNG wizards (2017)] Wizards suit rare tasks and turn "annoying and overly controlling" when repeated; give repeat users a faster route.
  [fact NNG content-dispersion (Oct 2023, 13 tests)] Stretched mobile-first layouts on desktop raise load and cost, and accordions fragment; keep related content in one viewport [inference: the same holds for staff screens].
- [fact NNG response-times-3-important-limits (1993)] 0.1 s feels instant, 1 s keeps thought flowing, 10 s loses attention: the base for "source in under 1 s".
  [fact https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/list-details] List and details side by side from 641 px wide, stacked below, for back-and-forth work.
- [fact NNG intranet-usability-the-trillion-dollar-question (2002, old)] Loss scales with staff times tasks: $3,042 a year per employee at worst against $1,563 at best, on 16 tasks.

## 5. Pattern catalogue (reference products, what to copy, what to avoid)
### A. CPA full-return review with source viewer (RV-1 to RV-9)
- TaxCycle with DoxCycle (https://www.taxcycle.com/resources/help-topics/review-tools/review-sidebar/) [fact; I also viewed its screenshots]:
  F9 opens the review sidebar at the first message; its filter shows counts ("Require attention (36)", "Unreviewed overrides (1)", "Questions (5)", "Corrections (2)"); marks are question, correction, first and second review (Ctrl+6 to Ctrl+9); hover shows who and when; a History log lists each event.
  A blue triangle marks a field that has a source; F6 or double-click jumps to it; several sources give a drop-down; right-click "Prior year" opens the same field last year (TC preparation-tools/forms-and-fields/jump-links-and-drill-down-f6/).
  DoxCycle (TC doxcycle/link-documents/jump-between-doxcycle-and-taxcycle/): a Link button makes the document and the form follow each other; F11 opens a slip's document; blue then green ticks for first then second review of each document, with a filter for those still pending (TC doxcycle/doxcycle-review-tools/review-check-marks/).
  Taxprep Review Mode is the same idea (https://www.taxprep.com/assistance/TF/2019/v50/en-ca/Content/Review%20Tools/Review_mode.htm) [fact]: Ctrl+0 turns the cursor into a mark tool, a click marks a cell, a double-click opens the source form; marks are first review, second review, error, uncertainty, other (Ctrl+1 to Ctrl+5; https://www.taxprep.com/assistance/T1/2018/v32/en-ca/Content/Review%20Tools/ReviewMark.htm). These are the personal and trust edition pages; T2 is likely the same [inference].
- GitHub pull request review (https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/reviewing-proposed-changes-in-a-pull-request) [fact]: "Viewed" collapses a file and feeds a header progress bar; "If the file changes after you view the file, it will be unmarked as viewed"; the end is Comment, Approve or Request changes with a summary.
  The Jan 2026 update adds a resizable file tree with markers for comments, errors and warnings (https://github.blog/changelog/2026-01-22-improved-pull-request-files-changed-page-on-by-default/).
- SPbinder (https://tax.thomsonreuters.com/en/products/spbinder/features) [fact]: index in the order of the return; hyperlinked cross-references between figures on any file type; a leadsheet with cross-referenced sources, change tracking and variance detection; threaded notes.
- CaseWare Working Papers (https://documentation.caseware.com/2022/WorkingPapers/en/Content/Engagements/Review-Signoff/Annotation/About-Annotation.htm) [fact]: tickmarks show who and when; a global reference shows on the account and on every document that uses it (fits "one figure, one string everywhere").
- Copy: a link marker on every number; multi-source drop-down; same-line-last-year jump on the same key; counts on every filter; "unreviewed overrides" as its own list; who and when on every mark; comments typed on the number itself (question or correction) that the preparer clears at that number (TaxCycle: click the field's check mark to resolve, https://www.taxcycle.com/resources/help-topics/review-tools/review-marks/); explicit Viewed with progress that resets on change (fits RV-7 and the approval-void state); a file-tree style coverage list with markers.
  Taxprep and TaxCycle both have first and second review marks: one CPA today, but keep the data model open to a second level [inference].
- Avoid: sign-offs that stay when numbers change (CCH Axcess Engagement: "the sign-offs remain in place", https://help-engagement.cchaxcess.com/FinPrep/Content/Workpapers/Sign-off-workpaper.htm) [fact]; thousands of messages (TaxCycle ships "5000+ Review Messages", https://www.taxcycle.com/features/review-tools/) [fact; the risk is inference];
  a modal over the return (NNG data-tables); exception-only review as the default, since RV-8 keeps the full return.

### B. Preparer workbench (RV-20 to RV-25)
- Tax software diagnostics: Taxprep (https://www.taxprep.com/assistance/T2/2025/v20/en-ca/Content/Review%20Tools/DiagClass.htm) [fact]: nine classes; mandatory modification, missing information and error must be acted on, the rest are advisory. Tabs Take Action, My Diagnostics, All; double-click goes to the cell; mark Reviewed or Ignored (Taxprep T1/2018/v30 DiagAbout.htm).
  UltraTax CS (https://www.thomsonreuters.com/en-us/help/ultratax-cs/miscellaneous/review-tools-and-features) [fact]: blue chevrons where last year had a value and this year has none; red chevrons where a person overrode a transferred value, with acknowledge or restore.
  TaxCycle: "Critical messages cannot be signed off"; a Quick Fix light bulb offers the likely answers as one click (sidebar page and screenshot).
- Validation screens: Juno (https://juno.tax/blog/how-ai-tax-preparation-works, Mar 2026) [fact, vendor]: source PDF beside each extracted field, confidence per field, "Low-confidence reads are surfaced first".
  Rossum (https://knowledge-base.rossum.ai/docs/keyboard-shortcuts) [fact]: Tab to the next field, Enter to the next unreviewed field; the box turns green only after a person validates (https://updates.rossum.ai/en/a-new-validation-screen-for-a-more-intuitive-experience).
- Linear (https://linear.app/docs/triage) [fact]: keys 1 accept, 2 decline, 3 duplicate, H snooze; Space peeks and arrows step (linear.app/docs/peek); X selects, Shift+arrows extend, Cmd/Ctrl+K lists every action (linear.app/docs/select-issues).
- Karbon (https://karbonhq.com/resources/karbon-work-dashboards/) [fact, vendor]: "My Work" is an assignee filter sorted by due date; "Waiting on Client" is a list, not a board, for more visible detail; saved views.
- Copy: due date first with named saved views; "waiting on" states with an owner; mandatory and advisory tiers; missing-versus-last-year and override markers with restore; one-click likely answers; a next-unresolved key; keys printed on screen.
  Judgment inputs: GOV.UK inputs, small radios, MOJ add another, several inputs on one page (allowed for staff, see section 2).
- Avoid: one flat list where every flag looks alike (https://psnet.ahrq.gov/primer/alert-fatigue) [fact]: clinicians override the "vast majority" of warnings; tiers, role tailoring and interrupting only for severe ones help. A kanban board as the preparer's main view, and pagination of a small queue [inference].

### C. Ops checklists (RV-30, RV-21)
- GOV.UK task list (https://design-system.service.gov.uk/patterns/complete-multiple-tasks/) [fact]: statuses Completed, Incomplete, In progress, "Cannot start yet" (grey, not a link), "There is a problem"; "The more you add, the harder it is for users to remember them"; made for long public transactions, silent on staff repeat use.
- Karbon template (https://karbonhq.com/templates/self-assessment-tax-return/) [fact, vendor]: sections Kick-off, Client tasks, Production, Review and File; roles Client Manager, Preparer, Reviewer, Client; automators reassign work and move it on when a section completes.
- CCH Axcess Engagement and CaseWare sign-off (CCH link above; https://documentation.caseware.com/2022/WorkingPapers/en/Content/Engagements/Review-Signoff/Roles/Sign-Off-Document.htm) [fact]: preparer signs before reviewer; only the signer can remove a sign-off; a colour shows the role that signed; a role set can make a document read-only after sign-off.
- TaxDome pipelines [unverified: help pages returned 403, search snippet only]: kanban of job cards moving through stages that run automated actions.
- Copy: fixed order with "cannot start yet" and the reason; automatic hand-off when the last step lands; who and when on each step; one upload per step; what is left, as links.
  Avoid: a step that can be ticked without its evidence (the plan already ties steps to uploads); free order, which the task list prefers but RV-21 cannot allow.

### D. Owner pipeline (RV-40)
- Karbon dashboards (https://karbonhq.com/resources/12-work-dashboards-to-create-in-karbon-for-complete-clarity/) [fact, vendor]: views are filters, sort and saved views: a bottleneck view by status (many items in Prep means Review is next), "Waiting On Us", "Waiting on Client" as a list, weekly capacity (due this week or overdue, by assignee), ready to bill.
- Kanban Guide (https://kanbanguides.org/english/) [fact]: WIP, throughput, work item age ("elapsed time between when a work item started and the current date") and cycle time; limit WIP; make policies explicit.
- MOJ numeric data and case list (MOJ components/numeric-data/, pages/case-list/) [fact]: numeric data is Experimental, one figure with a label of at most 20 characters, no trend; the case list wants few columns and search before the table.
- TaxDome kanban [unverified, as above].
- Copy: a strip of four to six numbers (open, due in 7 days, waiting on us, waiting on client, blocked), each linking to its filtered list; a table by state in lifecycle order with due-date bands and the age of the oldest return; saved views.
  Avoid: averages that hide one stuck return (show age per item) [inference]; drag and drop between states (WCAG 2.5.7); any chart without its table.

- DoxCycle (https://www.taxcycle.com/products/doxcycle/) [fact; screenshot viewed]: index tree by person and section with review icons; pages stacked, each under a strip with type, taxpayer and tick; extracted fields at the right with a tick each and a Post button; a status bar with page and review counts; synced with the return.

Superhuman (https://blog.superhuman.com/superhuman-is-built-for-speed/) [fact]: under 100 ms, aims under 50 ms, local store, preloads threads likely to be opened.

## 6. AI-native tax and accounting products (2025 to 2026): what their review screens do
- Ready to Review, Thomson Reuters (https://tax.thomsonreuters.com/en/products/ready-to-review; blog https://tax.thomsonreuters.com/blog/ai-tax-return-preparation-how-ready-to-review-transforms-the-workflow/, 19 Dec 2025) [fact]: 1040 returns, W-2 income and prior-year returns first; agents read source documents and last year's return, fill the return, run the tax engine.
  The reviewer gets "verification links back to the source documents", "two-year comparisons", "categorized diagnostics" and flagged outliers; a person signs before delivery and e-file.
- Black Ore Tax Autopilot (https://www.cpapracticeadvisor.com/2026/04/29/black-ore-launches-tax-autopilot-for-broad-availability/182311/) [fact, launch news]: "links each data point back to source documents, and flags items requiring attention"; workpapers; "Firm professionals remain the final authority for sign-off".
- Juno Reviewer (https://juno.tax/product/reviewer) [fact, vendor]: compares source documents to return fields and flags mismatches; click a flag for "side-by-side fields, bounding boxes, and context"; assign fields to teammates, mark reviewed, track progress; year over year "without re-checking every line".
- Fieldguide (https://www.fieldguide.com/products/agents/overview): a reviewer agent "confirms every conclusion traces to its evidence". Basis (https://www.cpapracticeadvisor.com/2026/02/24/basis-raises-100-million-to-deploy-ai-agents-for-accounting-firms/178759/) and Numeric (https://www.numeric.io/product/ai-in-numeric): agents work for hours or draft rules, then return work "for review";
  approve a rule once and like records follow. Neither page shows the review screen. Accrual: "The CPA reviews exceptions and signs off" (third-party blog https://crossing.one/blog/accrual-ai-tax-prep-automation-accounting-firms-2026). Filed's comparison (https://www.filed.com/blog/best-ai-tax-prep-platforms, vendor): "none of these numbers has been independently benchmarked".
- Confidence: I found no source that tests which display works best for reviewers [not found]. Juno shows a score per field and sorts by it; Hyperscience asks a person only where the model is below the accuracy target and will "take you directly to the field that it needs assistance with"
  (https://www.hyperscience.ai/resource/introducing-human-centered-automation/; keys listed in the UI: https://www.hyperscience.ai/resource/demo-hyperscience-platform/); Rossum uses box colour. [guess] A word plus a non-colour cue, not a percentage, fits rule 7.
- Oversight evidence: [fact NNG explainable-ai (12 Dec 2025)] people rarely click citations, and some are invented. [fact https://arxiv.org/abs/2006.14779] Explanations raised acceptance of AI advice "regardless of its correctness". [fact https://www.eecs.harvard.edu/~kgajos/papers/2021/bucinca2021trust.shtml] Forcing steps cut overreliance, but people rated those designs lowest.
  [fact https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/] Intent preview, confidence signal, action audit and escalation are its named patterns. [fact https://www.ledge.co/content/checklist-review-ai-accounting-work (vendor)] Separate manual inputs from system output; corrections made in review must show in the audit trail.
  [inference] This backs the plan: code checks citations, the approval record stores sources opened, AI never approves.

## 7. Anti-patterns (what makes internal tools painful)
- Database rows with buttons: "Don't do this. It's lazy." [fact DWP get-started/data-interfaces]. Everything flagged [fact AHRQ]: over 100 alerts a day in one setting; the fix is tiers and interrupting only for severe ones.
- Sign-off that survives a change [fact CCH link in 5A; GitHub resets it]. Sort or select that stops at the page edge [fact MOJ sortable-table/, multi-select/]. One thing per page for repeaters [fact Service Manual, NNG wizards].
- Hidden or dispersed content: [fact GOVUK components/tabs/] tabs hide content and fail when readers must go in order or the page is slow; [fact NNG content-dispersion] accordions fragment.
- Low-contrast helper text: [fact DWP components/timeline/design-notes] "agents with lower quality screens" could not read GOV.UK secondary-colour text. [inference] Keep the plan's #627283 grey off anything the CPA must read.
- A bar that is always there becomes wallpaper (banner blindness) [fact DWP components/key-details-bar].
- Slowness [fact NNG response-times]; commenters say focus drifts at 3 to 5 s (https://news.ycombinator.com/item?id=36739565, low grade). Buyer is not the user, no test in real conditions, pagination costing 50+ clicks (https://news.ycombinator.com/item?id=21224209, commenters, low grade).
- Decay [fact https://vercel.com/blog/stopping-the-slow-death-of-internal-tools, 27 Dec 2025]: tools rot when upkeep needs "tribal knowledge" and updates stop when processes change. [inference] The plan's data-before-code and one-test-per-rule habits answer this.

## 8. Verdict: where GOV.UK and MOJ fit and where they hurt
Fit well, use as they are:
- Forms, inputs, small radios, error summary, summary list, tags, inset text, details, file upload, confirm an action, alert, task list, and numeric table cells (the table styles set tabular figures [fact https://raw.githubusercontent.com/alphagov/govuk-frontend/main/packages/govuk-frontend/src/govuk/components/table/_mixin.scss]).
  Reason: tested, accessible, one look with the client app; the Service Manual holds internal services to the same standards, and MOJ Frontend is built to sit on GOV.UK Frontend [fact releases page].
- Page frame and tokens (header with our logo, service navigation, spacing, type, focus, functional colours). Reason: WCAG 2.2 AA and one look for free; three departments brand internal services their own way, so no crown is normal (section 2).
- Short lists (queue, ops list, lessons) as MOJ sortable table plus filter plus case list pattern, sorted in the browser over the whole list, no pagination. Reason: the section 3 limits do not bite under a few hundred rows [inference].
- Timeline for comments and audit trail (dark text, per the DWP contrast finding); button menu for actions; identity bar as a quiet strip naming the return; pagination only if a list outgrows a screen.
Hurt, so compose app- parts on the same tokens and write the reason in the design notes (RV-52 allows it):
- Three-pane review and source viewer: no such pattern in GOV.UK, MOJ, DWP, HMRC or Home Office; the best tools use synced panes, keys and marks (5A, 5E).
- Dense tables: a GOV.UK cell is 19 px type (25 px line) with 10 px top and bottom padding, so about 46 px a row [fact table _mixin.scss, GOVUK styles/type-scale/, styles/spacing/; the sum is inference]. Type steps stop at 16 px.
  The table has no sort, sticky header or dense mode and says to split big data across tables or pages [fact GOVUK components/table/], the opposite of one return read in order. Add an app- dense modifier and sticky headers (NNG data-tables); 16 px type with 5 px padding would give about 31 px rows [guess].
- Filtering and selection: reload, "Apply" at the top, first page only [fact MOJ]. The queue needs inline filters, saved views and keyboard select.
- Keyboard layer, peek, resizable panes: nothing exists; build to WCAG 2.1.4 as rule 10 says. GitHub lets people turn single-key shortcuts off [fact https://docs.github.com/en/get-started/accessibility/keyboard-shortcuts].
- Side navigation as the coverage tracker: h4 headings and sideways scroll [fact MOJ side-navigation/]; fix in src/ui. Notification badge: MOJ says accessible with its header, not the GOV.UK header; ours is neither, so test it.
- Public-user rules that suit review sections but need care elsewhere: no tabs, no accordions, no disabled buttons (rules 8, 14). Keep them for return sections; allow `details` for secondary trace notes, since NN/g advises staged disclosure [inference].
