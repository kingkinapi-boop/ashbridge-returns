# Agentic build practices, 2026: what works, what fails, what to change
Scout research for the Lead, 29 Sep 2026. Reference, not authority: the blueprint and decisions/ win. Anything that costs money or changes a clause is red for Zo. Companion file: reference/research/2026-09-29-claude-code-facts.md.
Labels: [fact Xn] = the page listed as Xn under Sources says so (URL and date there; A = Anthropic, C = everyone else). [inference] = my reading for this build. [guess] = unverified.
Limits: Reddit is blocked to my tools, so Hacker News, blogs and papers stand in. Opus 5.5 (22 Sep) and Sonnet 5.5 (28 Sep) are days old: only Anthropic and launch-partner numbers exist, no independent field reports yet. I ran no code and read no secret.
Already in this repo (reference/build-practices.md, lessons-deep.md, .claude/agents, hooks): tests by another agent, read-only acceptance tests, planted faults, mutation plan, Stop-hook gate, JSON status, skip Spec Kit, skip agent teams. "Keep" below means that; the words go to what is new.

## Five findings that matter most
1. Verification, not generation, is the bottleneck. Frontier agents saturate visible tests yet fail held-out ones, and the gap grows 28 points per tenfold code size [C28]; agent commits add mocks 36% of the time vs 26% [C31]; review capacity caps throughput [C32][C11]. Spend on held-out tests, mutation testing, calibrated checkers and small diffs before spending on more builders.
2. Keep parallelism small and integrate through a train. Anthropic says start with 3 to 5 [A5]; Google finds multi-agent lowers sequential-task results 39 to 70% and independent agents amplify errors 17.2x vs 4.4x when centralized [C14]; Cursor's 20 agents behind a lock acted like 2 or 3 [C13]; one Gas Town trial cost about $100 for an hour and every PR was closed [C17].
3. Model drift is silent and this build is exposed. Agent files use aliases (opus, sonnet, haiku) that "update over time", and a safety classifier can re-run a request on an older model mid-session [A10]; Haiku 5.5 is due within weeks [A15]; Anthropic's 2025 postmortem shows three bugs degraded Claude for weeks and its own evals did not catch them [A26]. Pin full IDs, log the model per job, run a weekly canary set.
4. Weekly self-improvement should be a ratchet on tests and hooks, not more prose. When an issue recurs, improve the controls [C4][C12]; measure first-pass acceptance, rounds per card and post-merge rework, not volume [C5]. Always-loaded text stays short: a 2026 study found context files did not raise success and cost over 20% more [C26]; Anthropic says under 200 lines [A9].
5. "Robotic" is a taste and evaluation problem. Anthropic's design harness needed an evaluator scored on design quality, originality, craft and functionality, tuned on scored examples, and it still missed unintuitive interactions [A17]; synthetic users are too agreeable [C36]. Keep Zo's approved designs first, real staff on made-up data at each gate, agents only as a pre-screen.

## (a) Ranked practices (rank = value to this system; verdict = ADOPT, ADAPT or SKIP)
### Trust in "done"
1. ADAPT (pull forward) held-out tests: the spec-writer keeps 1 to 3 composed-scenario tests the builder never sees; only the checker and train run them. [fact C28] visible suites saturate while held-out ones fail; one agent shipped a 2,900-line "compiler" that memorised test inputs. Repo has this as ADOPT LATER (1.5): do it now for money and tax cards.
2. ADOPT (keep) evidence, not claims: reports carry the command and its output, and the checker re-runs it. [fact A1] "show evidence rather than asserting success". [fact A18] "it is easy to see tests pass and assume the job is done, when this is rarely the case". [fact C17] a Gas Town PR merged with failing integration tests. Tests-first stays [fact C10]. Add: the merge tool refuses a card with no report file and commit hash. [inference]
3. ADOPT (keep) mutation testing (plant small bugs, see whether tests notice) on money, tax, CSV and citation code, and feed survivors back. [fact C6] Radar v34 names it a feedback control for "self-correction before human review". [fact C29] a pilot lifted mutation strength from 51 to 81% up to 87 to 100% by having the agent write tests that kill survivors, and warns "do not game the score". A survivor becomes a spec-writer task, never a builder edit.
4. ADAPT a test-theatre sensor per card: mocks of our own modules, tests changed after the spec commit, tests with no outcome assertion, new skip or todo. [fact C31] over 1.2M commits, agent commits change tests 23% of the time vs 13% and add mocks 36% vs 26%. [fact C8] Beck watched for the AI "disabling or deleting tests". REVIEWER.md samples 5 tests by hand: automate the count.
5. ADOPT (new) a calibration set for the checker and the Reviewer: 10 to 20 seeded-defect branches (weakened test, wrong rounding, uncited box, clause with no card, unreachable screen state) they must catch weekly and after any model change. [fact A19] start with 20 to 50 tasks from real failures, read transcripts, keep capability and regression sets apart. [fact A17] an LLM grader is "inclined to be generous" to LLM output and needed "several rounds" of tuning on scored examples.
6. ADAPT the Reviewer and checker prompts: report only gaps that affect correctness or a cited clause, ranked, at most ten. [fact A1] "A reviewer prompted to find gaps will usually report some, even when the work is sound"; chasing all of them breeds over-engineering.
### Parallel work and integration
7. ADAPT the worker caps. Normal's 2 is fine. Turbo's max_workers of 12 (up to 20; 6 to 12 cloud plus 4 to 6 local, modes skill) is well past the 3 to 5 below (12 is 2 to 4 times that) and at or above one expert's 10 to 15 sessions, so start turbo at 6 and add 2 at a time only while first-pass acceptance, green-train rate and unreviewed-train count hold; treat 12 as the ceiling, 20 has no evidence behind it. [fact A5] "Start with 3-5"; "three focused teammates often outperform five scattered ones". [fact C11] work in progress limit = review capacity. [fact C25] Cherny runs 5 local plus 5 to 10 web sessions and abandons 10 to 20%. [fact C35] HN practitioners report 2 to 6. The modes skill already brakes on merge conflicts (line 45); add the other two brakes. [inference]
8. ADAPT a bisect fallback for red trains. The merge skill removes the card that owns the named failing module (merge skill, line 27), which does not help when two cards interact. Then halve the boarded cards, re-run, land the green half, and serialise the interacting pair afterwards. [fact C19] Gas Town's Refinery runs gates on the merged stack and bisects to the bad request; [fact C34] one solo developer lands one commit at a time, fully tested.
9. ADOPT (keep) one file one owner, worktrees, serialised shared files (repo 3.6). [fact A18] parallel agents "fix that bug, and then overwrite each other's changes". Add contract-level overlap: two cards that assume the same contract clause or decision run one after the other even when paths differ. [inference from fact C15 "conflicting decisions carry bad results"]
10. SKIP agent teams and lock-file claiming; WATCH Projects. [fact A5] teams are experimental, "task status can lag", no resume for in-process teammates. [fact C13] locks made 20 agents run like 2 or 3. [fact A20] Projects (public beta, Pro and Max) has "no fixed number" of threads and a cap of 200 new threads a day, so it cannot enforce our mode caps or per-card claims; useful later as a dashboard. [inference]
### Specs, context and drift
11. ADOPT (keep) thin specs; SKIP heavy spec pipelines. [fact C3] spec-kit "created a LOT of markdown files for me to review"; Kiro turned a small bug fix into 4 user stories and 16 acceptance criteria. [fact C7] Radar keeps spec-driven development at Assess: "relearning a bitter lesson". [fact C21] OpenSpec (70.7k stars) sells small per-change deltas; [fact C22] Kiro groups independent tasks into waves, as our 17 waves do.
12. ADAPT short always-loaded text with a monthly prune. [fact A9] CLAUDE.md "under 200 lines". [fact A1] ask of each line "Would removing this cause Claude to make mistakes?", and /doctor proposes cuts. [fact C26] context files did not raise success; repo overviews did not help. [fact C12] about 60 lines, each earned by a past failure. Ours is 87 lines plus NOW.md (36 now, 60 max) by import. Rule: a line that no failing test, hook or metric backs moves to a skill or is deleted.
13. ADOPT (keep) lazy skills and state outside the chat. [fact A22] a skill body loads only when used; listings are cut at 1,536 characters; /skill-doctor shows each skill's cost. [fact A4] a JSON feature list, progress file and git let each session start clean ("the model is less likely to inappropriately change or overwrite" JSON). [fact A27] the session is an event log outside the context window.
14. ADAPT a drift gate: a card that changes behaviour edits its clause or amber row in the same branch, and matrix.mjs --plan fails otherwise. [inference] Drift between spec and code is the named risk in one 2026 preprint proposing a blocking "drift gate" (theory, no measurements) [C40]; OpenSpec archives each change back into the specs [C21]; repo has the card-to-clause check (1.7).
### Self-correction and weekly improvement
15. ADOPT a weekly steering loop (one Reviewer routine): inputs metrics.jsonl, failed checks, ledger, /insights (friction report over up to 200 recent sessions on that machine [A9]); output at most three changes, each a test, hook, rule test or deleted line; also read 5 sampled worker transcripts and tag each failure by type (MAST's three families: design, misalignment, verification [C16]), because [fact A19] "You won't know if your graders are working well unless you read the transcripts". [fact C4] "Whenever an issue happens multiple times, the feedforward and feedback controls should be improved". [fact C5] "A fast output that requires extensive rework is not a productivity gain". Self-reported speed misleads: METR measured 19% slower in early 2025 [C27]. Add model and tokens to each metrics line. [inference]
16. ADOPT a subtraction review at each phase gate and after each model release: re-test every guard, delete those that caught nothing in four weeks of metrics. [fact A17] "every component in a harness encodes an assumption about what the model can't do on its own"; the sprint construct was dropped with Opus 4.6. [fact A27] context resets became "dead weight" on Opus 4.5. [fact C13] "Many of our improvements came from removing complexity". Due now: both 5.5 models are new.
17. ADAPT ensembles with one reconciler, for research and hard plans only. [fact A12] /deep-research fans out, cross-checks and votes per claim, dropping claims that fail. [fact A5] competing-hypothesis teams beat anchoring. [fact C14] independent agents amplify errors 17.2x, centralized 4.4x. [fact A2] +90.2% over one agent but about 15x tokens. Use 2 to 3 blind readers plus one reconciler that must cite, for blueprint-change proposals, tax-interpretation questions and phase reviews; never for code. /code-review ultra reproduces each bug: 3 free runs on Max, then about $5 to $25 (red) [A24]; spend the free three on the first money-and-tax train and the phase 3 gate. [inference]
18. ADOPT (extend) hooks for hard rules; SKIP /goal for builders. [fact A23] a PreToolUse deny holds even under bypassPermissions; the Stop hook has a block cap. [fact A1] hooks are deterministic, CLAUDE.md is advisory. [fact A11] the /goal evaluator (Haiku by default) "does not call tools", so it only judges what the transcript shows: keep the Stop hook that runs the acceptance command. Add hooks: model-pin check, per-card diff-size cap, workers cannot edit .claude/ or hooks.
### Practical, not robotic
19. ADOPT taste before code (repo has D00 to D11) and put a reference screenshot in every screen card: "take a screenshot of the result and compare it to the original. list differences and fix them" [fact A1]. Anthropic's frontend-design skill is about 400 tokens because models converge on "Inter fonts, purple gradients" [fact A25]; ours must steer to GOV.UK and MOJ patterns. [fact C18] once agents build, "design becomes the limiting factor". A community GOV.UK skill exists but has 1 star and a weekly auto-publish Action [fact C38]: read it, do not install it; the crown and GDS Transport are not for a private firm.
20. ADAPT a calibrated screen evaluator (the tester) as a pre-screen. [fact A17] four criteria and few-shot scored examples; it caught "display-only" features and stubs but left "interactions that felt unintuitive"; the full harness cost $200 vs $9 solo. Rubric for us: GOV.UK and MOJ pattern match, axe, keyboard walk, plain-language check; axe finds about 57% of issues by volume, the rest is manual [fact C39]. Zo and a CPA sign off.
21. ADOPT task-time and click budgets against "slow and painful": scripted preparer journeys on the biggest made-up return, time and clicks per task, train fails on regression (extends timing test 2.22). [inference] Real staff use each phase's build on made-up data at the gate: [fact A2] "people testing agents find edge cases that evals miss".
22. ADAPT AI usability checks as a pre-screen, never sign-off. [fact C37] an AI heuristic pass found 73 and 77% of issues vs 57 and 63% for five experts, but was weak on component recognition and multi-screen issues. [fact C36] synthetic users think "every idea" is good. Cheap before Zo looks; no use as proof.
### Token efficiency
23. ADOPT routing (section c) with pinned IDs and one model per job. [fact A21] each model has its own cache; switching model mid-session forces a full re-read (so does changing the tool set when MCP tools load upfront); opusplan toggles count as switches; on the 5.5 models changing effort keeps the cache. Subagent, workflow and teammate caches last 5 minutes unless subagentPromptCacheTtl is 1h.
24. ADOPT subagents for read-heavy work, with 1,000 to 2,000 token summaries back [fact A3]; prefer CLI tools such as gh to MCP servers [fact A9]. Taskmaster's default 36 tools cost about 21k tokens, its core mode about 5k [fact C21]. Up to 20 subagents run at once, 3 levels deep [fact A6].
25. ADOPT clear-and-compact habits: one job per session; after two failed corrections /clear and rewrite the prompt [fact A1]; compact at task breaks, not mid-task [fact A21]; cloud sessions cannot /clear, so start a new one [fact A8]. Quality falls as context fills [fact A3].

## How many agents in parallel
- Anthropic: 3 to 5 teammates, 5 to 6 tasks each [A5]. Osmani: 3 to 5, limit = review capacity [C11]. Cherny: 5 local plus 5 to 10 web, 10 to 20% abandoned [C25]. HN practitioners: 2 to 6 [C35]. Willison: parallel works for research, code reading, small chores and carefully specified work, but he "can only focus on reviewing and landing one significant change at a time" [C9].
- Google (180 configurations): parallelizable work +81%, sequential work -39 to -70% [C14]. Anthropic: multi-agent uses about 15x tokens and most coding has fewer parallel parts than research [A2]. Cognition: parallel writers make conflicting hidden decisions; subagents that only answer questions avoid it [C15].
- Bigger works only with a built harness: Cursor reached hundreds on one branch with planners, workers and a judge after locks and flat peers failed [C13]; Anthropic's 16-agent compiler cost about $20,000 over about 2,000 sessions and "nearly reached the limits of Opus" [A18]; Gas Town runs 20 to 30 [C19].
- [inference] For us: normal's 2 is conservative. Turbo's max_workers of 12 (up to 20) is past the 3 to 5 given for collaborating agents, near what one expert supervises (10 to 15), and below what purpose-built harnesses report at high cost (Cursor hundreds, Gas Town 20 to 30). Our workers are independent one-card jobs in separate worktrees, the friendly case, and the modes skill already brakes on merge conflicts. Go wide stepwise (practice 7). The real limits are Zo's and the CPA's review time, then the shared Max limit, not compute. Read-only helpers (scouts, readers) fan out safely.

## Community systems: what lasted, what did not
- Stars read 29 Sep 2026 [C21]: Superpowers 292.8k, spec-kit 139.4k, OpenSpec 70.7k, GSD 64.4k (archived), awesome-claude-code 54.8k, BMAD 53.6k, Taskmaster 28.1k, SuperClaude 23.9k, Gas Town 18.2k [C19], ccpm 8.4k, Agent OS 5.5k. Stars measure attention, not results.
- Lasted (my reading of stars and activity, not usage data): test-first plus a fresh subagent per small task plus review between tasks (Superpowers: 2 to 5 minute tasks, red-green-refactor, "verification-before-completion") [C21]; per-change spec deltas (OpenSpec); standards injected by context (Agent OS); "right-sized process" (BMAD says go straight to implementation for clear changes); plan, work, review, compound with about 80% of effort in plan and review [C23]; a merge queue that bisects [C19].
- Absorbed by the platform: Ralph's loop-until-the-tests-pass idea [C24] now has first-party forms, /goal and Stop hooks [A11][A23]; task fan-out is subagents, /batch and workflows [A12]; parallel sessions are worktrees, agent view and Projects [A28][A20]; standing knowledge is skills and auto memory [A22].
- Renamed, archived or unproven: claude-flow became ruflo, and one April 2026 audit found about 290 of 300+ MCP tools were "JSON state stubs" and its context hook wasted 15,000 to 25,000 tokens a session (single audit) [C20]; GSD archived 26 Jun 2026 and moved to Open GSD; SuperClaude's v5 plugin system is "not yet available"; ccpm's "89% less time lost" and "3x faster" show no method or sample [C21].
- Verdict: SKIP installing any framework; borrow ideas by reading them (verify before complete, bisecting train, thin deltas, lessons as tests). [inference] Renames, archives and weekly auto-published skills are a drift and supply-chain risk; Radar calls the flood "semantic diffusion" [C6].

## (b) Failure modes others hit that this system does not obviously guard against
- F1 Silent model change. Not guarded: agent files use aliases. [fact A10] opus moved to 5.5 at v2.1.280; cyber-flagged requests fall back to Opus 4.8 (Opus 5.5) or Sonnet 5 (Sonnet 5.5) with only a transcript notice. [fact A26] Anthropic's own evals "didn't capture the degradation users were reporting" for weeks. Guard: pin IDs, log model per job, weekly canary (practice 5).
- F2 Intent conflicts between cards that merge clean and pass alone. [fact C33] a commenter: "two agents completing the same task successfully via completely different paths, one of which quietly broke edge cases". [fact C16] inter-agent misalignment is one of three failure families in 1,600+ traces. Partly guarded (paths, train journeys). Guard: practice 9.
- F3 Lenient or nit-picking reviewers. Not guarded [A17][A1]. Guard: practices 5 and 6.
- F4 Test theatre beyond edit protection: over-mocking, special-casing, skip and todo, tautological property tests [C31][C28]. Partly guarded (protect-spec, flaky = fail). Guard: practices 1, 3, 4.
- F5 Code erosion over many cards. Not guarded. [fact C30] structural erosion rose in 77% of runs and verbosity in 75.5%; agent code was 2.3x more verbose and 2.0x more eroded than human code; quality prompts helped the start, not the decline. [fact A18] one agent's whole job was merging duplicate code. Guard: a simplify card per phase plus size and duplication sensors. [inference]
- F6 Cognitive debt: nobody can explain the system. [fact C6] "humans are dangerously tempted to step out of the loop"; Zo and the CPA cannot read code. Partly guarded (clause to test trace). Guard: one plain page per train (what changed, which clauses, which tests) and the Reviewer explains one random card back each week. [inference]
- F7 AI-written tests are the only oracle for tax behaviour. [fact C4] "a lot of faith into the AI-generated tests, that's not good enough yet"; [fact A18] the compiler run needed GCC as a known-good oracle. Guard: CPA-approved, hand-computed worked examples as golden oracles, written outside the AI's authorship. [inference]
- F8 Green is not success in unattended runs. [fact A7] a green routine status "does not mean the task in your prompt succeeded"; routines run with no permission picker and count against a daily cap. [fact A8] idle cloud sessions expire and lose background work. Guarded by "a claim is not a fact" and the 90-minute release. Guard: a job counts only when a tool finds its report file and commit; jobs are idempotent, state in git. [inference]
- F9 Cost blowups. [fact A2] about 15x tokens for multi-agent; [fact A9] about 7x for teams in plan mode; [fact C17] $100 in 60 minutes. Guarded by modes, caps, ledger and MAX_ROUNDS 3. Add a per-card token budget.
- F10 Stale guards outlive their reason [A17][A27][C13]. Guard: practice 16.
- F11 Human review capacity. [fact C32] AI writes faster than humans review. Guard: stop starting cards when more than two trains wait unreviewed; only RED reaches Zo (in place). [inference]
- F12 Third-party code in the agent's own toolbox (skills, plugins, MCP servers, hooks; the hooks guide says review its security notes before shared use [A23]). Guard: extend R00 supply-chain rules to .claude/ and plugins: none installed without a read and a pin.
- F13 Wrong measures. [fact C27] METR calls its new data "an unreliable signal"; [fact C5] volume metrics reward rework. Guard: the weekly loop uses first-pass acceptance, rounds per card, post-merge rework and defects found at gates.
