Date 1 Oct 2026. Researcher A. ## Opened and read [fact]

- Limits (https://static.developer.intuit.com/output_html/qbo/docs/learn/limits-and-throttles.html): 500 requests per minute per realm; 10 requests per second per realm and app; 40 batch requests per minute per realm and app trigger throttling; recommended at most 30 payloads per batch; a query returns at most 1,000 entities (paginate); 120 second request timeout; HTTP 429 means wait 60 seconds. A transaction may hold up to 10,000 attachments and 10,000 linked transactions.
- Sandbox (https://static.developer.intuit.com/output_html/qbo/docs/develop/sandboxes/sandbox-faqs.html): at most 10 sandbox companies; regions US, Canada, Australia, France, India, UK; Plus covers all six, Advanced is US only; each is active two years, then must be replaced (no renewal). The Canada sandbox arrives with sample data: a party-planning company, 173 transactions, 29 customers, 37 vendors, 21 items, 95 accounts. [snippet, newer page] region and SKU cannot be changed after creation.
- OAuth (https://static.developer.intuit.com/output_html/qbo/docs/develop/authentication-and-authorization/oauth-2.0.html): accounting scope is `com.intuit.quickbooks.accounting`; access token 60 minutes; refresh token rolling 100 days and rotated on every refresh (always store the newest one); a five-year hard ceiling is reported in `x_refresh_token_hard_expires_in`.

## From search summaries of Intuit pages [snippet]

- Change data capture (https://developer.intuit.com/docs/api/accounting/changedatacapture): the `cdc` operation takes a list of entity types and a changedSince timestamp; look-back up to 30 days; at most 1,000 objects per call (use a shorter window); deleted objects come back after active ones, marked Deleted; all entities except JournalCode, TimeActivity, TaxAgency, TaxCode, TaxRate. Grouped by type, then by last-updated time. Implication: CDC is a sync tool for the last 30 days, not a history; older changes need a full re-read.
- Audit log: an Intuit help thread (https://help.developer.intuit.com/s/question/0D50f00005vidJ6CAI/are-there-any-apis-to-read-quickbook-audit-logs-programmatically) is reported as saying the Audit Log is UI only, not in the API. Not read directly. Treat as probably true; confirm.
- Reports: TransactionList accepts `start_date`, `end_date`, `transaction_type`, `accounting_method`; columns include `tx_date`, `txn_type`, `doc_num`, `account_num`, `created_by`, `lastmod_date`, `lastmod_by` (forum threads, for example https://help.developer.intuit.com/s/question/0D5TR000003l7Sq0AI/). A thread titled "Is there a way to get a unique identifier for a transaction through the API" mentions a "qboTxnId". Wrong parameter or column names are silently ignored (a forum report about the PHP SDK), so a rule test must check that a requested column really comes back.
- Attachments (help.developer.intuit.com upload topics): Attachable is an entity; upload is multipart (JSON metadata plus file); `AttachableRef` holds `EntityRef` {type, value} linking the file to a transaction; reads give `FileAccessUri` and `TempDownloadUri`; the temporary link is short-lived (one answer guesses about 15 minutes, unconfirmed). Each download needs a fresh Attachable read.
- Access: the Intuit App Partner Program covers Canada except Quebec (a help thread asks about a private internal Quebec app; no answer read). Matters at go-live, not in the sandbox.
- GIFI: nothing about GIFI found on developer.intuit.com in any search. [guess] The API has no GIFI field on Account; the mapping will live in our app (blueprint TB-3) or in a QBO Canada UI feature outside the API. Check against the QBO Canada product itself (angle B).

## Not verified (open questions for the checker or a human)

1. Whether TrialBalance, GeneralLedger, JournalReport, TransactionList, ProfitAndLoss and BalanceSheet rows carry the source transaction id. [inference] GeneralLedger, JournalReport and TransactionList rows give the entity id in a cell; TrialBalance, P&L and BalanceSheet give account ids only. Trace route: report row (account) to GeneralLedger or TransactionList for that account to the entity by id. Confirm in the API Explorer.
2. Whether any report row shows that a transaction has attachments. [inference] No; query `Attachable` where `AttachableRef.EntityRef.value` is the transaction id.
3. Adjusting journal entries: `JournalEntry` has an `Adjustment` boolean, a `PrivateNote` (memo) and per-line `Description` (from memory, not opened). Confirm they appear in reads and in JournalReport.
4. As-of and date-range behaviour: P&L takes `start_date`/`end_date`; BalanceSheet and TrialBalance take an end date as of. `accounting_method` (Cash or Accrual) changes figures. Whether TrialBalance dates mean "as of" or a period is not confirmed. For a T2, state year end and accrual basis on every pull and save them with it.
5. Minor versions and the full query-entity list: not opened. Pin a `minorversion` on every call and record it.
6. Row limits inside one report response: not confirmed. 500 requests per minute is ample for one company at a time.

## What this means for the build [inference]

- Three reads per return: TrialBalance (as of year end), GeneralLedger or TransactionList by account (rows with type and id), and the entity by id (memo, lines, attachment refs). Store the raw JSON of each with date, realm, minorversion and a fingerprint (EV-1, EV-2). The pointer "QBO line" is realm + entity type + id + line.
- Attachments: copy the bytes at read time, because the link expires; fingerprint them as documents.
- CDC reaches back 30 days and there is no audit log, so "what changed since the CPA approved" must be detected by us: re-pull the trial balance and entities and compare with the stored pull.
- Sandbox: 10 companies, two-year life, Canada available. To use the sample-client test world, load made-up transactions through the API rather than relying on the party-planning sample company.
