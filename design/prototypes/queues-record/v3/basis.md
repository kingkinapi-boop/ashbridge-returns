# Parts used, and what is composed (queues and return record, version 3)

Version 3 is the single version drawn after design sitting 1 (decisions/0020: Z20-1 queues and record as version A with tabs and bulk assign on the list; Z20-6 one record shell, the same tabs for every role). It polishes that choice for the next sitting; it does not reopen it. Cards: D13 (sign-in and the record shell) and D04 (the preparer queue). The brief is `design/briefs/queues-record.md` (QR1 to QR8, QR20, QR21 applied; QR9 to QR19 wait).

Pages are static HTML written by `node design/prototypes/queues-record/v3/build/build.mjs` (no packages) and linted by `node design/prototypes/queues-record/v3/build/check.mjs`. Browser checks are in `build/verify.mjs`. Open `index.html`. Folder layout: `*.html` pages at the top, `static/` holds every style sheet, script and image (never a folder named assets: it is git-ignored on Windows), `build/` holds the generator and the checks.

Styles: `static/basis.css` is compiled by `design/basis/build.mjs` from the official GOV.UK Frontend 6.5.1 and MOJ Frontend 11.1.0 with the Ashbridge Tax settings (`design/basis/settings.scss`): Roboto asked for and not shipped, brand colours as functional colours, no crown, no logotype. `static/app.css` is layout and density only. Scripts: `static/govuk-frontend.js` and `static/moj-frontend.js` are the official UMD bundles (the `.min.js` files are ES modules and do not load from file://); `static/app.js` stands in for the build's React behaviour and holds every in-place action so no page repeats it: roles and sign-in, the lists (views, filter, sort in the address, counts, bulk assign), search, record tabs as client-side routes, hold, the Documents viewer and the Ops forms. Data: fifteen sample clients (names end "(Test)", from `reference/sample-clients/`) plus 285 synthetic filler returns; every return has a record page; pinned time Monday 8 Jun 2026, 11:20.

## Official parts used
GOV.UK: skip link, Generic header, service navigation (the role's lists, then Sign out last), button, tag, table (numeric cells), text input, password input, select, radios (small), checkboxes (small), file upload, fieldset, label, hint, form group, error summary, error message, notification banner, task list, details (Keyboard shortcuts), inset text, back link, footer. The summary list is not used: the identity bar's facts are composed (`app-facts`, below) because a summary list takes twice the height.
MOJ: identity bar, button menu (the record's actions; one action is a plain button), sub navigation (the record tabs and the list views), badge (counts in the view tabs), alert (approval void, hold states), timeline (History), sortable table (every list over 5 rows).

## Composed outside GOV.UK or MOJ, and why
- `app-header-row`, `app-search`, `app-search__label`, `app-search__input`, `app-search__button`: header search in the Generic header beside the logo, so the page starts higher. GOV.UK has no staff search; it is a label, an input and a button. One match opens the return; more show the results page; none says so (rule 21).
- `app-header-user`: "Signed in as ..." at the far end of the service navigation bar, before Sign out. GOV.UK has no signed-in line.
- `app-tablewrap`: a labelled scrollable region around every table (the lists, the record's tables, the search results, the guide's tables) so a wide table scrolls sideways inside it at 320 px and the page does not (rule 13, WCAG 1.4.10). It takes keyboard focus, so a person without a mouse can scroll it.
- `app-list`: marks a list page (body hook for tighter spacing under the heading and the view tabs).
- `app-listbar`, `app-listbar__field`, `app-listbar__input`: the "Show" menu and the filter box on one line above a list. MOJ's filter reloads the page and takes a column of the screen (RV-52 gap).
- `app-linkbutton`: a real button drawn as a link, where choosing something is an action and not navigation (choosing a document, Clear the filter). It carries `aria-pressed` and, when pressed, the words "open in the viewer".
- `app-bulkbar`, `app-bulkbar__summary`, `app-bulkbar__row`, `app-bulkbar__field`, `app-bulkresult`: bulk assign. It appears only when rows are chosen (no disabled button), is sticky at the foot of the window, and keeps its GOV.UK error summary and the result inside the bar, so the rows above do not move (rule 19). MOJ multi select reloads the list and has no sticky result.
- `app-pipeline`, `app-pipe`, `app-pipe--zero`, `app-pipe__count`, `app-pipe__label`, `app-pipe__age`: the Board's state strip, real buttons with a count that narrow the list below. Carried over from version A unchanged; D10 redraws the Board. GOV.UK has no count strip.
- `app-record`: marks a record page.
- `app-tabrow`, `app-listnav`: one row holding the record tabs and, at its end, Back to the list, Previous and Next, which follow the list the person came from (rule 21).
- `app-identity-title`: the corporation and year end as the page's one h1, with its state and tier words beside it, inside the MOJ identity bar (RV-50). The bar's own CSS is laid out as a grid in `static/app.css` so the actions sit beside the title and the facts run across the full width.
- `app-facts`, `app-fact`: the identity bar's facts as label and value pairs that wrap, at most ten. A summary list takes twice the height and pushes the tabs and the work below the fold at 1366 x 650.
- `app-since`: "Since you last opened this return", one strip under the identity bar on the landing tab and Overview. It is a list of links; inset text is for a quote or a note.
- `app-panel`: one record tab's content, shown or hidden by the client-side route.
- `app-docs`, `app-docs__list`, `app-viewer`, `app-viewer--page`, `app-viewer__head`, `app-viewer__meta`, `app-viewer__send`, `app-viewer__scroll`, `app-sourcepage`, `app-src__hit`: the Documents list with the source viewer beside it, never below, full height, the box kept in view, focus moved in, "Send to second window" opened by script with `window.open(url, 'ashbridge-source')`. A stand-in for the shared source viewer (D03); replace it when D03 lands.
- `app-result`: the result of an in-place action on a record (an Ops step saved, a chase recorded): one or two lines in the same green frame as the bulk result, placed where the person acted, with the words saying what happened (colour is not the only cue). GOV.UK's success banner is 100 to 170 px tall at this width and fell below the 1093 x 525 fold under the chase form.
- `app-steps`, `app-step`, `app-step__head`, `app-step__name`, `app-step__status`, `app-opsform`: the Ops tab's checklist. Each step holds its own in-place form of three fields or fewer. A task list cannot hold a form. `app-opsform` also lays out the chase form on the History tab (three radios and one button, which writes a dated staff note; QR16 is still open, so this is a stand-in): the field and the button on one row and a one-line error summary above, so the form and its error fit the first screen at 1093 x 525.
- `app-money`: tabular figures for money.
- `app-width-container--wide`, `app-shortcuts`: defined by `design/basis/` and listed in `design/basis/parts.md`. See the first deviation below.

## Deviations from the basis, and why
1. `app-width-container--wide` has no side gutter between 1020 and 1600 px in `basis.css` (it sets `max-width: 1600px` only). `static/app.css` adds a 30 px margin (15 px under 641 px, auto from 1660 px). Basis gap to fix in `design/basis/`, which this branch does not edit.
2. Tags: GOV.UK 6 tags are 19 px with a 160 px maximum width. In the lists they are 16 px, no maximum width, one line (two lines for blockers and waiting words), so a return row stays one line high and the table fits 1093 px.
3. Service navigation: item spacing is 16 px (GOV.UK: 20 and 30 px) so the role's lists, the signed-in line and Sign out fit one row at 1093 px.
4. Table cells: padding 6 px 10 px 6 px 0 (GOV.UK: 10 px 20 px 10 px 0); body text 16 px with 1.375 line height on app pages. Repeat desk work on a laptop with two monitors (Zo, decision 0009); 24 px targets are kept (rule 12).
5. MOJ identity bar: laid out as a CSS grid (title and tags, actions beside them, facts across the full width) instead of its floated columns. The MOJ sortable table's sort button is recoloured from its hard-coded blue to the Ashbridge link colour.
6. `.govuk-template__body` carries no font family in GOV.UK 6, so `app.css` sets Roboto with Arial fallback on it. No web font is loaded.
7. The `govuk-frontend-supported` class that GOV.UK adds on load is set by the page's own first line, because the official script runs after paint.
8. The logo is a link to the person's own list on app pages and plain on sign-in pages. On a list page that link starts the list afresh (first view, no filter, default order) rather than reloading, so it is never a link that changes nothing (the self-link rule); `check.mjs` lists these as the logo-to-own-list exemption. The active service navigation item is text with `aria-current="page"`, not a link.
9. MOJ sub navigation: the bar under the current tab is drawn as an inset shadow of the same size and colour (black while the link has focus, as in MOJ), and MOJ's absolutely positioned `::before` bar is switched off. With the `::before` bar in place axe 4.13 cannot read the background behind the tab text and its count badge ("pseudo element", reported as incomplete, which this version counts as a failure). The look is the same.
10. MOJ timeline: the vertical line is a 5 px border on the left of the timeline (same colour) instead of MOJ's absolutely positioned `::before` bar, which left axe unable to read the contrast of the title and byline text ("pseudo element", incomplete). The small marks beside each entry stay MOJ's own and are 10 px long so the whole mark is still 15 px; the line starts at the top of the first entry, 10 px higher than MOJ's.
11. MOJ sortable table: the sort button in each heading is at least 24 px high (MOJ's is 22 px at 16 px text), so every target meets rule 12 without relying on spacing. GOV.UK back link: 2 px of padding above and below (and 2 px less margin above) so it is 24 px high, not 20.
12. The in-place forms on the Ops tab and the History tab: the GOV.UK error summary in a form is sized with its border inside the form's width (border-box) and may shrink, so at 320 px it does not run 17 px past the form; its title and message sit on one line. The result of the chase form is under the button, not at the top of the page, so recording a chase moves nothing above it and the result stays where the person is looking (rule 19).
13. Page scroll padding at the foot of the window (7 rem, for the sticky bulk bar) applies on list pages only. On a record page nothing sticks to the foot, and the padding would scroll the page whenever a control near the bottom took focus.

## Rules checked by script
`node build/check.mjs` (no packages): retired terms and unknown clause IDs in the brief, the pages, the script and the style sheet; the brief names the blueprint commit; no self-link, no `#` link to nothing, no link drawn as a button, no control drawn as plain text, no filler in a data cell; counts in the view tabs, the menu options and the state strip agree with the rows; every `app-` class used is listed here and every class listed here is used; only govuk-, moj- and app- classes; no zoom, no import, no web font, no inline style, no style element; one h1, skip link, title, unique ids, label targets, table captions and scoped headers, sortable tables over 5 rows, no disabled control, no preselected radio, shortcuts listed, record tabs equal the one set, the sign-in rules (one failure message, no locked state, no resend control, paste and password managers allowed). Browser checks in `build/verify.mjs`: axe (with the incomplete results counted as failures) on every page state for every role, the keyboard Tab walk, 320 px reflow, the task budgets at 1366 x 650 and 1093 x 525, and `design/verify/rules.mjs` V1 to V8.
