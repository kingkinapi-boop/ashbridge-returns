The five record files each hold all five tabs: a tab change is a client route (`pushState`, its own URL, 0 page loads, the filter and scroll of each list kept, the window gets the new list). The file name only chooses the first tab. `?as=anita|dev|sam` picks the person (kept for the browser session); `?item=<id>&src=<n or n.m>` selects a figure and source and is kept in the URL with `replaceState` (no history entry); `?q=` is the list filter; `?state=done` seeds one finished row of each kind; `?state=void` shows the approval void. Not drawn: the Overview and History record tabs (this card does not fill them).

## Structure, top to bottom
- One record shell: Generic header (Ashbridge Tax logo at the left, the one search box at the right), MOJ identity bar (corporation and year end, who is signed in, Sign out), MOJ sub navigation (five record tabs), then the split. The designer of the shell (D13) may redraw it; the viewer is a pane inside it and the final fit is the panel's.
- Split: the list at the left, a splitter (role separator, arrow keys resize, Home, End, Enter resets), the viewer at the right at full height. Pane 480 px by default, 360 to 800; at 1093 wide it narrows the list and never stacks. At 600 px and under it is one view at a time with a Back control.
- Viewer: title and zoom (page sources only), the figure's sources as numbered steps (MOJ sub navigation; an adjusting entry's own sources are a second row), the origin word and dot (in words, with a shape), the evidence (page image with the box, sheet grid with the cell outlined, or a card), who added it and when, then the decision slot. A page opens at the largest zoom at which the box fits, or readable (smallest text 12 px) with the box's left edge in view; zoom has buttons only (D01's list has no zoom keys).
- Second window: opens only on a click or the key o (never on load). The check box "Every time" beside "Open in a second window" is remembered for each signed-in person (default off) and its state is written next to it. While the window is open and following, the pane hides, the list takes the width and the decision moves above the list; it comes back when Follow is off or the window closes. Window closed and blocked states are in words. Presence is a heartbeat (2 s, closed after 6 s) over a BroadcastChannel; sign-out from any window sends every window to the signed-out page.
- Decision slot per tab, one job each. Workbench (B): the shared cite-or-reason part, candidates with the exact value first and "rounds to this value" apart, none preselected, the reason box always visible so typing is the choice, Record, the GOV.UK error pattern inside the form. Review (A): "Supports, next source", a tick that is UI-only and says "your place, not a review mark"; pressing it twice never unticks (a separate "Remove tick" button has no key); the last source goes to the next unhandled figure. Documents (B): Accept and Reject beside the box and the OCR words. Exceptions: one reason box, "Accept the risk" or "Comment, do not accept". Ops (C): Complete, and Chase, which writes a dated staff note ("chased on <date>") and sends nothing. A finished row (C) shows a tag and an Undo that asks for a reason; there is never a live second Complete.
- Keys, from D01's one list only: m next number, n next flag, p previous flag, o open the source (in the second window when that is on), ] and [ next and previous source, s search, Esc back to the figure you came from. `r`, `a` and `c` belong to the Review page (D02) and are not wired here; "mark and step" has no key. No key accepts, rejects, ticks, unticks, completes, chases or sends. Every key repeats a visible control with `aria-keyshortcuts`, none fires in a text field, and "Turn off single-key shortcuts" is under Keyboard shortcuts.

## Composed outside GOV.UK or MOJ, and why
There is no split view, no pane, no splitter, no page-image-with-box, no sheet grid, no step control with a "current, not a link" step and no done row in either library. Everything below sits in `static/app.css` (the four `app-cor` ones in `design/parts/cite-or-reason/`). No CSS `zoom`, no third-party font, no inline style in the markup.

Shell and layout (rules 13, 18, 20): `app-shell` (the page is exactly the viewport tall, so the pane runs full height and the page never scrolls), `app-shell--stack` (a column: header, return, work), `app-shell--page` (landing, results, signed-out scroll as normal pages), `app-wide` (full-width container, the same job as the basis's `app-width-container--wide`), `app-return` (identity bar plus tabs, never shrinks), `app-split` (grid: work and pane; the basis names `app-panes` for this job), `app-split--no-pane` (the pane hides while the window follows), `app-split__left`, `app-split__work` (the one scroller beside the pane), `app-split__pane`, `app-splitter` (APG window splitter), `app-viewer-root`, `app-window-main`, `app-scroll` (a labelled, focusable region around a table that scrolls sideways at 320 px).
Header, search and bar: `app-brand` (logo link on the brand blue), `app-header-row`, `app-header-search` (MOJ search made one compact line), `app-bar-who`, `app-bar-link` (the identity bar's right side: who is signed in, Sign out).
Work column: `app-headline`, `app-h1` (one h1 per page, kept small so rows fit), `app-filter`, `app-tools`, `app-navbar` (Next number, Previous flag, Next flag), `app-winctl`, `app-win-status` (the second window's state in words), `app-winslot` (the decision, above the list, while the window follows), `app-counts`, `app-done` and `app-recorded` (the live results messages that take focus), `app-section-h`, `app-void` (the MOJ alert made one compact line), `app-keys-inline`, `app-summary-strip`, `app-summary-strip--window-top` (the window's one-line top strip).
Tables and buttons: `app-table-dense` (GOV.UK table at 16 px with tight rows so at least 3 full rows show beside the pane), `app-row--selected` (the selected row, with a bar as well as a colour), `app-what` (the row's kind in words under its name), `app-button-compact` (GOV.UK button, 24 px tall minimum, in a dense row), `app-button-glyph` (the zoom buttons), `app-actions`, `app-key` (the key cap beside a control), `app-req` (the red asterisk on a required field, as in the client app, A20), `app-tag-origin`.
Viewer: `app-viewer`, `app-viewer--window`, `app-viewer__head`, `app-viewer__title`, `app-viewer__zoom`, `app-zoom-level`, `app-viewer__note`, `app-viewer__steps` and `app-viewer__steps--sub` (MOJ sub navigation as numbered source steps), `app-steps__current` (the current step is not a link), `app-steps__sep` (divider between candidate groups and between steps and Prev, Next), `app-steps__go` (Prev and Next), `app-reset-button` (a step is a button wearing the MOJ link class: choosing a source changes no page and no history), `app-viewer__meta` (the "Source n of N" line, visually hidden words), `app-viewer__prov` (origin and dot line), `app-meta-group`, `app-viewer__body`, `app-viewer__stage` (the only scroller inside the pane), `app-viewer__empty`, `app-viewer__card`, `app-card__added` (who and when), `app-ocr` (the OCR words and composite key, bold, visible), `app-only-narrow` (Back to the list, shown under 600 px), `app-warning` (GOV.UK warning text, spaced for the pane).

## Choices made this round (amber, to reverse by editing this prototype)
- Three inline styles are set by script, not in the markup: the box position (`left`, `top`, `width`, `height` in percent on the box), the page width at the chosen zoom, and `--app-pane-w` on the split. Rule 1 names only the box position; the other two are flagged to the Lead.
- No Accept, Reject, Complete or Chase buttons on rows: one decision place (the viewer's slot, or above the list while the window follows) and Undo on the finished row only. Rows show "Show sources", "Candidates (n)", "Show the change" and similar constant labels.
- The tick reads "Supports, next source" (and "Already ticked, next source" once ticked); a candidate group is named in the meta line and by a divider in the steps; an adjusting entry's sources are numbered sub-steps ("2.1").
- Tags and key caps are 16 px (GOV.UK tag is smaller). Text below 16 px appears only in the sheet grid (13 px, source text, 12 px or more) and the "Boxed figure" label (13 px on a dark ground).
- Made-up additions for the test world: the adjusting entry `01-AJE-01` and its sources, QBO Transaction ID 2188, snapshot fingerprints, flag `01-F10`, a client answer, a written reason. Money prints in whole dollars, as the test world does.
- The MOJ identity bar's text alignment is overridden (the official class centres it); the bar is the one shell for every role.
- Header search is a stand-in: it searches this prototype's figures, values, exceptions, items and sources, in the format shown on the pages (so a value copied from a row finds it), and always shows the results page, even for one hit (the build may go straight to a single hit). The results page sits outside the return shell, with the Generic header and its own search box.
- A separate "Prototype only: load page images slowly" check box under Keyboard shortcuts lets the panel see the loading state; it is session storage and not part of the design.
