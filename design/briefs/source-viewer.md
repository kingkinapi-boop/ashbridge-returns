Re-checked 3 Oct 2026 against blueprint v1.2 (main 518279e9). Clauses: EV-5, EV-6, EV-10, EV-11, EV-14, TB-2, TB-7, TB-9, TB-10, TB-11, TB-13, RV-4, RV-11, RV-22, SEC-3, SEC-4, RT-14, RT-16, CK-2, CK-12, rules 18 to 23; Z20-3, Z20-7, A251, A252, A358, A485. Role: design research only. Family: the one viewer that the CPA review, the workbench and the queues and record embed (R5 of reports/findings-designs.md).

## Why one viewer
The three designers each invented a viewer: a new window per click, a pane docked under a table, panes that stack below 1100 px, a fixed pane that never scrolled to the box, a second window that went stale on a section change, a flag that showed the number's source instead of its own evidence, and "SIN ending 456" (breaks SEC-4). D03 is designed once, panelled, then embedded; no family draws its own.

## Research (pages opened, 1 Oct 2026)
- DataSnipper, "How to add a Validation Snip" (search result, page body not readable here): the tick mark in the cell is linked to the rectangle drawn on the PDF; stored in the workbook. Copy: the cell-to-box link is the unit, not the page. Avoid: nothing in their help shows the click-back behaviour, so we spec it ourselves. https://knowledge.datasnipper.com/how-to-validate-data-on-a-document ; Excel Online snips page opened, silent on viewer behaviour: https://knowledge.datasnipper.com/how-to-use-snips-in-datasnipper-excel-online
- Caseware Working Papers, "Create tickmarks" (opened): tickmarks and document references are annotations on a line; hover shows who added it and when. Copy: who and when on every pointer (RV-11). https://documentation.caseware.com/2022/WorkingPapers/en/Content/Engagements/Review-Signoff/Annotation/Create-Tickmarks.htm
- Microsoft Dynamics 365 Invoice capture side-by-side viewer (opened, same pattern Hubdoc and Dext sell; their own help pages were not opened, only a comparison search): fields left, original document right; an eye icon beside a field positions and highlights the value on the document; page, zoom, fit and rotate controls top right; draggable resize line; colour states for mapped and unmapped values; confidence thresholds. Copy: one control per figure that jumps and boxes; resizable divider; page and zoom controls. Avoid: lines paged five at a time, and edit mode inside the viewer. https://learn.microsoft.com/en-us/dynamics365/finance/accounts-payable/invoice-capture-workspace
- PDF.js (opened): viewer URL hash takes `page`, `nameddest`, `zoom`, `pagemode`; no rectangle in the hash. The viewer object's scrollPageIntoView takes a destination array with fit type `XYZ` or `FitR`, in PDF coordinates (GitHub issues 6947, 9704, search result only). Implication: we draw our own overlay box from stored box coordinates and call scrollPageIntoView; do not rely on URL hashes. https://github.com/mozilla/pdf.js/wiki/Viewer-options
- W3C APG window splitter (opened): role `separator`, aria-valuenow, min, max, label, aria-controls; arrow keys resize, Enter collapses, optional Home, End, F6. Use for the pane divider. https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/
- MDN window.open (opened): a named target reuses one window; needs a user click each call; returns null when blocked; `noopener` breaks the link back. https://developer.mozilla.org/en-US/docs/Web/API/Window/open
- MDN BroadcastChannel (opened): same-origin windows message each other; baseline since 2022; sender does not hear itself. Use to make the second window follow every selection. https://developer.mozilla.org/en-US/docs/Web/API/BroadcastChannel
- Not found: any accessible-viewer standard beyond the above; a screen-reader name for "boxed figure" must be our own (see budgets).

## Task scripts

|---|---|---|---|---|---|

| Preparer | Cite an orphan or a tax choice typed in Taxprep (RV-22, TB-6), or write the reason for an override or a dropped cell (RT-14) | a few per return | the cell, the candidate sources (exact value first, "rounds to this value" listed apart, none preselected), the evidence | pick one source or write a reason | record, next row |
| Preparer | Verify an extracted value (EV-6) | many | value, box, OCR words | accept or reject | next value |
| Preparer | Check the books behind a figure | several per return | the figure, each account's QBO balance from the dated snapshot, each adjusting entry with its type, reason and sources | agrees, or goes to the entry's own source | next source (TB-9) |
| CPA | Judge an accepted risk with its source open | a few per return | the exception, the preparer's answer ("accepted risk") with its source or reason, amount and tax effect, the source | accept with a reason, or comment | next unjudged risk, then the first unmarked section |
| Any | See that the books changed after approval | rare | the QBO item with the snapshot value and the re-read value | nothing (approval void, return back in trace) | the changed cells |
| Ops | Check a document or CRA capture | per return | the item and its source | complete or chase | next item |
Source kinds, one viewer (EV-5): a document page with a box; a sheet, row and column (EV-14, grid with the cell outlined); a QBO line (TB-10): snapshot date and fingerprint and the account, and for a transaction its QBO Transaction ID, date, type, number and memo; a trial-balance line names snapshot and account only, no id; a line read without an id shows "no QBO id: matched by date, type, number, account, amount" with the flag for a person (TB-13); an adjusting entry shows its type, reason and its own sources as steps (TB-2, TB-9); a client answer; a CRA data capture (an Auto-fill value shows its pull date, CK-12); last year's return and assessment, a cell of the filed return or of the notice (EV-5, TB-8); a written reason (author, time). Every source header shows its origin word (third party, client filed with CRA, client prepared, client said, judgment: EV-10) and its dot in words (EV-11, rule 7). No evidence shows "Not checked: no evidence" (CK-2), never a blank.

## Budgets (measured at 1366 x 650 and 1093 x 525, rule 18)
- Open a source: 0 page loads, 1 click or 1 key, visible in under 1 s (first paint of the page image or card; skeleton after 300 ms; failed state with a retry). Measured cold: the largest test-world return, a page never opened before, masked image not cached; the first open includes the server-side masking (SEC-4), so the 300 ms skeleton stays.
- Box scrolled into view and focus moved in on open; Escape returns focus to the figure it came from. No history entry added.
- Step to next or previous source: 1 key (`]` and `[`), shows "Source 2 of 4", with kind, name, page and who added it.
- Second window: opened by one click or `o` on a user gesture, named, no `noopener`; follows every selection and tab change; a "Follow" toggle; a visible "Window closed, open again" state; closes on sign-out. Opens only when asked, never on load; the choice is remembered for each person; the control is visible and its state is in words.
- Beside the work, never below: pane at the right, resizable divider (APG splitter), minimum 360 px; at 1093 wide it narrows the trace, it never stacks. Under 600 px it becomes a full-width view with a Back control.
- SIN, date of birth, banking details masked in the page image itself (black out the boxes server side before the image leaves, SEC-4); no digits in alt text, labels or titles: "SIN on file".
- Loads / clicks / fields: check the books behind a figure 0 / 1 to open, 1 key per step / 0, cold open under 1 s (TB-7, TB-2, TB-10); judge an accepted risk, source open, 0 / 2 (Accept or Comment, Record) / 1 (the reason when accepting) [proposal] (EX-1, A421); open a QBO line with no id 0 / 1 / 0, the composite-key flag visible at once (TB-13); turn the second window on once 0 / 1 / 0, remembered (Z20-3).

## Pattern options (settled: drawn as A, B and C in design 1; B was chosen, Z20-7)
1. Docked right pane, second window optional (Dynamics split viewer). Copy the divider, page and zoom controls, eye-style "show me" per figure. Avoid: a separate edit mode. Fits all three families with one component.
2. Right pane plus a persistent trace strip above it listing the figure's sources as numbered steps (Caseware annotation list, TB-9). Copy: numbered steps and who and when. Avoid: a list that scrolls out of view.
3. Two-monitor default: the viewer is its own window, a small summary in the work page (DataSnipper snip-to-cell idea turned around). Copy: the follow channel. Avoid: popup blockers, a lost window; so needs option 1 as the laptop fallback.
GOV.UK and MOJ: no split-view part exists, so compose with MOJ sub navigation for sources (not in design/basis/parts.md: the Lead adds it, or use MOJ side navigation, listed, to be reviewed), GOV.UK pagination for step, summary list for non-document cards (QBO line, adjusting entry, last year's cell), tag for kind, origin and dot (words, rule 7), inset text for the reason.

**Fixes for the designer, in order** (the one component: `viewer.js`, `window.js`, `work.js`; no new pattern)
1. Opening zoom "fit the box": the largest zoom at which the box fits the pane width, capped where the source's smallest text is 12 CSS px; if the box cannot be both whole and readable, open readable and scroll to the box's left edge. Zoom persists per kind for the session; buttons Zoom -, Zoom + and Fit box (D01's list has no zoom keys, A485). Never clip the box (fault 4). Page images at 2x so 200% stays sharp.
2. Chrome to one row above the page: title, "Source n of N", kind and zoom in one line; who, when and the OCR words in one line under it (the OCR words stay visible, Lead's amber; full text in the accessible name). Page area at least 60% of the viewport height at 1093 x 525, in the pane and the window. Steps keep 24 x 24 targets.
3. One shell: identity bar inside a landmark, splitter inside main, one viewer landmark, page height equal to the viewport (no 1 px scroll). Record tabs as client routes (pushState, 0 loads) that send the new list to the window; the viewer draws no record tabs of its own.
4. Window link both ways: each page announces itself on load (`work-hello`, `win-hello`) with a tab id and the return id; the other answers with its state; presence by heartbeat (2 s, closed after 3 missed), not the handle. The window follows the last focused work page of the same return and shows that return's identity; another return's page never drives it.
5. Sign-out from any window broadcasts `signout`; every same-origin page goes to the signed-out page. Note for V00 (security): the server ends the session; the channel is the second line.
6. Selection in the URL by `history.replaceState` (`?item=&src=`): reload and Back return to the same figure and source, no history entry (rules 18 and 21 both hold). The prototype keeps cites and reasons in session storage so the panel can test reload.
7. Decision slot in the viewer (`extra`): from the box, 1 Tab reaches the decision. Keys come from D01's one list only (A485): `n` next flag, `p` previous flag, `m` next number, `o` open the source (in the second window when that is on), `r` reviewed and next (marks a section in the host, not here), `]` and `[` source steps, `s` search; "mark and step" has no key this round. Base B's Cite and Record; from A only the mechanics (step, the last source goes to the next unhandled figure, never unmarks) with a UI-only "Supports this figure, next source" tick that says "your place, not a review mark" (K3, RV-5, RV-11, rule 22); from C the Complete tag with Undo that asks for a reason, and Chase as a dated staff note ("chased on <date>"), never a sent message. One shared next: the next unhandled row after this one in list order, then the first unhandled above, else focus the "All items checked" message and announce it.
8. While the window is open and following, the pane hides and the list takes the width; when Follow is off, the window closes or is blocked, the pane comes back. The window shows the same viewer as the pane. A checkbox beside "Open in a second window" remembers the choice for each signed-in person (default off, state in words, Z20-3).
9. The list keeps at least 3 full rows beside the pane at both sizes (the summary band and shortcut line fold).
Not the viewer's job (Lead adds to D02): the mark comes off when the number changes; Approve only when every section is marked and every accepted risk is judged.
